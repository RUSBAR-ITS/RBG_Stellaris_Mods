## 1. Статус и объём

**Требования +100/+30 и переключение согласованы пользователем 2026-11-15 ответом «Согласен». В тот же день пользователь прямо поручил дополнить триггер удаления совместным условием технологии и активного чита. Версия `0.0.7` реализована; синтетические проверки пройдены, игровая проверка остаётся пользователю.** Сохранить чит «Расширенная модификация видов» как модификатор государства, увеличить его бонусы до +100 очков и +30 доступных признаков и добавить отключение через тот же пункт главного меню. Исходная поставка — `0.0.5`.

База: Tass Cheat Tool `20261012`, Workshop ID `682851228`, и установленная Stellaris `v4.5.*`. Источники, определения и контрольные суммы записаны в [аудите](../../TMP/TCTE/species_modding_audit.json).

В объём включено расширение `can_remove_beneficial_genetic_traits`: дополнительное разрешение действует, когда у государства игрока одновременно есть технология `tech_gene_expressions` и модификатор `modifier_tass_extra_species_modding`. Прежние условия по традициям сохраняются. Поведение «Дополнительных послов» не входит в это ТЗ; его последующее изменение в 0.0.8 реализовано по [отдельному ТЗ](TZ_ENVOYS_RU.md).

## 2. Бонусы и поведение кнопки

Сохранить исходный ID `modifier_tass_extra_species_modding`, иконку и бессрочное действие при включении (`days = -1`). Значения заменить следующим образом:

| Архетип | Очки признаков | Доступные признаки |
| --- | --- | --- |
| `BIOLOGICAL` | `BIOLOGICAL_species_trait_points_add = 100` | `BIOLOGICAL_species_trait_picks_add = 30` |
| `ROBOT` | `ROBOT_species_trait_points_add = 100` | `ROBOT_species_trait_picks_add = 30` |
| `MACHINE` | `MACHINE_species_trait_points_add = 100` | `MACHINE_species_trait_picks_add = 30` |

Это прибавки к действующим значениям государства, а не установка итогового количества. Новые технологии, традиции и признаки не выдаются.

| Состояние государства | Единственная отображаемая кнопка | Нажатие |
| --- | --- | --- |
| Модификатора нет | «Расширенная модификация видов» | Добавляет исходный модификатор бессрочно и снова открывает главное меню |
| Модификатор есть | «Удалить расширенную модификацию видов» | Удаляет именно этот модификатор и снова открывает главное меню |

Пункт остаётся на месте прежнего чита. Обе подписи одновременно не отображаются; вариант «Уже действует» больше не блокирует доступ к отключению. Наличие определяется через `has_modifier`, включая случай, когда исходный модификатор уже присутствует в сохранении. Отдельный флаг состояния не нужен.

После удаления кнопка вновь предлагает включение. Повторное включение не должно накапливать копии бонуса. Действия влияют только на государство, открывшее меню. Удаление бонуса не запускает изменение видов, не удаляет их признаки и не отменяет изученные технологии или традиции; допустимость имеющихся шаблонов после снижения лимита проверяется в игре.

## 3. Реализация и локализация

Внутри TCTE переопределить два исходных файла Tass с сохранением относительных путей:

- `common/static_modifiers/tass_cheat_static_modifiers.txt`: изменить только шесть числовых параметров `modifier_tass_extra_species_modding` с 50/5 на 100/30; остальные модификаторы сохранить;
- `events/tass_cheat_events_1_country.txt`: заменить прежний вариант `tass_cheat.1.trait_points` двумя взаимоисключающими вариантами с проверкой отсутствия или наличия модификатора. Первый выполняет `add_modifier`, второй — `remove_modifier`; оба возвращаются в `tass_cheat.1` через `hidden_effect`.

Сохранить ID главного события, остальные варианты, порядок, область государства, доступ игроку, `tass_cheat_menu_on` и штатное закрытие. Существующий вход в ресурсное меню `tass_cheat.4` должен продолжить работать с реализацией TCTE 0.0.5. Не использовать `replace_path` для каталогов.

По прямому уточнению пользователя для 0.0.7 удалить полную копию `common/scripted_triggers/05_scripted_triggers_traits.txt`. Разместить только изменённый `can_remove_beneficial_genetic_traits` в `common/scripted_triggers/tcte_species_traits_triggers.txt`, сохранив его блок из 0.0.6 без изменений. Остальные 49 определений не включать в TCTE: они загружаются из оригинального файла игры.

Scripted triggers переопределяются по ID последним загруженным определением (LIOS; [заметки разработчика мода](https://github.com/openly-retro/stellaris-machine-robot-expansion/wiki/Dev-notes:-Modding-Den-highlights)). Имя `tcte_species_traits_triggers.txt` сортируется после `05_scripted_triggers_traits.txt`, единственного найденного определения этого ID в ванили и Tass. Сохранить ванильный ID для существующих вызовов. Не использовать `replace_path`, не изменять файлы игры. Загрузку выбранного определения движком проверить в игре.

Новая кнопка удаления и новые подсказки получают ключи с префиксом `tcte_`, на русском и английском. Подпись включения можно сохранить через исходный ключ. В событии использовать актуальную подсказку +100/+30, не ссылаться на прежний текст +50/+5. Подсказки объясняют дополнительное разрешение при наличии `$tech_gene_expressions$` и его прекращение после отключения чита с сохранением обычных разрешений. Сохранять формат локализации, UTF-8 BOM и ссылки на существующие игровые термины.

Обновить README, changelog, ТЗ и отдельный список переопределений базового мода на двух языках. В списке ванильных изменений различать исходный файл и отдельный файл TCTE с единственным триггером. Версию повысить до `0.0.7`, сохранить `supported_version="v4.5.*"`, зависимость Tass Cheat Tool, обновить архив и подключённую копию, удалив прежнюю полную копию из неё. Плейсеты, политики, ресурсное меню, послы и другие читы сохраняются.

## 4. Исследование удаления положительных признаков

В установленной версии право удаления проверяется в `species_possible_remove` конкретного признака. Для общего разрешения полезных органических признаков используется `can_remove_beneficial_genetic_traits` из `common/scripted_triggers/05_scripted_triggers_traits.txt`, строка 71. Его область `this` — вид, `from` — модифицирующее государство; сначала проверяется наличие `from`.

Условия этого триггера:

- если `has_biogenesis_dlc = no` **или** уже принята традиция `tr_genetics_adopt`, требуется `tr_genetics_resequencing` — **«Генетическое ресеквенирование»**;
- в другой ветке, при Biogenesis без принятой `tr_genetics_adopt`, требуется `tr_purity_genotype_regeneration` — **«Восстановление генотипа»**.

Это проверка наличия традиции, а не числовой модификатор. В определениях `tr_genetics_resequencing` и `tr_purity_genotype_regeneration` нет отдельного числового бонуса, который разрешал бы удаление: связь реализуется прямым `has_tradition` в триггере.

Существует и отдельный путь через технологию **«Воздействие на генную экспрессию»**, `tech_gene_expressions` (`common/technology/00_soc_tech.txt`, строка 3132). Триггер `can_remove_vocational_genetic_traits` (строка 63 того же файла триггеров) проверяет `from = { has_technology = tech_gene_expressions }`. Он разрешает удаление только тех признаков, которые вызывают эту проверку. Например, `trait_agrarian` («Аграрии») допускает общий триггер **или** технологический, а `trait_quick_learners` («Способные») вызывает только общий триггер.

Технология **«Адаптация генома»**, `tech_gene_tailoring`, открывает базовое изменение признаков через `feature_flags = { modify_traits pop_self_modification }` и добавляет очки. Эти флаги сами по себе не заменяют описанные условия удаления полезных признаков. Названия сверены с английскими ключами и приоритетной русской базой.

По прямому поручению пользователя расширить только `can_remove_beneficial_genetic_traits`. Сохранить `hidden_trigger = { exists = from }` и выполнение проверок в `from`, то есть у модифицирующего государства. Итоговая логика: **прежнее ванильное разрешение ИЛИ (государство игрока И технология И активный модификатор)**. В новой ветке объединить `is_ai = no`, `has_technology = tech_gene_expressions` и `has_modifier = modifier_tass_extra_species_modding` через AND; старую ветку включить в OR без изменения её условий.

| Прежнее разрешение | Технология | Чит | Итог для игрока |
| --- | --- | --- | --- |
| Нет | Нет | Нет | Запрещено |
| Нет | Да | Нет | Запрещено |
| Нет | Нет | Да | Запрещено |
| Нет | Да | Да | Разрешено |
| Да | Любое | Любое | Разрешено |

ИИ сохраняет прежнюю логику даже при наличии технологии и модификатора. Без `from` разрешения нет. Сам чит доступен для включения без технологии: +100/+30 действуют сразу, а разрешение на удаление требует совместного условия. Технология не выдаётся автоматически. После удаления модификатора дополнительное разрешение прекращается; старые условия по традициям продолжают работать.

Не изменять `can_remove_vocational_genetic_traits`, условия остальных триггеров и определения отдельных признаков. Дополнительное разрешение применяется только там, где вызывается `can_remove_beneficial_genetic_traits`; прочие условия конкретного признака продолжают действовать. Действие расширяет возможность редактирования, не удаляя признаки автоматически.

## 5. Проверки и приёмка

Уточнение 0.0.7 реализовано: поставка содержит одно определение триггера в отдельном файле; прежней полной копии нет. Блок триггера побайтово совпадает с 0.0.6, 110 остальных игровых файлов сохранены, в манифесте изменена версия. Проверены порядок имён файлов, сохранение 49 ванильных определений в статической модели загрузки, все 256 сочетаний условий и состав архива. [Отчёт 0.0.7](../../TMP/TCTE/trigger_override_validation.json). Игровая загрузка ещё не проверена.

Фактический результат 0.0.6: пройдены 256 сочетаний разрешения, четыре состояния видимости, восемь переходов переключения, шесть числовых бонусов и раскрытие новых ссылок на трёх базах локализации. Остальные 49 ванильных триггеров и 106 прежних игровых файлов сохранены. [Отчёт](../../TMP/TCTE/species_modding_validation.json), [таблица условий](../../TMP/TCTE/species_modding_truth_table.json), [исходники и константы](../../TMP/TCTE/species_modding_sources.json).

После реализации проверить:

1. Совпадение исходников с исследованной базой; целевые значения ровно 100/30 во всех трёх архетипах. Прочие определения исходного файла модификаторов сохранены.
2. Для двух состояний `has_modifier`: виден ровно один нужный вариант; включение выдаёт исходный модификатор один раз бессрочно, удаление снимает только его. Последовательность включить → удалить → включить не создаёт накопления.
3. Возврат обоих действий в главное меню, сохранение его флага, условий доступа и всех остальных вариантов, особенно входа в ресурсное меню и действия дополнительных послов.
4. Наличие RU/EN строк, ссылки, кодировки и соответствие подсказок числам кода. В новых кнопках и подсказках нет устаревших значений 50/5.
5. Для уточнения 0.0.7 — неизменность остальных игровых файлов относительно 0.0.6, кроме версии манифеста и переноса единственного триггера. Проверить отсутствие полной копии в моде, архиве и подключённой копии; двуязычную документацию.
6. Полную таблицу сочетаний технологии, модификатора, игрока/ИИ, наличия `from`, Biogenesis, принятой ветки генетики и двух традиций: результат равен исходному разрешению ИЛИ новой совместной проверке. По отдельности технология и чит не дают нового разрешения. Исходная ветка сохранена; остальные триггеры поступают из ванильного файла.

Пользователь проверяет в игре новый и уже активный модификатор, смену подписи после каждого нажатия, итоговые очки и доступные признаки для трёх архетипов, снятие только бонусов чита, повторное включение и состояние шаблонов после удаления бонуса. Отдельно проверить все четыре сочетания технологии и чита без нужной традиции, а затем сохранение права от традиции при выключенном чите. Для чистой проверки подходит «Способные» (`trait_quick_learners`), использующий общий триггер без альтернативы профессионального редактирования. Синтетические проверки не подтверждают перерасчёт ограничений движком и отображение меню.
