## Корень поставки

Корень мода — `PDE/`. В нём находятся дескриптор, обложка и значок решения. В дескрипторе выпуска указаны `version="2.0.4"` и `supported_version="v4.6.*"`. Базовая версия проверки — Stellaris 4.6.0. Новые игровые ключи получают принятый в PDE префикс `cdpd_`, события используют пространство имён `CDPD`. [Текущий дескриптор](../../PDE/descriptor.mod) · [События PDE](../../PDE/events/cdpd_menu_events.txt)

Документы проекта находятся в `docs/PDE/`: требования, классификация, реестр предупреждений и журнал изменений. Здесь же находятся [ТЗ 2.0.0](TZ_RU.md) и [список ванильных файлов и функций](VANILLA_CHANGES_RU.md). Входные данные для исследования и результаты отдельных прогонов находятся в `TMP/PDE/<версия игры>/`. PDE использует встроенную копию механизма меню RB_SDM под собственными именами. Игроку достаточно установить PDE. [Требования](REQUIREMENTS_RU.md) · [Руководство RB_SDM](../../RB_SDM/README_RU.md#как-перенести-раздел-в-свой-мод)

## Игровые файлы

Дерево показывает состав поставки. В `catalog/` приведён один конечный раздел в качестве образца. Порядок экранов и конечных разделов задан в схеме меню. Экран списка может подключать несколько файлов каталога. [Структура меню PDE](MENU_STRUCTURE_RU.md)

| Файлы | Ответственность |
| --- | --- |
| `cdpd_decisions.txt`, `cdpd_access_triggers.txt` | Планетарное решение, доступ в пределах границ, проверка игрока-инициатора. Решение сохраняет выбранное тело и передаёт управление событию державы `from`. Для собственной колонии и незаселённого тела в своей системе используется штатный интерфейс. Для чужой колонии, включая досветовую в своей системе, ваниль ограничивает доступ. [Решение PDE](../../PDE/common/decisions/cdpd_decisions.txt) · [Правило игры](E:/SteamLibrary/steamapps/common/Stellaris/common/game_rules/00_rules.txt:4698) |
| `cdpd_placement_triggers.txt`, `cdpd_menu_triggers.txt` | Первый файл определяет допустимую цель для каждого вида размещения, включая тип тела, класс и климат. Второй определяет видимость раздела по наличию хотя бы одного доступного потомка. Для кнопки удаления достаточно наличия соответствующего ID на выбранном теле. |
| `cdpd_menu_events.txt`, `cdpd_add_events.txt`, `cdpd_remove_events.txt` | Вход, сеанс и главное меню, экраны разделов добавления и один плоский экран для пункта верхнего уровня «Удалить депозиты». Следующая и предыдущая страницы переиспользуют текущее событие списка. |
| `cdpd_menu_effects.txt`, `inline_scripts/cdpd/menu/` | Подсчёт доступных пунктов в порядке каталога, присвоение позиций, вывод страницы, переходы и очистка сеанса. Кнопка раздела открывает дочерний экран с первой страницы. Кнопка депозита применяет операцию и обновляет список. После действия заново проверяется доступность текущего раздела и его родителей. |
| `cdpd_deposit_effects.txt` | Добавление и прямое удаление выбранного экземпляра, обслуживание обязательных модификаторов и счётчиков. Здесь описываются особенности конкретных ID, например пара `d_titanic_life_blocker` и `titanic_life`. |
| `cdpd_menu_l_*.yml`, `cdpd_deposits_l_*.yml` | В первом файле каждого языка — решение, разделы и навигация. Во втором — подписи и подсказки действий со ссылками на игровые ключи названий и описаний. Если для действия предусмотрено предупреждение, первой идёт красная фраза, через пустую строку — название и полное описание. [Реестр предупреждений](QUEST_TOOLTIP_WARNINGS_RU.md) |

## Как один депозит попадает в оба меню

Например, для `d_energy_3` заводится одна запись в `orbital/cdpd_energy.txt`. В ней указываются ID, правило размещения, подсказки для каждой операции и, при необходимости, особая обработка. Положение записи задаёт порядок в разделе «Орбитальные депозиты → Энергокредиты». Экран раздела использует один и тот же перечень сначала для подсчёта доступных пунктов, затем для вывода. Если на данном теле не подходит ни одна энергетическая залежь, пункт «Энергокредиты» скрывается.

Для удаления `cdpd_all.txt` последовательно подключает те же конечные каталоги и `cdpd_remove_only.txt`. Из этой последовательности пользователь видит только ID, уже присутствующие на выбранном теле. Поэтому `d_energy_3` можно удалить даже с колонизируемого мира, а `d_arc_furnace_1` из списка исключений доступен только для удаления. У каждого ID одно место в исходных списках. Покрытие — 529 ID для добавления и 592 для удаления. В `cdpd_remove_only.txt` входят 63 ID, включая `d_astral_threads_deposit_2` и `d_crystal_rift`. Служебный `d_null_deposit` учтён отдельно. [Классификация и исключения](DEPOSIT_CLASSIFICATION_RU.md)

## Из чего состоит кнопка депозита

Для `d_energy_3` связь задаётся в `PDE/common/inline_scripts/cdpd/catalog/orbital/cdpd_energy.txt`. У записи один ID депозита и два действия. При показе экрана добавления или удаления запись передаёт в шаблон соответствующий набор `LABEL`, `TIP`, `VISIBLE` и `ACTION`. Ниже приведены ключи из поставки 2.0.0. [Каталог энергии PDE](../../PDE/common/inline_scripts/cdpd/catalog/orbital/cdpd_energy.txt) · [Шаблон кнопки RB_SDM](../../RB_SDM/mod/common/inline_scripts/rb_sdm/rb_sdm_option.txt)

| Поле кнопки | Добавить `d_energy_3` | Удалить `d_energy_3` |
| --- | --- | --- |
| `LABEL` — надпись на кнопке | `cdpd_add_energy_3_label` | `cdpd_remove_energy_3_label` |
| `TIP` — текст при наведении | `cdpd_add_energy_3_tip` | `cdpd_remove_energy_3_tip` |
| `VISIBLE` — когда показывать | На выбранном теле разрешено разместить эту орбитальную залежь | На выбранном теле есть `d_energy_3` |
| `ACTION` — что выполнить при нажатии | Добавить экземпляр `d_energy_3` на выбранное тело | Удалить экземпляр `d_energy_3` с выбранного тела |

**Текст для игрока.** Русские надписи на кнопках и полные подсказки обоих действий находятся в `PDE/localisation/russian/cdpd_deposits_l_russian.yml`. Английские значения тех же ключей — в `PDE/localisation/english/cdpd_deposits_l_english.yml`. В каждом из этих файлов есть два общих ключа предупреждений, по одному на операцию. Для семи ID у игры отсутствует описание на обоих языках. PDE показывает собственную строку с месячной выработкой станции, взятой из определения депозита. Конкретная подсказка ссылается на нужную фразу, когда для этого действия есть пометка в реестре. Названия разделов и кнопок навигации находятся в `cdpd_menu_l_russian.yml` и `cdpd_menu_l_english.yml` соответствующих языков.

Пример для русской локализации. `$d_energy_3$` подставляет игровое имя, `$d_energy_3_desc$` — игровое описание. Для этого ID в реестре отмечено только удаление. [Игровые ключи](../../Localisation_Base/1-Prio_Russian_Localization_Fix_RE/russian/megacorp_l_russian.yml) · [Основание для предупреждения](QUEST_TOOLTIP_WARNINGS_RU.md#кнопка-удаления)

```yaml
l_russian:
 cdpd_add_energy_3_label: "Добавить $d_energy_3$"
 cdpd_remove_energy_3_label: "Удалить $d_energy_3$"
 cdpd_remove_quest_warning: "§RВНИМАНИЕ!!! Удаление этого депозита может нарушить ход уже начатого квеста!§!"
 cdpd_add_energy_3_tip: "$d_energy_3$\n$d_energy_3_desc$"
 cdpd_remove_energy_3_tip: "$cdpd_remove_quest_warning$\n\n$d_energy_3$\n$d_energy_3_desc$"
```

Все 529 кнопок добавления используют предварительный показ из `cdpd_option_preview.txt`. На 592 кнопках удаления свойства берутся из локализации депозитов. Общий обработчик клика находится в `cdpd_deposit_button.txt`. [ТЗ подсказок](TZ_TOOLTIP_EFFECTS_RU.md)

**Исполнение действия.** Общий шаблон `common/inline_scripts/cdpd/menu/cdpd_option.txt` выводит надпись и подсказку, а при нажатии повторно проверяет доступность и вызывает действие на сохранённом теле. Условия размещения реализуются в `common/scripted_triggers/cdpd_placement_triggers.txt`. Эффекты добавления, прямого удаления и обработка обязательных модификаторов находятся в `common/scripted_effects/cdpd_deposit_effects.txt`.

## Правила действий

Доступ к решению имеет только игрок. При проверке добавления учитываются условия выбранного тела. Тип державы и число уже установленных экземпляров не ограничивают выбор. Один клик добавляет или удаляет один экземпляр. Общие модификаторы и счётчики обслуживает эффект депозита. [ТЗ 2.0.0](TZ_RU.md#экземпляры-и-состояние-планеты)
