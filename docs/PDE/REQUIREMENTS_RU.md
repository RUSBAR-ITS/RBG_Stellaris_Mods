## Состояние проекта

Согласованные требования к переработке Planetary Deposits Editor (PDE) на основе RB_SDM. Каталог сверен с ванильной Stellaris 4.5.4. Из 593 уникальных ID планетарное решение предлагает 529 для добавления и учитывает ещё 63 только для удаления, служебный `d_null_deposit` учитывается отдельно. Категории, исключения и ванильные источники каждого депозита ведутся в справочнике. [Справочник депозитов](DEPOSIT_CLASSIFICATION_RU.md) · [ТЗ 2.0.0](TZ_RU.md)

Планетарное решение PDE 2.0.0 доступно только державе игрока. Решение проверяет инициатора (`from = { is_ai = no }`), его вес для ИИ равен нулю.

Вход использует штатные решения Stellaris на своих колониях и незаселённых телах в границах державы. Решение сохраняет выбранное тело и открывает меню для державы, которая его приняла. На чужой колонии, в том числе на досветовой планете в своей системе, доступ через штатное окно ограничивает игра. [Ванильное правило](E:/SteamLibrary/steamapps/common/Stellaris/common/game_rules/00_rules.txt:4698) · [Структура PDE 2.0.0](PROJECT_LAYOUT_RU.md)

## Правила ручного размещения

Общее условие колонизируемого мира проверяет `is_colonizable = yes` или `is_colony = yes` через `cdpd_is_colonizable_or_colonized`. Для орбитальной залежи обе проверки должны дать отрицательный результат. Индивидуальные ограничения по классу тела и климату сохраняются.

| Условие | Правило для меню PDE |
| --- | --- |
| Тип объекта, класс и климат | Для каждого ID сохраняем допустимый тип объекта и класс небесного тела. Для планет сохраняем климатические ограничения. Если климат лишь повышает вес генерации, остальные допустимые классы остаются доступны. При смене класса в ванильном сценарии учитываем класс цели в момент размещения депозита. |
| Орбитальные депозиты | Для любого ID из ветки «Орбитальные» запрещаем размещение на колонизируемом мире, даже если он ещё не заселён или ванильный сценарий выдаёт там тот же ID. Среди неколонизируемых тел действуют допустимые классы конкретного депозита. |
| Номиналы базового орбитального ресурса | Один список допустимых тел на ресурс. Если на выбранном теле доступен один номинал энергии, доступны все согласованные `d_energy_*`. У физики свой список, общий для всех `d_physics_*`, включая +25. Это же правило действует для остальных базовых орбитальных серий. При ручном добавлении берём обычные цели ванильного ресурса. Сценарные исключения описываются в справочнике и не расширяют список тел. |
| Туманность | Положение системы внутри или вне туманности не влияет на ручное размещение. |
| Именные миры и системы | Особенность доступна на любом объекте подходящего типа и класса с подходящим климатом. Название, конкретная система и флаг, служащий только для опознания уникального мира, не ограничивают размещение. В справочнике сохраняется ванильное место появления. |
| Происхождение и тип державы | На одной и той же подходящей цели игрок видит один набор депозитов для любого типа и происхождения державы, включая обычные державы, коллективный разум и машинный интеллект. После размещения условия ванили определяют доступные должности, выработку и бонусы. |
| Повторное размещение | Для каждого из 529 доступных ID кнопка добавления остаётся видимой при наличии экземпляров на подходящем теле. Каждый клик добавляет ещё один экземпляр. В меню удаления ID занимает одну строку, каждый клик убирает один экземпляр. |
| Технологии и события державы | На подходящем теле кнопка добавления видна и доступна при любом наборе изученных технологий и на любой стадии связанного события или квеста, в том числе до его начала. После размещения условия добычи ресурса и действия бонусов определяет ваниль. |
| Радиационное заражение | Для `d_irradiated_ruins` нужен колонизируемый мир с действующим `irradiated_planet`, кроме `pc_ark`. Для `d_ancient_battlefield` и `d_ancient_bombardment_craters` подходит тот же мир либо любой класс из `is_starting_planet_type`. Добавление и удаление всех трёх сохраняет исходное состояние модификатора. |

## Эффекты добавления и удаления

Правило действует для всех депозитов, включая блокеры. После добавления должны работать все собственные эффекты экземпляра при текущих ванильных условиях. Сюда входят выработка и содержание, изменения предела районов, должности и модификаторы, в том числе заданные в других игровых файлах проверкой наличия депозита. Условный эффект включается, когда выполнено его условие. Редактор не должен повторно начислять то, что игра уже учитывает.

Добавление депозита через PDE не запускает и не продвигает связанный квест, событие, аномалию или спецпроект. Самостоятельные результаты сценария, включая флаги сюжетного прогресса, награды, соседние депозиты и сопутствующие модификаторы, остаются за рамками операции.

После удаления должен исчезнуть весь вклад удалённого экземпляра, независимо от того, как он появился. Для модификаторов, флагов и счётчиков, которые обслуживают сам депозит, нужно сверить состояние с оставшимися экземплярами и другими действующими источниками. Удаление не отменяет самостоятельные результаты ранее состоявшихся событий. При неизменных внешних условиях добавление депозита на тело без него и его эффектов, а затем удаление возвращают действующие бонусы, штрафы и служебное состояние к исходным значениям.

### Обязательные модификаторы планеты

Для депозита, который в ванили привязан к определённому модификатору планеты, фиксируем пару ID и подтверждающий скрипт. При ручном добавлении PDE ставит на планету и депозит, и обязательный модификатор. Если модификатор уже есть, используется существующий экземпляр.

При удалении последнего зависящего от него депозита PDE снимает и модификатор, в том числе у пары, изначально созданной ванилью. Пока на планете остаётся другой экземпляр, другой зависимый депозит или самостоятельный действующий источник этого модификатора, он сохраняется в одном экземпляре. Совместная выдача депозита и модификатора одним событием сама по себе не подтверждает обязательную связь.

Подтверждённая пара — «Титанические формы жизни» (`d_titanic_life_blocker`) и «Титаническая форма жизни» (`titanic_life`). Ванильный скрипт находит планеты по наличию модификатора и добавляет на них депозит. Депозит даёт 8 социологических исследований в месяц и −1 к общему пределу районов, а модификатор даёт +25% социологических исследований от должностей. PDE применяет пару напрямую. Через год после колонизации сама игра может проверить этот модификатор для события колонии. ## Удалить депозиты

«Удалить депозиты» — самостоятельный пункт верхнего уровня. Он открывает плоский список без категорий и подкатегорий. Источник списка — полный каталог известных ID, включая депозиты и блокеры, исключённые из ручного добавления. [Каталог Stellaris 4.5.4](../../TMP/PDE/v4.5.4/deposits.json)

Единственное условие показа ID в этом списке — присутствие хотя бы одного его экземпляра на выбранном небесном теле. Это относится и к депозитам, появившимся в ванильной игре, и к депозитам, установленным через PDE. Ограничения добавления по типу тела, классу и климату при удалении не применяются.

Если на теле нет ни одного известного депозита, пункт «Удалить депозиты» скрыт. При удалении список и его страницы пересчитываются. Когда на теле исчезает последний экземпляр конкретного ID, его пункт исчезает из списка. Когда список пустеет, исчезает и пункт верхнего уровня.

### Прямое удаление блокеров

PDE удаляет выбранный блокер напрямую, в том числе при недоступной обычной расчистке. Такое удаление не запускает очередь и таймер расчистки, не списывает её стоимость и не вызывает `on_cleared`. Награды, новые депозиты, население и события, которые должна выдавать расчистка, при удалении через PDE не возникают.

Если блокер ограничивал доступ к существующей особенности, проверяем снятие именно его блокировки. При разборе `on_cleared` нужно выявить операции, которые обслуживают собственное состояние блокера. Например, при удалении блокера с общим счётчиком сохраняется вклад остальных типов блокеров, а при отсутствии счётчика не должно появиться отрицательное значение.

## Предупреждения о квестах

Если ID отмечен для выбранного действия, подсказка кнопки начинается с красного предупреждения. Через пустую строку выводится название депозита, под ним — полное описание. Для остальных ID подсказка начинается сразу с названия. Для добавления и удаления используются отдельные списки. Пометка привязана к ID, не требует проверки журнала квестов и не меняет доступность кнопки. [Списки ID и ванильные основания](QUEST_TOOLTIP_WARNINGS_RU.md)

- **Добавление.** «ВНИМАНИЕ!!! Добавление этого депозита не запустит связанный с ним квест!»
- **Удаление.** «ВНИМАНИЕ!!! Удаление этого депозита может нарушить ход уже начатого квеста!»

Применять `§R…§!` только к фразе предупреждения. Желательный размер — 200% от обычного только для этой фразы. Пока в штатном тултипе RB_SDM не подтверждено локальное масштабирование, используется обычный размер. [Оформление и проверка](QUEST_TOOLTIP_WARNINGS_RU.md#правила-показа)

## Видимость разделов и страницы

Главное меню содержит «Планетарные депозиты», «Орбитальные депозиты», «Блокеры» и «Удалить депозиты» в этом порядке. Внутри раздела располагаются либо дочерние папки, либо действия над депозитами. [Структура меню PDE](MENU_STRUCTURE_RU.md)

Доступность меню вычисляется для выбранного объекта. В ветках добавления пункт депозита показывается, если на этом объекте разрешено его размещение. В разделе удаления доступность определяется наличием депозита. Пункт раздела или подкатегории показывается, если среди **всех его потомков** есть хотя бы один доступный депозит. Это правило действует на любой глубине. Единственный доступный депозит сохраняет весь путь к нему. При исчезновении последнего скрывается вся опустевшая ветка.

На каждом уровне страницы строятся после фильтрации. В пределах текущего раздела сохраняется заданный автором порядок видимых пунктов. Видимая подкатегория занимает одно место на странице родительского раздела независимо от числа депозитов внутри. Скрытые пункты не занимают места и не создают пустых страниц. [Динамическое меню RB_SDM](../../RB_SDM/README_RU.md#что-делает-шаблон)
