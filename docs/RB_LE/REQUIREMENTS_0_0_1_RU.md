## Цель прототипа

ТЗ утверждено для реализации. Целевая версия Stellaris — `v4.6.*`. Графическая часть рассчитана на UI Overhaul Dynamic, Workshop ID `1623423360`.

Версия 0.0.1 проверяет одну возможность. Игрок открывает правую карточку лидера в окне «Лидеры», нажимает «Редактировать личное дело» и видит имя именно этого персонажа. Событие служит для просмотра. Планетарное решение и повторный выбор персонажа в этом сценарии не используются.

## Карточка и событие

Кнопка «Редактировать личное дело» располагается по центру отдельной строкой под штатными кнопками «Выбрать лидера» и «Уволить лидера». Нижний край фона карточки опускается, чтобы вместить эту строку. Портрет, биография и штатные кнопки сохраняют свои размеры и положение. Возможность открыть дело правителя независима от доступности его увольнения.

Основой служит `interface/topbar_leaders_view.gui` из UI Overhaul Dynamic. Для исследованной разметки предлагается увеличить высоту `leader_portrait_background` с 705 до 770 и поставить кнопку размером 300 × 60 в точке (87, 795) с привязкой `upper_right` относительно `topbar_leaders_view`. Это единицы GUI. Критерий приёмки — положение кнопки на экране игрока.

| Элемент | Русский текст | Английский текст |
|---|---|---|
| Кнопка в карточке | Редактировать личное дело | Edit Dossier |
| Заголовок события | Личное дело | Dossier |
| Полное описание события | `Имя: <Имя выбранного лидера>` | `Name: <Selected leader’s name>` |
| Единственная кнопка события | Выход | Exit |

Описание занимает одну строку. Вместо текста в угловых скобках выводится текущее отображаемое имя персонажа. «Выход» закрывает событие одним нажатием.

## Передача выбранного лидера

Цель нажатия — игровой объект лидера, чья карточка открыта в этот момент. Рабочая гипотеза для проверки — кнопка `effectButtonType` получает область `leader`. Если это подтвердится, обработчик передаёт ссылку на этого персонажа в событие для игрока. Имя вычисляется в локализации события, например через `$NAME$: [event_target:rb_le_selected_leader.GetName]`. Подпись «Выход» должна воспроизводиться точно и с одной только ванильной русской локализацией.

В ванильном `common/button_effects/example.txt` лидер отсутствует в перечне документированных объектов кнопки. Штатные кнопки выбора и увольнения обслуживает движок. Если скрипту достанется держава или ранее выбранный объект карты, это фиксируется как результат проверки. Подстановка правителя, командира выделенного флота или поиск по имени не удовлетворяет ТЗ. [Исследование выбора лидера](VANILLA_LEADERS_4_6_0_RU.md#выбор-лидера-в-интерфейсе)

## Проверка и приёмка

| Проверка | Ожидаемый результат |
|---|---|
| До запуска игры | Имя GUI-кнопки и обработчик связаны, событие содержит одну опцию, обе локализации ссылаются на одну цель. |
| Открыть карточку лидера А, который не является правителем, и нажать новую кнопку | Открывается одно событие. В описании только `Имя: <имя А>`. Нажатие «Выход» закрывает его. |
| Открыть карточку другого лидера Б, затем вернуться к А, каждый раз вызывая событие | Событие последовательно показывает Б и А. |
| Выделить на карте флот с командиром А, затем открыть дело другого лидера Б | Показано имя Б даже при ранее выделенном флоте. |
| Открыть карточку правителя | Событие показывает имя правителя и доступно также при неактивной кнопке увольнения. |
| Осмотреть карточку с UI Overhaul Dynamic при игровом масштабе пользователя | Новая кнопка целиком помещается внутри фона, отделена от штатного ряда и не перекрывает биографию. |

Передача цели считается подтверждённой после проверки в игре пользователем. Совпадения имени только на карточке правителя для приёмки недостаточно.
