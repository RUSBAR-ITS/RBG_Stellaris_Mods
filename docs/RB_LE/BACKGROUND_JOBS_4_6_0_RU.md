## Какие должности могут быть предысторией

**«Гражданин» (`civilian`) может быть прежней профессией.** Если игра выбрала группу свободных граждан, имеющих право давать лидеров, она может взять их должность для биографии. У страты `civilian` задан положительный базовый вес происхождения, у самой должности нет лимита рабочих мест. Запись `weight = 0` в конце определения должности относится к распределению населения по рабочим местам. Для генерации биографии используются другие поля. См. `common/pop_categories/02_other_categories.txt:1`, `common/pop_jobs/00_other_jobs.txt:5` и `common/leader_classes/00_README.txt:222`.

В [русской таблице](BACKGROUND_JOBS_4_6_0_RU.csv) отфильтруйте **«Может быть прежней профессией (ID)» → «Да»**. Чтобы увидеть только должности, для которых установлен путь через население, выберите **«Обычная генерация из населения» → «Да»**. В строке «Гражданин» оба ответа — **«Да»**. Колонки с названиями скриптовых команд отражают только прямые присвоения.

| Может быть прежней профессией (ID) | Строк | Основание |
|---|---:|---|
| **Да** | 102 | По файлам игры установлен хотя бы один путь. Для 86 ID найдена обычная генерация из подходящего населения, для 23 — явное назначение профессии скриптом. Семь ID встречаются в обеих выборках. |
| **Нет** | 154 | Для самого ID найдено препятствие для обычной генерации и нет явного назначения в просмотренных скриптах. Сюда входят и названия без собственного ID. Причина указана в строке. |
| **Не установлено** | 175 | Остаётся вопрос о доступности рабочего места, правах населения или генерации лидеров в конкретной державе. Для `sand_caretaker` единственный найденный источник недоступен играбельным державам. |
| **Служебное значение** | 1 | Скрипт присваивает `none` («Нет»). Это отдельный исход для поля профессии. |

Например, **физик** встречается и при обычной генерации, и в скрипте; **капитана** скрипт назначает напрямую, а его ID закрыт для населения. У **жреца** `priest` есть контекстное название, но самостоятельного ID должности в этой сборке нет. Отметка «Да» у обычной генерации предполагает, что должность занимает группа, удовлетворяющая `can_generate_leader_from_pop_group` или военному аналогу, а лидер получает индивидуальный принцип. Это вывод по правилам ванили 4.6.0. Частота выпадения в сохранениях не измерялась.

## Состав каталога

В установленной Stellaris 4.6.0 (3d1a) найдено **369 ID должностей** в 21 файле с определениями. У должностей есть **135 уникальных контекстных названий** в `swappable_data`. Из них 72 совпадают с ID должностей и 63 существуют только как названия. В [полном каталоге CSV](BACKGROUND_JOBS_4_6_0_RU.csv) **432 строки данных**, по одной на ключ. Две колонки связывают исходную должность и все варианты её названия в обоих направлениях.

| Группа для обсуждения | Строк | Что в неё вошло |
|---|---:|---|
| Назначается скриптом | 23 | Встречается в явном присвоении лидеру. Например, капитан, физик, аристократ и блюститель. |
| Основная должность | 15 | Дополнительные кандидаты для первого меню. Например, солдат, шахтёр, техник и роботостроитель. |
| Особая должность | 115 | Другие кандидаты с рабочим определением. Сюда попали, например, рыцарь, профессор, астродобытчик на ковчеге и астральный исследователь. |
| Дрон или единица | 98 | Работа в стратах дронов и две роботизированные должности угасшей империи. |
| Состояние или зависимое население | 61 | Например, ассимиляция, чистка, подопытные, неразумные животные, отдельные подневольные роли и глубокий сон на ковчеге. |
| Закрыта для населения | 56 | В определении стоит прямой запрет `possible = { always = no }`, а явное назначение лидеру в скриптах не найдено. Например, исследователь `researcher` и дуэлянт. |
| Только название | 63 | Есть у другой должности в `swap_type.name`; самостоятельное определение отсутствует. Например, жрец у бюрократа и турист у гражданина. |
| Служебное значение | 1 | `none` («Нет») — зарегистрированный ID. Ваниль использует его в событии `paragon_events_4.txt:3180`. |

Это рабочая группировка для выбора состава меню. Каждая строка попала в одну группу. Прямое назначение имеет приоритет. Например, у рыбака `angler` есть собственный ID и запрет для населения, он также служит названием фермера. Черта лидера прямо назначает ему профессию рыбака. Все три факта видны в одной строке. Во всём каталоге **71** определение с прямым запретом для населения, включая служебное значение и несколько явно назначаемых профессий.

## Как игра выбирает профессию

При обычной генерации игра выбирает подходящую группу населения, а затем одну из занятых ею должностей. Учитываются численность занятых, вес должности и поправки для класса и принципов державы. У солдата добавочный вес для командира равен 100. У должности без поправок базовый множитель равен 1. Возможность случайного выбора зависит также от прав населения и доступных рабочих мест. При гештальтном личном принципе генератор оставляет лидера без страты и прежней должности. Правила описаны в `common/leader_classes/00_README.txt` в разделах Leader Generation Details и Job weight. Проверки группы населения находятся в `common/game_rules/00_rules.txt` в правилах `can_generate_leader_from_pop_group` и `can_generate_military_leader_from_pop_group`.

В скриптах найдено **22 конкретные профессии** в `change_background_job`. Ещё одну, блюстителя `fe_overseer`, ваниль задаёт через `background_job` при создании лидера. Капитан и командир `commanding_officer` встречаются в обоих путях. Отдельно скрипт назначает `none`. Ссылки на конкретные строки приведены в CSV. Проверка `has_background_job` сама по себе подтверждает только чтение значения. Так, `common/scripted_triggers/03_scripted_triggers_paragon.txt:330` перечисляет в том числе рыцаря, рейнджера и дуэлянта.

## Предложение для редактора

**Личное дело → Предыстория → Изменить прежнюю профессию** использует 101 ID с итоговой отметкой «Да» и источником в играбельной державе. Для лидера с гештальтным личным принципом команда скрыта. Для остальных лидеров кнопки зависят от того, какие профессии в принципе доступны в их нынешней державе. [Условия для каждого ID](BACKGROUND_JOB_VISIBILITY_4_6_0_RU.csv) · [Требования к меню](DOSSIER_MENU_REQUIREMENTS_RU.md#прежняя-профессия)

При разборе доступности у солдата проверяется возможность создать рабочее место. Для капитана ваниль использует прямое назначение в `common/scripted_effects/paragon_effects.txt:2834`.

«Блюститель» (`fe_overseer`) исключён из меню играбельных держав. Должность вызывает `can_fill_precursor_job`, где для владельца требуется `is_fallen_empire = yes` (`common/pop_jobs/07_fallen_empire_jobs.txt`, `common/game_rules/00_rules.txt:2961`). Отметка «Да» в справочном CSV сохраняется: ваниль прямо задаёт эту предысторию лидеру, которого покровитель дарит отпрыску (`common/scripted_effects/federations_event_effects.txt:2702`).

После выбора доступной профессии сверяются `has_background_job = <ID>`, досье, штатная биография и сохранение после загрузки. У персонажа с авторской биографией текст может обходиться без подстановки профессии.

## Чтение таблицы и проверка

- Колонки явного присвоения и проверки отмечают буквальные ссылки в установленных скриптах `common/` и `events/`. Скриптовая локализация вынесена в отдельную колонку. Для обычной генерации отдельно проверены условия должности и группы населения. У ограниченных по числу мест должностей колонка «Пример источника рабочего места» указывает найденное положительное добавление мест. Для неограниченной должности такое добавление не требуется.
- Пустой столбец определения указывает на название без собственного ID. В столбце источников названия тогда указан владелец и строка. Признак запрета для населения отражает только безусловный `always = no` в `possible`. Другие условия могут ограничивать найм на должность.
- Веса взяты из развёрнутых определений парсера проекта. Пометка «по условию» отсылает к исходному файлу в той же строке. Русские названия сверены по ключам `job_<ID>` в порядке приоритета проекта. Для двух отсутствующих в локальной базе ключей использована установленная русская ваниль (`professor`, `culture_worker_gestalt`). Динамические названия сохранены с игровой подстановкой.
- При проверке сопоставлены все ID развёрнутых определений с установленными файлами, проверены связи вариантов и адреса явных присвоений. Таблица описывает скрипты. Назначаемость каждого ID конкретному персонажу требует проверки в игре.
