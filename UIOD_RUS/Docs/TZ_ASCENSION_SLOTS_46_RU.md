## Назначение

Первый этап утверждён для UIOD_RUS 0.0.4 и охватывает ауру Исполнителя желаний и повторяемую технологию Ascension Slots (Workshop `1890399946`). Основание — скрипты Stellaris 4.6.0 и журнал игры. Обе правки действуют при любом языке интерфейса. Русские строки поставляются по [ТЗ локализации](TZ_RU.md).

## Аура Исполнителя желаний

Основой служит только определение `desire_aura_max_intensity_effect` из ванильного `common/scripted_effects/psionic_auras_scripted_effects.txt`. Сохранить обе ветки 4.6 для планет и кораблей-колоний, их условия владения, оккупации и наземного боя в той ветке, где оно проверяется. Каждая затронутая колония получает свой флаг `recent_colony_aura_effect_triggered` на 10 лет. Сохранить подсчёт повышений, выбор цели и отправку сообщения владельцу ауры через `recipient = root.aura_owner`, в том числе в системе без принадлежащей ему звёздной базы.

В обеих ветках проверять предел из `event_target:global_event_country.uiod_ascension_limit`. Эту переменную рассчитывают существующие события Ascension Slots. У подходящей колонии с уровнем ниже предела повысить текущий уровень ровно на один. У колонии на пределе или выше эффект пропускает повышение, отметку и включение в счётчик.

Для начисления нужен отдельный `script_value` с префиксом `uiod_rus_`, вызываемый только этой аурой. Ванильная формула `add_planet_ascension_tier` в `common/script_values/01_script_values_paragon.txt` ограничивает результат через `max = 10` и использует `trigger_scope = planet`. Значение `uiod_rus_next_ascension_tier` читает уровень текущего объекта (`has_planetary_ascension_tier` в области `this`) и прибавляет единицу. Чтение уровня проверяется в игре отдельно для планеты и ковчега. Границу обеспечивает проверка перед начислением. Прочие ванильные события продолжают пользоваться исходной формулой.

## Повторяемая технология

В определении `ui_tech_ascension_theory_repeatable` удалить строку `ai_update_type = all`, которую парсер игры 4.6.0 отклоняет. Сохранить исходные стоимость, условия появления, веса для исследований и ИИ, предел уровней и прибавку в одну ячейку бонуса за стремление за каждое завершённое исследование. Настройки числа ячеек и события сабмода работают по его существующим правилам.

## Состав и порядок загрузки

Игровые файлы первого этапа находятся в каталоге UIOD_RUS.

| Файл | Назначение |
|---|---|
| `common/scripted_effects/uiod_psionic_auras_scripted_effects.txt` | Заменяет одноимённый файл Ascension Slots с единственным определением ауры. |
| `common/script_values/uiod_rus_ascension_values.txt` | Содержит расчёт следующего уровня для ауры. |
| `common/technology/ui_tech_ascension_theory_repeatable.txt` | Заменяет одноимённый файл Ascension Slots с исправленной технологией. |

Порядок сверху вниз в лаунчере: UI Overhaul Dynamic → UI Overhaul Dynamic - Ascension Slots → UIOD_RUS. Совпадение путей двух файлов нужно для замещения файлов сабмода. Ванильный файл с остальными аурами загружается целиком. При реализации обновить целевую версию UIOD_RUS до `v4.6.*`, манифест, перечень файлов поставки, инструкцию и учёт затронутых функций. При последующих обновлениях Ascension Slots два одноимённых файла требуют сверки с новой версией автора.

## Проверка и приёмка

1. Синтетически проверить конечные определения с указанным порядком загрузки. Сверить технологию с исходной построчно, эффект с двумя ветками ванили, разрешение ссылки на новое значение и поставку с двумя действующими файлами русской локализации.
2. В игре проверить, что из `error.log` исчез `Unexpected token: ai_update_type`, а игра использует исправленный эффект. Предупреждение о переопределении ванильного ключа ауры возможно и с рабочей заплаткой.
3. Определять фактический уровень через `has_planetary_ascension_tier`. При лимите выше 10 проверить переходы 9 → 10 и 10 → 11 на отдельной планете и ковчеге. Проверить остановку на заданном лимите, в том числе при лимите ниже 10. У уже превысившей лимит колонии уровень сохраняется.
4. Проверить повторное срабатывание до истечения десятилетнего флага и повышение после его истечения. Проверить счётчик затронутых колоний, пропуск чужих и оккупированных колоний, уведомление кочевой державе в системе без её базы.
5. Проверить технологию с включённой и отключённой опцией Ascension Slots. При включённой опции завершённое исследование даёт одну ячейку. Игровые проверки проводит пользователь после реализации.

## Возможный второй этап — знаки уровней роста колонии

В окне колонии UI Overhaul Dynamic виджет `ascension_tier_icon` использует ванильный `GFX_ascension_tier`. В `interface/icons.gfx` для него указаны 11 кадров текстуры `gfx/interface/icons/leaders/leader_skill.dds`. В самой текстуре (209 × 22 пикселя) первый кадр — пустой контур, следующие десять — знаки I–X. Рядом с иконкой имеется отдельная подпись `ascension_tier`; локализация `PLANET_ASCENSION_TIER` принимает число через `$TIER|Y$`. Наличие подстановки само по себе не подтверждает, что движок выводит подпись на уровнях 11–100.

Решение о втором этапе принимается отдельно. Если вернёмся к знакам, сначала проверить на двух пробных кадрах для уровней 11 и 100, может ли виджет показать их из отдельного атласа. Это позволит оценить читаемость трёх цифр при размере кадра 19 × 22 пикселя и сохранить общий атлас значков лидеров.
