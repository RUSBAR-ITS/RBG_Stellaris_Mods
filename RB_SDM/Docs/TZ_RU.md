## Назначение и поставка

**Утверждено 22 ноября 2026 года. Реализация 0.0.1.** RUSBAR Stellaris Dynamic Menu — самостоятельный мод-шаблон, из которого автор может перенести событийное меню в свой мод. Целевая установка — ванильная Stellaris v4.5.4. Первый игровой комплект имеет версию `0.0.1` и поле `supported_version="v4.5.*"`. Все собственные игровые идентификаторы начинаются с `rb_sdm_`, события используют пространство имён `rb_sdm`.

В каталоге `RB_SDM/mod/` размещаются `descriptor.mod`, игровые скрипты и локализации RU/EN. Руководство в корне проекта и документы в `Docs/` хранятся вне игрового комплекта. Шаблон работает самостоятельно, включая запуск без DLC. Перенос меню в PDE — отдельная задача. [Руководство](../README_RU.md)

## Точка входа и доступ ИИ

В демонстрации точкой входа служит планетарное решение на собственной колонии. Оно знает планету и страну-инициатора (`from`). Событийному меню для открытия нужны страна и сохранённая цель `event_target:rb_sdm_target`. Их может передать и другое событие. Фильтрация, порядок и разбивка на страницы общие. В первом выпуске триггеры и эффекты демонстрационного каталога ожидают планету. Для каталога с целью другого типа автор подбирает триггеры и эффекты для соответствующей области.

**Доступ к конкретному решению задаёт автор мода.** У демонстрационного решения один переключатель — скриптовый триггер страны `rb_sdm_open_menu_ai_enabled`. Значение по умолчанию — `always = no`. Чтобы разрешить ИИ принимать решение, автор меняет его на `always = yes`. Это настройка в файлах мода. Копия решения с собственным переключателем настраивается независимо.

| Инициатор | Доступность и результат |
|---|---|
| Игрок, любое значение переключателя | При выполнении обычных условий решение открывает меню на выбранной колонии. |
| ИИ, выключено | Условие `potential` исключает решение для этой страны, его `ai_weight` равен нулю. |
| ИИ, включено | На подходящей собственной колонии решение получает положительный `ai_weight` и может быть выбрано движком. При принятии решения запускается действие для ИИ. |

Обе проверки решения используют один переключатель для страны-инициатора. Условия на саму колонию действуют в обоих режимах. При исполнении решение повторно проверяет тип инициатора и разрешение ИИ. Для игрока оно открывает родительское окно, для ИИ вызывает отдельный обработчик с той же целью. В демонстрации используется скрытое событие страны, которое выбирает первый доступный пункт каталога, проверяет его `VISIBLE`, выполняет его `ACTION` один раз и очищает временные данные. При пустой выборке вызов завершается без действия. При переносе шаблона автор задаёт своё действие ИИ. Окна и навигация относятся к сеансу игрока.

## Поведение меню

У раздела есть упорядоченный каталог и положительный целый размер страницы `S`. В демонстрации `S = 10`. При входе в раздел меню проверяет условия для выбранного объекта, пропускает недоступные пункты и сохраняет относительный порядок доступных. Их число обозначено `N`. При `N > 0` меню показывает `ceil(N / S)` страниц. На странице `p` видны доступные пункты с номерами от `(p − 1) × S + 1` до `min(p × S, N)` включительно. Нумерация начинается с единицы.

Вход из родительского меню открывает страницу 1. Кнопки «Предыдущая» и «Следующая» показываются только при наличии соседней страницы. «Назад» возвращает в родительское меню, «Закрыть» завершает сеанс. Все четыре кнопки располагаются после списка и стоят вне лимита `S`. Заголовок или описание показывает текущую страницу и их общее число через подстановки.

После действия открывается та же страница с обновлённым списком. Если она исчезла, открывается последняя существующая. При `N = 0` раздел показывает сообщение «Нет доступных пунктов», «Назад» и «Закрыть». В этом состоянии счётчик страниц и кнопки листания скрыты.

## Каталог и пересчёт

Автор ведёт один каталог на раздел. Запись содержит стабильный идентификатор, ключ подписи, ключ подсказки, имя триггера доступности и имя эффекта. Порядок записей определяет порядок показа. Подпись, подсказка и действие принадлежат записи на любой странице.

Один и тот же каталог подключается как параметризованный `inline_script` в двух местах одного `country_event` раздела. При подготовке окна, в `immediate`, записи разворачиваются в упорядоченные проверки. В теле события те же записи разворачиваются в обычные `option`, каждая со своим условием показа. Размер страницы задаётся один раз на раздел. Ручная таблица соответствия пунктов страницам не требуется.

1. При открытии, перелистывании и после действия обнулить общий счётчик. Обойти каталог один раз. Каждому доступному пункту присвоить следующий номер, начиная с 1. Недоступному записать 0, в том числе если раньше он был доступен.
2. По итогу обхода вычислить число страниц и ограничить запрошенную страницу фактическими границами. Вычислить первый и последний номера этой страницы.
3. Каждая `option` проверяет сохранённый номер своей записи на попадание в эти границы. При пустом результате скрыть все содержательные кнопки. Пересчёт вызывают события меню. Повторная проверка выбранного пункта при нажатии описана ниже.

Для 200 кандидатов один пересчёт выполняет 200 проверок доступности. Само событие содержит 200 объявленных содержательных кнопок с простыми проверками номера. Фактическое время открытия оценивается в игре. Основание проекта — параметризованные `option` в ванильном `common/inline_scripts/grand_archive/collection/stage_3_reward_option.txt` и операции над переменными из `events/000_how_to_use_variables_in_script.txt`.

## Состояние и выбор пункта

Модель — один открытый сеанс на страну. Страна игрока является `ROOT` окна и хранит признак сеанса, запрошенную страницу, счётчики и номера пунктов. Входное решение сохраняет планету как `event_target:rb_sdm_target` в цепочке событий. Условия и действия записей выполняются в области этой планеты. Сеансы разных стран независимы.

Пока сеанс открыт, повторный вход через решение не создаёт второе окно для этой страны. «Назад» сохраняет сеанс, а повторный вход в раздел начинает с первой страницы. «Закрыть» освобождает сеанс и удаляет его служебные данные. При утрате цели переход завершает сеанс. Для штатного завершения окна движком проверить тот же результат, в том числе возможность вновь открыть решение.

Перед применением эффекта проверить наличие цели и доступность **той записи, которую нажал игрок**. Если запись за время показа стала недоступной, пропустить эффект и обновить список. Номер строки на экране никогда не определяет, какой эффект выполнить.

## Демонстрационный раздел

Вход открывает бесплатное мгновенное решение на собственной колонии страны-инициатора. Для игрока оно открывает родительское меню с одним демонстрационным разделом. Раздел содержит 21 пронумерованный пример и выводит их по 10. Выбор скрывает соответствующий пример до конца сеанса. При следующем открытии через решение все 21 пример снова доступны. Это позволяет воспроизвести сдвиг пунктов между страницами без изменения депозитов или экономики колонии.

## Приёмка

| Синтетический сценарий при S = 10 | Ожидаемый результат |
|---|---|
| Доступны 0, 1, 10 и 11 пунктов | Пустое состояние, затем размеры страниц `[1]`, `[10]`, `[10, 1]` соответственно. |
| Из 200 доступны чётные идентификаторы от 2 до 178 | 89 пунктов на 9 страницах. Первая содержит 2, 4, …, 20. Девятая содержит 162, 164, …, 178. Конкатенация страниц даёт все 89 ровно по одному разу. |
| Из 200 доступны только 191–200 | Одна полная страница, стрелок листания нет. |
| Доступны все 200 | 20 полных страниц. Первая и последняя открывают только существующего соседа. |
| Из списка 1–21 удалён пункт 1 | На первой странице теперь 2–11. Бывшая третья страница исчезла. |
| На странице 3 списка 1–21 удалён пункт 21 | Открывается страница 2 с пунктами 11–20. При удалении единственного оставшегося пункта раздел переходит в пустое состояние. |
| Размер страницы изменён на 3, доступны 7 пунктов | Размеры страниц `[3, 3, 1]`. Навигация по-прежнему вне лимита. |

В реализации синтетически проверить также уникальность ID, соответствие кнопки своему триггеру и эффекту, наличие RU/EN ключей, связность событий и состав игрового комплекта. Проверять фактический каталог и развёрнутые скрипты наряду с расчётом ожидаемых страниц.

Для решения проверить все четыре сочетания инициатора (игрок или ИИ) и значения переключателя. В скриптах сверить область страны, условия доступности, вес и ветку исполнения. В игре пользователь проверяет доступ игрока в обеих конфигурациях, отсутствие вызовов при запрете ИИ и фактическое принятие решения ИИ при разрешении. При состоявшемся вызове проверить целевую колонию, одно действие при наличии доступного пункта и отсутствие сеанса меню у ИИ. Положительный вес означает возможность выбора, срок принятия решения движком не фиксирован.

В установленной игре пользователь проверяет вход через решение, порядок и подписи кнопок, подсказки, листание в обе стороны, сдвиг после выбора, пустое состояние, «Назад», закрытие и повторное открытие. Отдельно проверить изоляцию стран, повторный вызов во время сеанса, смену доступности и утрату цели при открытом окне. Статус игровых проверок фиксируется после прогона.
