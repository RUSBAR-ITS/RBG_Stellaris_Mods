## Что делает шаблон

RUSBAR Stellaris Dynamic Menu показывает доступные действия для выбранного объекта в порядке, который задал автор. Если из 200 действий доступны 89, а на страницу помещается 10, игрок получает восемь полных страниц и последнюю с девятью действиями. Добавить действие между двумя существующими можно, вставив одну запись между ними в каталоге.

**Версия 0.0.1 для Stellaris v4.5.*.** Игровой комплект находится в [mod/](mod/). Реализация проверена синтетически на данных v4.5.4. Игровая проверка ожидается. [Техническое задание](Docs/TZ_RU.md) · [История изменений](Docs/CHANGELOG_RU.md) · [Учёт ванильных изменений](Docs/VANILLA_CHANGES_RU.md)

## Как опробовать меню

Демонстрация работает в оригинальной игре, в том числе без DLC.

1. Подключите каталог `RB_SDM/mod/` как локальный мод и включите его в игровом наборе. Откройте решения на собственной колонии и выберите «Открыть динамическое меню».
2. Откройте демонстрационный раздел. На первой странице отображаются примеры 1–10 из 21. Нажмите «Следующая» дважды, чтобы увидеть пример 21.
3. Выберите пример 21. Он исчезнет до конца сеанса, и меню откроет страницу 2 из 2 с примерами 11–20.
4. Перейдите на первую страницу и выберите пример 1. Освободившееся место займёт пример 11, а на второй странице останутся 12–20.
5. Нажмите «Назад» и вернитесь в раздел. Он откроется с первой страницы с учётом уже скрытых примеров. Нажмите «Закрыть» и откройте решение заново, чтобы увидеть исходный 21 пункт.

## Как разрешить ИИ принимать решение

Переключатель находится в файле [настроек решения](mod/common/scripted_triggers/rb_sdm_decision_settings.txt). Для доступа только игроку оставьте исходное определение.

```text
rb_sdm_open_menu_ai_enabled = { always = no }
```

Замените `always = no` на `always = yes`, чтобы ИИ мог принимать это решение на подходящей собственной колонии. Решение использует этот триггер для допуска страны и расчёта веса. Игрок в обоих режимах открывает обычное меню. ИИ при принятии решения получает выбранную колонию и выполняет действие, предусмотренное автором. В демонстрации это первый доступный пункт. При копировании решения дайте его переключателю новое имя, если требуется независимая настройка.

Планетарное решение — готовый вход для демонстрации. Чтобы открыть меню из другого события, сохраните планету как `event_target:rb_sdm_target` и вызовите родительское событие для страны игрока. У такого входа свои условия допуска. При смене типа цели проверьте область триггеров и эффектов своего каталога. [Точка входа и доступ ИИ](Docs/TZ_RU.md#точка-входа-и-доступ-ии)

## Как перенести раздел в свой мод

1. Из игрового комплекта перенесите шаблоны `common/inline_scripts/rb_sdm/`, служебные `scripted_effects` и `scripted_triggers`, родительское событие, событие списка и общие строки RU/EN. Замените префикс `rb_sdm_`, пространство событий `rb_sdm` и пути включений согласованно во всех копиях. Собственный дескриптор остаётся у принимающего мода.
2. Свяжите точку входа своего мода с родительским событием. В варианте с планетой решение сохраняет цель как `event_target:rb_sdm_target` и открывает событие для страны игрока. Вызовите публичное событие `rb_sdm.1`. Оно проверяет страну, цель и открытый сеанс. После смены префикса используйте новое имя цели во всей цепочке.
3. По образцу демонстрационного раздела задайте ключи заголовка и описания, родительское событие, упорядоченный каталог и целый размер страницы больше нуля. Для второго раздела создайте отдельный каталог и событие списка. В родительском окне `rb_sdm.2` задайте для кнопки раздела начальную страницу 1 и переход к его списку. В `rb_sdm_end_session` добавьте проход очистки нового каталога, чтобы удалить номера и временное состояние его записей.
4. Событие списка подключает этот каталог в `immediate` в режиме `rank` и в теле события в режиме `option`. Первый проход вычисляет номера для выбранной цели. Второе включение объявляет кнопки. Общий шаблон навигации использует тот же размер страницы. Чтобы изменить ёмкость с 10 на 6, замените `SIZE = 10` на `SIZE = 6` в `rb_sdm_begin_count` события списка `rb_sdm.3`. [События](mod/events/rb_sdm_events.txt) · [Эффекты меню](mod/common/scripted_effects/rb_sdm_menu_effects.txt)

## Как добавить пункт

Ниже приведена запись примера 7. Добавляя новый пункт, задайте уникальный ID, существующие триггер, эффект и строки локализации. Вставьте запись на нужное место относительно соседей. Параметр `PASS` выбирает операцию, `SCREEN` передаёт ID окна для возврата. [Каталог демонстрации](mod/common/inline_scripts/rb_sdm/rb_sdm_catalog_demo.txt)

```text
inline_script = {
    script = "rb_sdm/rb_sdm_$PASS$"
    ID = rb_sdm_demo_07
    LABEL = rb_sdm_demo_07_label
    TIP = rb_sdm_demo_tip
    VISIBLE = rb_sdm_demo_07_visible
    ACTION = rb_sdm_demo_07_select
    SCREEN = $SCREEN$
}
```

| Поле | Что задаёт автор |
|---|---|
| `ID` | Уникальный в моде ключ пункта. При перемещении записи ключ сохраняется. |
| `LABEL`, `TIP` | Ключи подписи и подсказки. Добавьте обе строки для RU и EN. Существующие игровые названия подключайте по ключу локализации. |
| `VISIBLE` | Имя скриптового триггера. Он получает выбранную планету и отвечает, доступно ли действие сейчас. Для демонстрационного пункта 7 условие проверяет, выбирали ли его в этом сеансе. |
| `ACTION` | Имя скриптового эффекта в той же области планеты. У примера 7 он помечает этот пример выбранным для текущего сеанса страны игрока. Пересчёт страницы выполняет шаблон. |

Если пункт изначально был одиннадцатым, удаление доступного пункта выше поднимет его на первую страницу. Его ключ, подсказка и действие останутся привязаны к одной записи. Так один и тот же каталог подходит для списка команд, вариантов выбора или типов депозитов.

## Как проверить свой каталог

Проверьте полный список, разреженный список и пустую выборку на одной цели. Особенно показателен случай, когда доступны только последние 10 из 200 записей. Все десять должны появиться на первой странице в исходном порядке. Для проверки привязки выберите пункт, который только что перешёл с другой страницы, и убедитесь, что выполнилось именно его действие.

Если раздел пуст при ожидаемых результатах, проверьте сохранённую цель и область `VISIBLE`. Если подпись верна, а эффект получает другой объект, проверьте область `ACTION`. Если счётчик верен, но видны пропуски, сверьте путь и порядок каталога в обоих включениях. Полная таблица ожидаемых результатов приведена в [критериях приёмки](Docs/TZ_RU.md#приёмка).
