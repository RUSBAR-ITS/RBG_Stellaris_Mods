## Назначение

**Утверждено и реализовано.** Новый сервер находится в `WEB_STTV/src/server/` и работает как самостоятельное приложение со своим конфигом подключения. Источник игровых локализаций — опубликованная коллекция `wiki.localization`. Сервер определяет ключ по игровому значению и позволяет читать один или несколько переводов. Для обеих операций достаточно доступа на чтение. [Запуск и результаты проверок](../README_RU.md)

## Определение ключа

Внутренняя функция получает контекст и игровое значение, возвращает ключ с точным регистром. Соответствия задаются в [отдельном файле правил](../config/localization_keys.json). При запуске сервер читает его по пути `localization_keys_file`, указанному относительно [конфига сервера](../config/server.json). Выбор ключа одинаков для русского и английского. Готовый ключ вызывающий код может сразу передать в поиск.

| Контекст | Правило первого этапа | Пример |
| --- | --- | --- |
| Название области науки | Явные соответствия для трёх областей | `physics → PHYSICS`, `society → SOCIETY`, `engineering → ENGINEERING` |
| Название научной категории | Идентификатор категории | `computing → computing` |
| Базовое название технологии | Идентификатор технологии | `tech_titans → tech_titans` |
| Базовое описание технологии | Идентификатор технологии с суффиксом `_desc` | `tech_titans → tech_titans_desc` |

Для неизвестного контекста или отсутствующего явного соответствия функция сообщает, что ключ определить не удалось. Существование вычисленного ключа проверяет операция поиска. Правила для базовых полей применяются, когда вызывающему коду нужно обычное название или описание по ID. Выбор варианта технологии и наследование её описания относятся к работе с объектом.

## Поиск строк

Публичный вызов `POST /api/localization/lookup` принимает один язык (`ru` или `en`) и массив точных ключей. Для одной строки достаточно массива с одним элементом.

```json
{"language":"ru","keys":["PHYSICS","tech_titans","__missing_example__"]}
```

```json
{
  "language": "ru",
  "items": [
    {"key": "PHYSICS", "text": "Физика"},
    {"key": "tech_titans", "text": "Титаны"},
    {"key": "__missing_example__", "text": null}
  ]
}
```

Поиск читает уникальные ключи пакета по индексу составного `_id` вида `{language, key}`. Сервер берёт исходную строку из `definitions[selected].raw` и раскрывает доступные ссылки при чтении. Поле `selected` уже указывает на определение нужного приоритета. Ответ сохраняет порядок и повторения исходного запроса. Отсутствующему ключу в запрошенном языке соответствует `null`, существующей пустой строке — `""`. Обе ситуации допускают HTTP 200. Некорректный запрос возвращает 400, недоступность БД — 503.

В `text` каждая обычная ссылка `$KEY$` раскрывается рекурсивно в том же языке, если словарь позволяет определить текст. Например, `physics_research` содержит `$concept_physics_research$` и возвращает «Физические исследования» для `ru` и «Physics Research» для `en`. Если связанный ключ отсутствует, ссылка замыкает цикл или подстановка требует игрового контекста, сервер сохраняет этот фрагмент в исходном написании. Например, `[Root.GetName]` остаётся в тексте. Остальные части строки раскрываются независимо. Игровая разметка сохраняется. Для каждого следующего шага сервер может запросить неизвестные ключи пакетом и повторно использовать уже прочитанные определения в пределах запроса.

## Проверка на сервере

Код разрабатывается в монорепозитории. Для приёмки копируем новую серверную часть в отдельный рабочий каталог на Ubuntu VM, запускаем её там и обращаемся по HTTP к этому экземпляру. Он читает действующую `wiki.localization` через локальное TLS-подключение. При повторном прогоне можно очистить выделенный каталог этого прогона. MongoDB, её данные и конфигурация службы находятся вне области очистки. Дополнительное ПО для тестов предварительно согласуется.

- Сверить определение ключей для трёх областей, категории и базовых полей технологии. Проверить неизвестный контекст и неизвестную область.
- Запросить `PHYSICS` и `tech_titans` по одному и вместе на обоих языках. Ожидаемые значения — «Физика»/«Physics» и «Титаны»/«Titans».
- Запросить `PHYSICS`, отсутствующий ключ и повторно `PHYSICS`. Проверить порядок, повтор, обозначение пропуска и точность регистра.
- Проверить раскрытие `physics_research` на обоих языках. На небольших примерах проверить цепочку ссылок, цикл и строку, содержащую одновременно разрешимую ссылку, отсутствующий ключ и динамическую подстановку. Эти примеры можно проверить в памяти процесса на VM.
- Сверить строки без ссылок с выбранным определением в MongoDB и проверить ошибку неверного языка.
