## Объём

Статус — проект на согласование, приложение к общему ТЗ. В Stellaris 4.5.4 (1b4f) у девяти базовых технологий три раздела получения пусты, хотя в скриптах прослеживается награда. Ещё у 19 стартовых технологий страница опускает условия начальной выдачи. Это 28 разных технологий. Цель первой итерации — дать одинаковый, проверяемый ответ в тултипе карточки и на странице на RU и EN. Полный объём исправлений и общая приёмка определены в основном документе. ## Девять скриптовых наград

В существующем разделе награды указывать, что может сделать игрок, кому достанется результат и какой именно. Для семи тайн предтеч путь начинается с действия с малыми артефактами. Империя открывает именной спецпроект, успешно завершает его и в соответствующем исходе получает **+10% прогресса**. Показывать доступность действия и условия ответа по игровым определениям. Например, исследование ирассианских тайн требует обнаружить их мир и доступно до первого запуска действия. Проект создаётся для империи, выполнившей действие. ## Условия стартовой выдачи

Для базовой технологии с `start_tech = yes` и непустым `starting_potential` добавить подзаголовок **«Получение на старте» / “Starting eligibility”** в раздел условий доступности, после существующих условий. Стартовой метке на карточке по-прежнему соответствует `start_tech`. Подзаголовок объясняет только старт. Общие ограничения из `potential` видны рядом, даже если отдельный стартовый блок содержит только проверку гражданских моделей. При отсутствии стартового условия подзаголовок опускается. Правила отбора для дерева остаются отдельной задачей.

| Условие в ванильном определении | Контрольные технологии |
|---|---|
| `is_nomadic = no` | `tech_solar_panel_network`, `tech_starbase_1`, `tech_starbase_2`, `tech_space_defense_station_1`, `tech_mechanized_mining`, `tech_colonization_1` |
| `is_nomadic = yes` | `tech_nomads_mechanized_mining`, `tech_waystation_1` |
| `is_low_tech_start = no` | `tech_basic_science_lab_1`, `tech_planetary_government`, `tech_maulers`, `tech_weavers`, `tech_weaver_bio_evasion_1`, `tech_weaver_bio_anti_evasion_1` |
| `is_low_tech_start = no` + `country_uses_bio_ships = no` | `tech_corvettes` |
| `is_eager_explorer_empire = yes` | `tech_subspace_drive` |
| `is_eager_explorer_empire = no` | `tech_hyper_drive_1` |
| `is_wilderness_empire = yes` | `tech_wilderness_terraform` |
| `has_origin = origin_fruitful` | `tech_critter_feeder` |

Показывать результат раскрытия скриптовых проверок с действительными названиями и исходной логикой И/ИЛИ/отрицания. У подпространственного двигателя в общем условии указан First Contact, а на старте требуется **одна из четырёх** гражданских моделей: `civic_eager_explorers`, `civic_privatized_exploration`, `civic_hive_stargazers`, `civic_machine_exploration_protocol`. У гипердвигателя стартовая проверка имеет обратный смысл. У корветов оба ограничения обязательны. «Низкотехнологичный старт» охватывает и досветовую цивилизацию, и два происхождения, и группу исследовательских гражданских моделей. [Двигатель](E:/SteamLibrary/steamapps/common/Stellaris/common/technology/00_first_contact_tech.txt:418) · [Определения двух проверок](E:/SteamLibrary/steamapps/common/Stellaris/common/scripted_triggers/00_scripted_triggers.txt:3877)

## Импорт и серверный контракт

1. Добавить весь `common/artifact_actions/*.txt` в профиль парсера и соответствующий путь артефактов в загрузчик. Одно именованное корневое определение — один документ коллекции `artifact_actions`, ключом служит имя блока. Сохранить происхождение в `artifact_actions_provenance` по правилам загрузчика. В эталонном файле 28 уникальных определений. Локальные объявления `@` обрабатывает парсер. Сведения о событиях, проектах, ситуациях и технологиях уже импортируются. [Профиль парсера](../../../config/parser_sources.json) · [Профиль загрузчика](../../../config/loader.json)
2. На сервере добавить действия с артефактами как точки входа. Прослеживать исполняемые вызовы, в том числе внутри `hidden_effect`, до команды награды. Сохранять условия входа, выбора ветви, назначения получателя и адреса команды. Для Инакса учитывать переназначение `scopes.from` в месте вызова. Для ситуации проверять роль `target` в соответствующей ветви. При недоказанной связи сохранять диагностику с исходным адресом. Применять правила к данным, игровые ID из таблиц служат контрольными примерами. [Обход источников](../sttv_server/progress_sources.py) · [Пути вызова](../sttv_server/acquisition_paths.py)
3. В ответе `POST /api/trees/technology-tooltip` добавить необязательный массив `sections.starting_potential` стандартного типа выражений. Три вида скриптовых наград используют ключи `research_options`, `researched_grants`, `research_progress`. Для выключенного подтверждённого DLC применять существующую отметку источника. Сервер подбирает RU/EN-названия и формулировки. Общий компонент фронтенда отображает полученные узлы и локализованный подзаголовок. [Обработка условий](TZ_CONDITION_TEXT_RU.md) · [Компонент карточки и страницы](../../frontend/ui/composite/TechnologyTooltipDetails.tsx)
4. Подключить входные коллекции и правила к действующему механизму ревизий индекса источников и коллекции `technology_tooltips`. Повторное открытие использует подготовленный документ. После изменения входа или сброса производных данных следующий запрос получает актуальные пути и условия. [Обслуживание кеша](../sttv_server/tree/service.py)

## Приёмка

- **Импорт.** Сопоставить ID всех 28 действий в исходнике, артефактах и MongoDB. Для семи действий пройти от исходного `enable_special_project` до события и сверить адреса и величины во всех 17 местах начисления. Профилей проекта должно хватать для воспроизведения результата.
- **Награды.** На RU и EN проверить все девять строк по приведённым цепочкам. Для Инакса проверить обе ветви выбора получателя, другое происхождение, уже изученную технологию и общий результат всех реплик. Для машины материальности проверить нужный исход ситуации, успех проекта, задержку и тип награды. Тестовое событие, описательная подсказка и выдача отдельной NPC-империи остаются отрицательными контролями.
- **Старт.** Проверить все 19 ID таблицы. В каждой локализации блок должен появиться ровно на этих 19 базовых страницах. У остальных 23 из 42 стартовых технологий сохраняется стартовая метка без пустого подзаголовка. Для обеих полярностей исследовательских гражданских моделей и для корветов сверить вложенность и локализованные имена. Сопоставить страницу и тултип при одинаковых настройках.
- **Регрессия.** Повторно открыть в браузере все 679 базовых страниц на RU и EN со всеми DLC. Сравнить с аудитом исходные идентификаторы источников, типы наград, ветви, адреса, проценты, подписи, значки и разметку. Эталон — 478 технологий хотя бы с одним источником, после девяти исправлений ожидается минимум 487. Дополнительные пути, обнаруженные общим правилом, внести в отчёт по ID с доказательствами из игры. Каждое исчезновение прежнего источника или изменение его смысла разобрать отдельно. Проверить один запрос с отключённым применимым DLC, чтение из прогретого кеша и сброс с повторной сборкой.
- **Результат.** Сохранить отчёт «до/после» по технологиям, ожидаемым изменениям и оставшейся диагностике в каталоге прогона. Проверка страниц удостоверяет отображение и соответствие скриптам. Фактическое получение в партии остаётся игровой проверкой пользователя. [Исходный аудит](TECHNOLOGY_ACQUISITION_AUDIT_RU.md) · [Браузерная сверка](../../../tests/frontend/conditionPages.mjs)
