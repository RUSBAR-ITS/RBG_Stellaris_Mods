## Охват

Снимок Stellaris v4.5.4 (1b4f). Сверены 679 базовых технологий и 1 506 компонентов из опубликованной MongoDB с данными страниц того же снимка. Прочитаны 436 именованных проектов из 39 файлов, включая модули корпуса и `required_component`. Для употреблений просмотрены скрипты основной установки, распакованные DLC и содержимое 32 архивов DLC. Таблицы ссылаются на пример точного компонента в проекте и место создания корабля.

Пустая карточка в этом отчёте означает отсутствие всех трёх разделов получения (вариант исследования, полная выдача, прогресс). Условия доступности и модификаторы веса могут присутствовать. У 201 технологии эти разделы пусты. У 97 технологий единственное явное значение базового веса равно нулю. У 81 из них уже показана награда, у 16 разделы пусты. Ещё у 38 из всех 679 отсутствует поле веса.

## Очередь исправлений

1. В индекс источников прогресса добавить связи по компонентам оружия, защиты и обязательному оснащению. Для фиксированных носителей понадобятся проекты из `common/global_ship_designs`, ссылки на создание кораблей и условия образования и изучения обломков. Сохранять отдельно технологию, компонент, проект, место создания, известные запреты и версионный коэффициент. Компонент с несколькими пререквизитами требует отдельной проверки выбора технологии движком.
2. Сначала проверить в игре шесть приоритетных путей. Контрольные случаи — корабль с запретом обломков, уже изученная технология, флот с защитой от обратной разработки и политика разбора обломков. После проверки добавить альтернативный путь для «Искусственной драконьей чешуи», у которой уже есть два раздела наград.
3. Для предтеч подключить каталог действий с артефактами и восстановить путь до спецпроекта. Проверить достижимость двух событийных цепочек выше и различать полную выдачу, открытие варианта и процент прогресса.
4. Отдельно обработать стартовую доступность. Для контроля веса оставить три случая с двумя объявлениями отдельной группой: `tech_dyson_swarm` (0 и 70), `tech_dyson_gun` (0 и 50), `tech_orbital_arc_furnace` (0 и 70). В отчёте сохранены оба значения в игровом порядке.

Для реализации понадобятся два дополнения к профилям импорта: проекты из `common/global_ship_designs` и действия из `common/artifact_actions`. Компоненты, события, ситуации, спецпроекты, политики и инициализаторы уже импортируются. Сопоставление носителей относится к серверному индексу, связывание наград с началом цепочки — к обходу путей вызова. [Профиль парсера](../../../config/parser_sources.json) · [Профиль загрузчика](../../../config/loader.json) · [Индекс источников](../sttv_server/progress_sources.py) · [Обход путей](../sttv_server/acquisition_paths.py)

Базовый процент брать из `DEBRIS_ANALYZED_TECH_PROGRESS` для соответствующей версии игры. Для проектов кораблей учитывать также вызовы в раскрытых игровых эффектах.

Проверка устанавливает статический путь до носителя. Состав обломков конкретного боя, захват вместо уничтожения, поздние изменения настроек флота, процедурные проекты империй и эффекты с динамическим именем проекта требуют отдельного подтверждения. Для исследования и сбора ресурсов в игре предусмотрены разные политики.
