## Запуск на Ubuntu

На VM `stellaris-wiki` стенд запускается службами `rit-mongodb-wiki`, `sttv-reference` и `sttv-frontend`. Проверить состояние можно командой `systemctl is-active rit-mongodb-wiki sttv-reference sttv-frontend`. Браузер обращается к порту 5173, загрузчик подключается к MongoDB по TLS на порту 27017. Правила nftables используют исходную подсеть `192.168.1.0/24`. При следующей смене IP проверьте адреса клиентов, привязку SSH-ключа и соответствие адреса сертификату MongoDB.

Из каталога `WEB_STTV/src/server` или его копии на VM выполните команду в окружении с Python 3.10+ и PyMongo 4.19.0. Передайте пароль MongoDB через переменную окружения `STTV_MONGO_PASSWORD`.

```sh
python3 -B -m sttv_server --config config/server.json
```

По умолчанию сервер слушает `127.0.0.1:8788` и читает коллекцию `wiki.localization` по TLS с `127.0.0.1:27017`. Адреса HTTP и MongoDB, путь к доверенному CA, имя БД и коллекция задаются в [конфиге сервера](config/server.json).

## Поиск перевода

```sh
curl -sS http://127.0.0.1:8788/api/localization/lookup \
  -H 'Content-Type: application/json' \
  -d '{"language":"ru","keys":["PHYSICS","physics_research","tech_titans"]}'
```

Ответ содержит поле `language` и массив `items` с парами `key` и `text` в запрошенном порядке. В этом примере значения — «Физика», «Физические исследования», «Титаны». Отсутствующему ключу соответствует `null`, пустому переводу — `""`. Сервер раскрывает статические ссылки для выбранного языка. Неразрешимые ссылки, игровая разметка и выражения с игровым контекстом сохраняются в тексте. [Контракт API](Docs/TZ_LOCALIZATION_API_RU.md)

## Выбор ключа в коде

Правила хранятся в [localization_keys.json](config/localization_keys.json). Поле `localization_keys_file` в `server.json` указывает путь к этому файлу относительно каталога `server.json`. Сервер читает правила при запуске.

Внутренняя функция `sttv_server.localization.determine_key(rules, context, value)` получает загруженные правила и возвращает точный ключ или `None`. Поддерживаются контексты `research_area`, `research_category`, `technology_name`, `technology_description` и `dlc_project_name`. Например, пара `research_area` и `physics` даёт `PHYSICS`. В HTTP-запрос передаётся готовый ключ.

## Содержимое тултипа

Запросите одну базовую технологию по игровому ID и языку. Для этого запроса достаточно документов MongoDB и локализации. [Правила содержимого](../../Docs/frontend/TZ_TECHNOLOGY_TOOLTIP_CONTENT_RU.md)

```sh
curl -sS http://127.0.0.1:8788/api/trees/technology-tooltip \
  -H 'Content-Type: application/json' \
  -d '{"technology_id":"tech_titans","language":"ru"}'
```

Ответ содержит `technology_id`, `language`, `name`, `description`, `sections` и `diagnostics`. Пустые разделы пропускаются. В `prerequisites`, `potential` и `allow` каждый исходный блок образует отдельное выражение. У логической группы есть `operator` и массив `children`. Записи `weight_modifier` идут в порядке исходного файла. Внутри `modifier` операцию и все её условия нужно читать вместе. У вычисляемого множителя может быть `formula` с шагами вычисления или `trigger`, называющий зависимость от состояния игры.

Готовая подпись узла находится в `text`. Для неизвестного узла возвращаются `kind = unrecognized` и исходное `expression`. При отсутствии названия условие сохраняет игровой ID, а `diagnostics` указывает недостающий ключ. Если технологию найти не удалось, сервер возвращает HTTP 404. Для неподдерживаемого языка или некорректного тела запроса возвращается HTTP 400. [Проверка API на игровых примерах](tests/tooltip_acceptance.py)

## Дерево технологий

Откройте стенд в браузере и выберите **Древо технологий**. В разделе **Настройки игры → DLC** измените выбор и нажмите **Применить**. Переключатель режима находится во вкладке **Настройки империи**. Очистка сохранённых деревьев доступна в **Настройки системы → Операции с БД**. [Стенд](http://192.168.1.36:5173/)

Опубликованный интерфейс на VM передаёт запросы к `/api/trees/` и `/api/localization/` серверу по HTTP. Игровые PNG раздаются с `/game-assets/`. При разработке адрес API для Vite задаёт `STTV_SERVER_URL`, базовый URL изображений при сборке задаёт `VITE_STTV_ASSETS_URL`.

| Запрос | Результат |
| --- | --- |
| `GET /api/trees/reference/dlcs` | ID, названия RU/EN и относительный путь PNG в `thumbnail` или `null` |
| `POST /api/trees/reference` с `{}` | Дерево со всеми DLC |
| Тот же запрос с `{"enabled_dlc":[]}` | Дерево без DLC. В массив можно передать выбранные ID |
| `DELETE /api/trees/reference` | Число удалённых коллекций в `removed_collections` |

Один экземпляр HTTP-сервера обслуживает реестр `tree_configs`. Каждая коллекция дерева содержит все исходные ID, а клиент получает видимые узлы и данные их карточек. Смена языка выбирает одну из двух сохранённых раскладок. Правила и порядок критериев находятся в [конфиге расчёта](config/reference_tree.json). [Спецификация и контрольные технологии](Docs/TZ_REFERENCE_TREE_RU.md)

## Проверки

Запустите проверку словаря из корня монорепозитория в окружении парсера, загрузчика и сервера с доступом к сетевому профилю MongoDB. Она сверяет шаблоны RU/EN и игровые ссылки через API и обходит четыре раздела базовых технологий. В отчёте показаны группы требований, пороги и модификаторы веса на примерах из базы. Для неизвестной конструкции сохраняются технология, путь и выражение. [Словарь тултипов](Docs/TZ_TOOLTIP_DICTIONARY_RU.md)

```powershell
python WEB_STTV/tests/tooltip_dictionary_acceptance.py --lookup-url http://192.168.1.36:5173/api/localization/lookup --report TMP/WEB_STTV/tooltip-dictionary/reports/coverage.json
```

Для матрицы деревьев нужен отдельный HTTP-экземпляр с пустым реестром. Положите копию `config/server.json` рядом с оригиналом, назначьте отдельный порт и уникальный `tree_collection_prefix` вида `tree_test_[a-z0-9]+_`, запустите экземпляр с этим конфигом. Из каталога сервера выполните `PYTHONPATH=. python3 -B tests/reference_acceptance.py config/test_server.json /путь/к/прогону/reports/matrix.json`. Проверка сверяет каждый документ с HTTP-ответом, обе раскладки, повторы и перестановки DLC, удаление всех 12 результатов и явную пересборку. Переменная `STTV_TREE_PUBLICATION_TEST=1` включает дополнительный unittest на конкурентные запросы, сбой публикации и смену ревизии.

При запущенном сервере, в каталоге его кода и с тем же окружением для подключения к БД выполните:

```sh
STTV_API_URL=http://127.0.0.1:8788/api/localization/lookup \
  python3 -B -m unittest discover -s tests -v
```

На Ubuntu VM `stellaris-wiki` прошли восемь тестов, включая загрузку правил из вложенного каталога по пути из `server.json`. Через HTTP проверены одиночный и пакетный поиск, RU/EN, отсутствующий ключ, регистр, повторы, раскрытие реальной ссылки и неверные запросы. В том же прогоне на примерах в памяти проверены пустой перевод, цикл, цепочка длиной более 1000 ключей, смешанные конструкции и ответ при недоступности БД. Рабочая копия сервера и логи находятся в подкаталогах `artifacts/server` и `reports` каталога прогона.
