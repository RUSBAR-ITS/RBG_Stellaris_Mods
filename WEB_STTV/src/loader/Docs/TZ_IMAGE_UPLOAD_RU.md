## Команда и конфигурация

**Утверждено.** В `WEB_STTV/src/loader/sttv_loader/` выделен модуль для явного запуска с Windows-машины, на которой установлена игра. Команда читает локальные источники, готовит PNG и передаёт их по SSH на Ubuntu. Она запускается независимо от импорта документов и работает при выключенной MongoDB.

Команда из корня монорепозитория

```powershell
sttv-loader upload-images --config WEB_STTV/config/loader_images.json
```

В отдельном конфиге изображений задать корень игры, каталог подготовленных JSON-дескрипторов DLC, правила отбора из таблицы ниже, рабочий каталог прогона, параметры SSH и корень назначения. Относительные локальные пути настроек отсчитываются от файла конфига. Для стенда использовать существующее SSH-подключение к `stellaris-wiki` (`192.168.1.36`) под `ansible`, с проверкой ключа хоста. Конфиг ссылается на учётные данные. Секреты в конфиг и отчёт не записываются.

## Отбор изображений

| Группа | Источник и правило | Файлов в проверенной установке |
| --- | --- | ---: |
| Технологии и варианты | `gfx/interface/icons/technologies/*.dds`, только непосредственно в этом каталоге | 864 |
| Научные категории | `gfx/interface/icons/technologies/categories/category_*.dds`, только непосредственно в этом подкаталоге | 13 |
| Стоимость исследований | В `gfx/interface/icons/resources/` взять три файла: `physics_research.dds`, `society_research.dds`, `engineering_research.dds` | 3 |
| Миниатюры DLC | Для каждого подготовленного JSON-дескриптора из `scripts/dlc/` прочитать скаляр `thumbnail`. Взять каталог игрового дескриптора из `source.file` и относительно него открыть изображение в установленной игре | 32 |
| Встроенные иконки текста | Шесть значков ресурсов и значок планетарного препятствия из списка `text_icons.files` | 7 |

Для технологий отбирается весь указанный каталог верхнего уровня. Основные технологии и их варианты в проверенной версии ссылаются на 802 разных файла. Выбор конкретной иконки по `icon`, ID или `inherit_icon` выполняется при работе с технологией. Подкаталоги `old_tech_icons` и `tech_templates` в отбор не входят.

Каждый DLC со своим `thumbnail.png` сохраняет собственный путь. Запись каталога DLC без дескриптора или дескриптор без `thumbnail` не создаёт изображения. Если поле есть, но указанный файл отсутствует, это ошибка подготовки с указанием дескриптора и пути. Текущий итог — **919 различных путей назначения**. Числа в таблице служат ориентиром для этой установки и могут изменяться между версиями игры.

## Формат и размещение

Постоянный корень назначения на сервере — `/home/ansible/web-sttv/assets/`. Он задаётся в конфиге отдельно от каталога кода и временных каталогов тестов. Имя и вложенность файла относительно корня игры сохраняются. У DDS расширение заменяется на `.png`, конвертация на рабочей станции сохраняет размеры и прозрачность. Исходный PNG копируется побайтно. Примеры путей под корнем назначения:

```text
gfx/interface/icons/technologies/tech_titans.png
gfx/interface/icons/technologies/categories/category_computing.png
gfx/interface/icons/resources/physics_research.png
dlc/dlc040_nomads/thumbnail.png
```

В проверенной установке файл `dlc/dlc027_overlord/thumbnail.png` содержит JPEG размером 280 × 160. При подготовке объявленной миниатюры загрузчик распознаёт формат по содержимому и преобразует такой JPEG в PNG того же размера под тем же именем. Остальные 31 миниатюру в формате PNG он копирует побайтно.

Загрузчик проверяет, что источники находятся в разрешённых каталогах, миниатюра лежит внутри каталога своего DLC, а итоговый файл — внутри настроенного корня назначения. Разные источники, претендующие на один итоговый путь, дают ошибку до передачи. Владелец, группа и режимы доступа на Ubuntu относятся к отдельной задаче. Для запуска загрузчику предоставляется каталог, уже доступный SSH-пользователю на запись.

## Повторная загрузка и сбои

- Для каждого итогового пути сверять SHA-256 подготовленного PNG с удалённым файлом. Передавать новые и изменившиеся файлы. При одинаковом содержимом пропускать запись.
- Новый файл или замену передавать во временное имя рядом с целевым файлом. После проверки содержимого публиковать переименованием. Если связь оборвалась между файлами, следующий запуск сверяет уже опубликованное и завершает загрузку. Область замены — один файл.
- Файлы, которые уже лежат на сервере и отсутствуют в текущем отборе, оставлять на месте. Очистка постоянного хранилища — отдельная операция.
- Подготовленные файлы текущего прогона размещать в `TMP/WEB_STTV/<прогон>/artifacts/`, итоговый отчёт — в `reports/` того же прогона. В отчёте указать корень назначения, количество выбранных, отправленных и пропущенных файлов по группам, ошибки с относительными путями и время работы. Ошибка чтения, конвертации или передачи даёт ненулевой код завершения.

## Приёмка

1. На небольших входах проверить отбор без рекурсии в каталоге технологий, разрешение относительного пути миниатюры, сохранение размера и альфа-канала DDS после конвертации и точное совпадение байтов исходного и целевого PNG.
2. На двух DLC проверить сохранение двух файлов с одинаковым именем `thumbnail.png` в разных каталогах. Отдельно проверить отсутствие поля, отсутствующий указанный файл, выход за каталог и конфликт итоговых путей.
3. Запустить загрузку с рабочей станции на Ubuntu VM в отдельный доступный для записи корень. Сверить набор относительных путей и SHA-256 на сервере с локально подготовленными файлами. Для исследованной установки ожидается распределение 864 / 13 / 3 / 32.
4. Повторить загрузку с теми же входами. Ожидается ноль переданных файлов. На тестовой копии изменить один источник и проверить замену одного файла. Смоделировать обрыв передачи, проверить целостность предыдущей версии целевого файла и успешное завершение после повтора.
