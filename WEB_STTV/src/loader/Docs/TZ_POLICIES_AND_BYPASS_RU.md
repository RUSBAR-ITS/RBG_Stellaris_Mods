## Источники и результат

Добавить в [эталонный профиль парсера](../../../config/parser_sources.json) все игровые TXT в двух каталогах и их подкаталогах. Применять действующие правила исключения документации, раскрытия вставок и хранения истории. Каждый исходный файл даёт один JSON с соответствующим относительным путём в каталоге артефактов.

| Источник Stellaris | Путь относительно `input_root` загрузчика | Коллекция MongoDB |
|---|---|---|
| `common/policies/**/*.txt` | `scripts/common/policies` | `wiki.policies` |
| `common/bypass/**/*.txt` | `scripts/common/bypass` | `wiki.bypass` |

Политика и тип перехода — именованные корневые блоки. В [профиле загрузчика](../../../config/loader.json) использовать `identity = key`. Один блок становится одним документом с игровым ID в `_id`. Сохранять все разделы и порядок повторяющихся записей. В частности, каждая `option` политики сохраняет свои `name` и `policy_flags`, а переход сохраняет исходный ключ локализации в `name`. Граница проекта — подготовка и публикация данных. [Проект содержимого тултипа](../../../Docs/frontend/TZ_TECHNOLOGY_TOOLTIP_CONTENT_RU.md)

## Публикация

Использовать штатное разделение на предметный документ, привязки в `policies_provenance` или `bypass_provenance` и историю исходного файла в `script_history`. На действующем стенде опубликовать дополнение с сохранением остальных коллекций и историй файлов. При штатной полной подготовке оба источника входят в общий набор.

## Приёмка

1. Сверить состав JSON с TXT в исходных каталогах и множество игровых ID с опубликованными документами. В установленном снимке ожидаются восемь файлов политик и один файл переходов. Количества служат проверкой снимка.
2. Сверить восстановленные деревья с подготовленными JSON штатной проверкой загрузчика, включая привязки и историю девяти файлов.
3. Проверить на опубликованных данных, какая политика и какой вариант устанавливают флаги `robots_outlawed`, `ai_outlawed` и `slavery_allowed`. Для `robot_pop_policy` проверить путь от `robots_outlawed` к варианту `robot_pops_outlawed`. [Игровое определение](E:/SteamLibrary/steamapps/common/Stellaris/common/policies/00_policies.txt:4159)
4. Проверить `gateway`, `wormhole`, `lgate` и `relay_bypass`. По значению `name` прочитать RU/EN через действующий поиск локализации. Для `relay_bypass` ожидаются «Гиперретранслятор» и «Hyper Relay». Импорт охватывает также остальные типы переходов. [Игровое определение](E:/SteamLibrary/steamapps/common/Stellaris/common/bypass/00_bypasses.txt:160)
