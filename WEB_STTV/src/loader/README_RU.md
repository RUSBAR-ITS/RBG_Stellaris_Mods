## Запуск

Из корня монорепозитория установите загрузчик и библиотеку чтения пакета в выбранное Python-окружение. Требуется Python 3.10 или новее.

```powershell
python -m pip install ./Instruments/Document_Package ./WEB_STTV/src/loader
sttv-loader create --config WEB_STTV/config/loader.json --profile network
sttv-loader load --config WEB_STTV/config/loader.json --profile network
sttv-loader verify --config WEB_STTV/config/loader.json --profile network
```

`create` создаёт недостающие коллекции и сохраняет их содержимое. `load` открывает готовые JSON и заменяет настроенные коллекции после сверки. Для полной смены версии игры отдельная команда `sttv-loader drop --config WEB_STTV/config/loader.json --profile network` удаляет всю БД выбранного профиля.

Профиль `network` использует Vault и сертификат из хранилища Windows для получения пароля MongoDB и доверенного CA. Профиль `local` берёт пароль из указанной переменной окружения, а CA из файла. Оба профиля используют TLS и SCRAM-SHA-256. [Конфигурация](../../config/loader.json)

## Источники и документы

`input_root` и `scratch_directory` отсчитываются от каталога конфига. Каждый элемент `sources` задаёт входной путь относительно `input_root` и имя коллекции. Для скриптов читает JSON рекурсивно. Если есть отдельное правило для подкаталога или файла, применяется самое конкретное правило.

| Значение `identity` | Документ и ключ |
| --- | --- |
| `key` | Определение с игровым ключом в имени блока |
| `field` | Определение с ключом в поле тела, например `id` события |
| `anonymous`, `fragments` | Определение с ключом `{root, file, item}`. Позиция считается с нуля до фильтрации |
| `file` | Все записи одного дескриптора DLC с ключом `{root, file}` |
| `package` | Запись пакета локализации с исходным составным ключом |

`root_types` ограничивает импортируемые имена блоков. `containers` задаёт путь через блоки-обёртки. В предметной коллекции доступны для запросов поля `source`, `pointer` и дерево `tree`. Привязки к исходнику хранятся в коллекции `provenance` под тем же ключом. История раскрытий хранится один раз на файл в `history_collection`, в том числе для файлов без импортируемых объектов.

## Публикация и восстановление

Загрузчик пишет во временные коллекции, проверяет размер готового BSON, читает данные обратно и сверяет восстановленные деревья. Лимит каждого документа составляет 16 МиБ. Затем коллекции последовательно переименовываются. В ходе переименований сторонний читатель может увидеть коллекции разных версий.

При сбое журнал `sttv__publication` позволяет восстановить прежний набор или завершить очистку уже опубликованного набора. После аварийного завершения повторите команду `load` из той же рабочей среды с тем же `scratch_directory`. Отдельная команда `verify` сверяет опубликованные данные в режиме чтения.

## Проверки

Команда `python -m unittest discover -s WEB_STTV/src/loader/tests -v` запускает проверки из корня репозитория. Для интеграционного теста задайте `STTV_LOADER_TEST_CONFIG` с профилем отдельной пустой БД, имя которой начинается с `sttv_loader_test_`. Тест пересоздаёт эту БД и в конце удаляет её.

На локальном MongoDB 8.0.12 прошли пять тестов, включая сбой записи привязок, прерывание публикации и восстановление. Через установленный CLI загружены и сверены 2 технологии, 15 событий, 19 переходов терраформирования, 36 записей DLC, 1 дескриптор и 1 000 строк локализации. Для пяти отдельных крупных событий выполнена запись в MongoDB и сверка восстановленного дерева. Наибольший из пяти документов привязок занял 14 729 102 байта у `nomads.4100`.
