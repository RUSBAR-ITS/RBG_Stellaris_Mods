## Результат

Реализовано утверждённое [ТЗ этапа 18](TZ_BACKEND_STAGE_18_RU.md). Подготовка читает технологические документы готового набора, преобразует игровые DDS в PNG и добавляет RU/EN-названия категорий. Остальные 14 видов документов для этой операции не загружаются. Исходники игры доступны только для чтения.

Текущий набор **`data/stage17/database_set` уже подготовлен** для [фронтенда 0.0.8](frontend/FRONTEND_STAGE_8_RU.md). Браузер открывает этот каталог без доступа к игре. Пересборка исходного AST и пересчёт дерева не требуются.

## Запуск

Из `WEB_STTV`, с установленными `src/backend/requirements.txt`:

```powershell
$env:PYTHONPATH="$PWD/src/backend"
python -B -m sttv.enrichment.assets --storage data/stage17/storage.json
```

На текущем компьютере вместо `python` можно использовать `data/.venv/Scripts/python.exe`. Зависимость Pillow 12.2.0 закреплена в requirements; [документация чтения DDS](https://pillow.readthedocs.io/en/stable/handbook/image-file-formats.html#dds).

Без `--storage` адрес набора берётся из `config/enrichment/assets.json`, по умолчанию через `config/storage.json` в `data/database_set`. Дополнительные аргументы: `--variables` и `--config`. Полный отчёт по умолчанию: `data/reports/assets.json`.

Для явной новой сборки вместе с изображениями:

```powershell
python -B -m sttv.database_sets --rebuild-libraries --prepare-assets
```

При наличии актуальной библиотеки можно заменить `--rebuild-libraries` на `--reuse-libraries`. Сборка публикует исходный локализованный набор, затем вызывает ту же операцию ресурсов. Если второй шаг не выполнен, отчёт отмечает ошибку; исходный набор остаётся опубликованным, подготовку ресурсов можно повторить отдельно. Ошибка публикации самой операции ресурсов сохраняет предыдущий снимок.

Python API: `prepare_assets(variables_path=None, config_path=None, *, storage_path=None)` из `sttv.enrichment.assets`. Он возвращает отчёт без консольного диалога. Открытие приложения никогда не вызывает подготовку.

## Конфигурация и хранение

`config/enrichment/assets.json` задаёт источники, поля выбора иконок, правила наследования, PNG-параметры, каталог ресурсов, переиспользование, локализацию и отчёт. Приоритеты перевода берутся из существующего конфига локализации.

| Данные | Адрес и содержание |
| --- | --- |
| Изображение | `assets/<SHA-256>.png`, исходные размеры и прозрачность |
| Ссылка технологии/варианта | `enrichments.presentation = { format_version: 1, icon_asset_id: ID или null }` |
| Общий реестр | `manifest.presentation.files`: относительный путь, хеш, MIME, байты, ширина, высота |
| Источники | `manifest.presentation.sources`: относительный игровой путь, хеш источника, ID результата |
| Значки стоимости | `manifest.presentation.research_icons`: физика, социология, инженерия |
| Категории | `manifest.presentation.categories`: ID → RU/EN, исходная/раскрытая строка и происхождение |

Основная иконка выбирается по `icon` либо ID. `inherit_icon = yes` использует основную; иначе вариант получает собственное изображение по `icon` либо `name`. Поведение отсутствующего `inherit_icon` вынесено в конфиг. Одинаковые PNG объединяются независимо от имени исходного файла.

Повторная подготовка сверяет исходные байты, настройки и версию декодера, затем размер и хеш готового файла. Изменение источника или параметров обновляет затронутый ресурс. Значение `reuse: false` отключает переиспользование преобразования. Неизменившиеся документы не записываются заново.

Ревизия представления участвует в снимке набора. Новое обогащение исключено из смыслового хеша входов дерева; прежние правила остальных обогащений сохранены. Формат манифеста остаётся версии 1 с дополнительным блоком. Общее число генерируемых схем — 34.

## Модули и диагностика

`enrichment/assets/` разделён на настройки, выбор представлений, преобразование/кэш, категории и публикацию. Используются существующие читатель набора, механизм локализации и атомарная смена манифеста. Схемы объявлены в `schema_generation/assets.py`; аудит ресурсов — в `storage/assets.py`.

Отчёт содержит счётчики, прочитанные источники, покрытие документов и время этапов. `references` считает обращения к преобразователю, `reused` — уникальные исходные пути, `unique_images` — уникальное подготовленное содержимое. Поэтому эти числа различаются. Наследующие варианты ссылаются на уже выбранную основную иконку.

Отсутствующее/недекодируемое изображение даёт предупреждение и `null`. Ошибки путей, хешей неизменяемых файлов или публикации завершают операцию ошибкой. Фронтенд показывает заглушку и сохраняет диагностику. Полный аудит теперь проверяет также ссылки представлений и все объявленные PNG:

```powershell
python -B -m sttv.storage audit --manifest data/stage17/database_set/manifest.json --report data/stage18/full_audit.json
```

Команда выше читает весь набор; она приведена для отдельного аудита, а не выполняется при открытии интерфейса.

## Проверки

Результаты текущей реализации:

| Проверка | Результат |
| --- | --- |
| Технологии / варианты | 679 / 206; проверены все 885 ссылок |
| Подготовленные изображения | 791 PNG, 5 032 468 байт (4,80 МиБ) |
| Категории | 13, все с RU/EN-названиями |
| Отсутствующие источники | 0 |
| Повторная подготовка | 12,69 с; 805 исходных изображений переиспользованы; 0 преобразований, записей документов и байтов изображений |
| Сохранность | Все 35 документов совпадают с прежними версиями после удаления только нового `presentation`; локализация и деревья сохранены |
| Выборочное чтение | 35 из 450 документов; остальные виды не читались |

Замер повторной подготовки включает сверку входов и загрузку локализации на текущем компьютере, при уже подготовленных ресурсах; это не время первой конвертации. Результаты: `data/reports/assets.json`, `data/stage18/acceptance.json`.

Пройдены 12 проверок ресурсов/хранения, 8 проверок сборки набора и 3 проверки генерации схем. Проверены размеры и alpha, дедупликация, наследование, приоритеты RU/EN, изменение исходника/настроек, повреждение PNG и прерывание смены манифеста. Выполнен аудит всех 791 изображения и 35 технологических документов; повторный полный аудит остальных 415 документов в этой итерации не запускался.

## Ограничения

Ресурсы относятся только к технологиям, вариантам и трём значкам исследований. Преобразование не увеличивает исходное разрешение: крупный показ небольших игровых иконок может выглядеть пиксельным. Проверка в Stellaris не требуется; визуальная оценка карточек выполняется в браузере.
