## Result

**Historical guide.** Describes the implementation before the syntax-tree database transition. Current operation and format: [stage six](BACKEND_STAGE_6_EN.md).

The approved [stage-five specification](TZ_BACKEND_STAGE_5_EN.md) is implemented. Both `inline_script` forms expand at the call site, including nested invocations and code passed as string arguments. Bindings are isolated between calls. Entry order, repeated keys, and empty results are preserved.

Call history is separate from the working tree. The builder and analyzer consume expanded nodes; statistics do not count metadata arguments or paths again. Game sources are read without modification.

## Configuration

`INLINE_SCRIPTS_DIR` in `global_variables.json` selects a directory relative to `STELLARIS_ROOT`; its current value is `common/inline_scripts`. Escaping the game root is rejected.

`config/backend.json` selects `parser.inline_scripts` through the usual `base`/`path` pair. `config/parser/inline_scripts.json` contains:

| Field | Current value | Purpose |
| --- | --- | --- |
| `path_field` | `script` | Path field in a block invocation |
| `parameter_case_sensitive` | `true` | Argument-name matching |
| `extension` | `.txt` | Template filename extension |
| `encoding` | `utf-8-sig` | Template encoding |
| `max_depth` | `64` | Maximum invocation depth |

The construct keyword stays in `constructs.json`; parameter delimiters and string rules remain in the existing syntax configurations. Game commands are not used to locate templates. Four separate closed schemas validate the parser configurations.

## Modules and interface

Under `src/backend/sttv/script/inlining/`:

- `binding.py` reads paths and arguments without interpreting argument names as logical operators.
- `loader.py` resolves safe paths and caches template text and SHA-256 within one operation.
- `substitution.py` replaces parameters before structural parsing; comments do not require bindings.
- `text.py` maps generated text to physical source fragments.
- `expansion.py` controls nesting, cycles, binding isolation, and node insertion.

`script/inline.py` exports `Expansion`, `FileTemplates`, `MemoryTemplates`, and `expand_inline_script`. `sources/expansion.py` creates a context from settings and excludes the template directory from independent inputs.

```python
from sttv.script.parser import parse_text
from sttv.sources.expansion import expansion_context

context = expansion_context(settings)
document = parse_text(text, settings.syntax, "example.txt",
                      expansion=context, root="TECH_PATH")
```

One context serves one operation; invocation IDs are unique within it. `role="template"` explicitly inspects a template without expanding it. A normal document containing an invocation without a context raises `inline_context_required` instead of skipping the inclusion.

## History and provenance

`document.metadata.inline_scripts` stores parents before children. Records contain IDs, parents, call sites, forms, raw and effective paths, template files, and `{name, raw, value}` arguments. `insertion = {container, index, count}` describes insertion into the final AST. Empty templates have `count = 0`.

Every node has an `origin`. Substituted text retains physical fragments, placeholder locations, and a separate generated-text span. Expansion and subsequent projection errors retain original locations and call chains. Nested invocations receive only arguments explicitly supplied through their invocation text.

The database uses validated `result_paths` JSON Pointers instead of AST positions. See the complete [database contract](DATABASE_MODEL_EN.md#inclusion-history).

## Database and profile

Database format is now `2`: required `metadata.inline_scripts`, extended `SourceLocation`, and `source` on script entries, repeated values, and local variables. Format 1 is unsupported.

`stellaris_4_5_4.json` has revision `2`. With separate user approval, it adds `is_preferred_weapons`, `is_councilor_type`, `ai_armor_ratio`, `ai_shields_ratio`, `is_ai_ship_role`, and the latter's two-argument context. All remaining effective rules match the original reference fingerprint, verified by a test.

Schemas remain generated by `schema_generation/`; `parser_inline_scripts.schema.json` is new. Failed builds preserve the previous database. Global `@...` variables, scripted triggers/effects, and game conditions are not executed.

## Game-data verification

Technology build: **679 technologies, 206 variants, 301 expanded invocations, 10 templates, no errors**. All RU/EN names are retained. Domain data changed in exactly 261 technologies containing inclusions; the other 418 technologies, categories, tiers, and local variables match the baseline after normalizing provenance. There are 1,272 warnings: 1,265 external variable references and seven repeated fields; their values are not guessed.

Corpus scan: 2,238 physical TXT files; 631 template-directory files excluded from independent inputs. Of the remaining 1,607 inputs, two are documentation, 1,583 parse completely, and 22 have diagnostics. There are 10,487 encountered invocations: 10,450 expanded and 37 failed, including parent calls whose children failed. The run reads 572 templates and reaches depth 3.

Frequency and scalar lists include only completely successful input files. Invocation counters also include attempts from failed files. Lists contain 56,322 frequency entries, 34,749 scalar values, and 3,785 names with scalar right-hand sides. These are corpus observations, not universal language rules. Game files, referenced templates, and existing research lists have identical before/after hashes.

## Limitations

The full corpus status is `partial`; `corpus_report.json` lists every failure and its call chain:

- One previously known construct without an operator: `common/named_colors/01_trait_colors.txt:65`.
- Three tradition files reference missing `traditions/tr_purity_imperfection_remediation_wilderness.txt`.
- Fourteen trait files reach templates without required `CLASS`; the specification prohibits implicit inheritance of parent bindings.
- Two event files reach `grand_archive/collection/stage_3_reward_option.txt` without `RELIC`.
- Two scripted-effect files pass unbound `TARGET` and `IGNORE_COUNTRY_GFX`; executing external scripted effects is outside this stage.

These diagnostics describe current processor limits and specific sources; they do not establish game-engine behavior. Conditional fragments and default parameters are reported as unsupported during expansion. Game files were not repaired; broader rules require a separate decision.
