## Формат и конфигурация

Реализованы [ТЗ этапа 17](TZ_BACKEND_STAGE_17_RU.md) и [открытие каталога во фронтенде](frontend/FRONTEND_STAGE_4_RU.md). Один исходный файл сохраняется в одном JSON `sttv.parse_document`, версия 1. `manifest.json` формата `sttv.database_manifest`, версия 1, содержит все 15 видов, описатели файлов, индекс объектов и общую метадату комбинаций дерева. Слияния в монолитные БД больше нет.

Адреса набора, манифеста, документов, временных операций и отчёта аудита задаёт `config/storage.json`; его ссылка используется сборщиком и обогащениями. Число процессов берётся из `config/parallel.json`. Корень по умолчанию — `WORK_DIR/database_set`. Фактические документы и объекты в манифест записывает сборщик.

Файл версии: `documents/<database>/<document_id>/<file_hash>.json`. SHA-256 записанных байтов определяет `file_hash`; `source_hash` исключает только корневое обогащение `technology_tree`. `set_id` зависит от исходных ревизий всех видов и реестра, `snapshot_revision` — от текущего содержимого манифеста. Ссылки на узлы: `{database, document_id, pointer}`, где указатель начинается с `/items/`. У `on_actions` сохраняются все фрагменты одного ID, у `terraform` — анонимные объекты с `id: null`.

Генератор схем создаёт 32 схемы, включая `storage`, `database_manifest`, `database_document`, `storage_report`. `database.schema.json` описывает отдельный документ. Конфигурации, локализация и история разбора используют общий контракт AST.

## Запуск

Из `WEB_STTV`, с установленными зависимостями Python:

```powershell
$env:PYTHONPATH="src/backend"
python -B -m sttv.database_sets --reuse-libraries
python -B -m sttv.enrichment.technology_tree
python -B -m sttv.enrichment.technology_tree --recalculate
python -B -m sttv.storage audit --manifest data/database_set/manifest.json --report data/reports/storage_audit.json
```

`--reuse-libraries` требует актуальных библиотек. Для их явной подготовки использовать `--rebuild-libraries`. Обогащение дерева читает готовый набор без доступа к игре. CLI `src/backend/main.py` сохраняет назначение отдельного сборщика технологий, но публикует новый манифест с пустыми остальными видами; для полного набора использовать `sttv.database_sets`.

Проверочный полный набор этой итерации: `data/stage17/database_set`. Его отдельные настройки — `data/stage17/backend.json`, `storage.json`, `tree.json`. Для расчёта по нему передать `--config data/stage17/tree.json`; для аудита — путь его манифеста. Старые эталонные файлы `data/databases` не изменены.

Отдельное обновление локализации работает через ту же транзакцию манифеста; Python-функция `enrich_localization(..., kind='technologies')` выбирает вид. Источники и их приоритеты остаются в конфигурации локализации. Изменение локализации меняет исходную ревизию и делает прежний расчёт дерева устаревшим до следующего вызова.

## Чтение и публикация

`sttv.storage.open_set(manifest_path)` фиксирует снимок. Доступны `iter_objects`, `resolve_object`, `read_document`, `iter_documents` и потоковые проекции. Поиск по ID использует манифест; проверка всех объявленных путей не читает их содержимое. Прочитанный файл одновременно разбирается и хешируется. `coverage()` различает проверенные и непрочитанные документы.

Расчёт дерева извлекает компактные свидетельства в ограниченном пуле процессов, события выбирает через индекс по запрошенным ID. Общий выбор родителей выполняется после объединения свидетельств. Переиспользование проверяет технологические документы и ревизии манифеста без повторного построения функциональных индексов.

Запись блокирует корень набора, готовит неизменяемые версии и атомарно заменяет только манифест. Ошибка до переключения сохраняет прежний набор. Уже открытый читатель продолжает использовать старые версии; последующее изменение снимка обнаруживается при проверке перед публикацией. Ошибка отчёта после переключения не скрывает факт публикации.

## Проверки и замеры

Рабочие результаты находятся в `data/stage17/`:

| Проверка | Результат |
| --- | --- |
| Полная сборка, 10 процессов, готовые библиотеки | 450 документов, 15 видов, 387,885 с |
| Сравнение с прежними БД | Все 450 документов совпали после нормализации конверта и ссылок; AST, история, локализация сохранены |
| Родители базовой комбинации | Все 679 решений совпали; 178 корней, 501 родитель, 0 неоднозначностей |
| Варианты | 206 отдельных вариантов и 3 сочетания; сохранение и повторное использование двух комбинаций |
| Первый расчёт с публикацией | 41,126 с |
| Последующий принудительный расчёт без изменений результата | 22,384 с; индексы 19,046 с; критерии 0,0025 с |
| Переиспользование комбинации | 3,697 с, 35 проверенных документов, 415 непрочитанных |
| Полный аудит | 450/450, 125,764 с, ошибок нет |

Принудительный расчёт прочитал 2 840 258 013 байт, в том числе 639 267 104 байта событий; аудит — 11 049 350 511 байт. Хеширование использует тот же проход. Это отдельные замеры на текущем компьютере, без очистки файлового кэша ОС; повторный расчёт и первый расчёт с записью имеют разный объём работы.

Полный прогон бэкенда: **269 тестов, все прошли**. Синтетические проверки покрывают детерминизм одного и десяти процессов, повреждение используемого/неиспользуемого документа, индекс и пути, взаимность связей, смену вариантов, блокировку, сбой переключения, старого читателя и ошибку отчёта. Отчёты приёмки: `source_comparison.json`, `acceptance/acceptance.json`, `storage_audit.json`; результаты тестов сохранены рядом.

Дополнительный принудительный расчёт с мониторингом памяти занял 33,244 с: максимум рабочего набора координатора — 530 329 600 байт, суммы процессов — 1 191 682 048 байт. Измерение выполнялось раз в секунду, ошибок сбора нет; это наблюдаемые максимумы, а не гарантированный предел памяти. В этом прогоне результат не изменился, записи документов не потребовалось; отчёт — `technology_tree_report.json`.

## Границы

Старые монолитные наборы не читаются продуктом. Инкрементальный повторный разбор игровых исходников, MongoDB, новая сетка и HTTP API не добавлялись. Старые версии и файлы, оставшиеся до неудавшегося переключения, автоматически не удаляются. Непрочитанные документы не объявляются проверенными: для полного охвата предназначен аудит.
