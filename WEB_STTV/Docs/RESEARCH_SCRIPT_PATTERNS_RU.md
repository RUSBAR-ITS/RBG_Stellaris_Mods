## Границы и метод

Дата: 2026-11-15. Установленная версия: **Cygnus v4.5.4 (1b4f)**, прочитана из `launcher-settings.json`.

Исследованы рекурсивно все файлы `common/` и `events/` в `E:/SteamLibrary/steamapps/common/Stellaris/`. Входные данные — только установленная ванильная игра. Моды, интернет, внешние реестры команд и журналы документации движка не использовались.

Цель — выделить наблюдаемые общие формы языка для обсуждения будущего парсера. Это исследование, а не ТЗ и не изменение реализации продукта. Измерительные скрипты находятся в `TMP/WEB_STTV/script_patterns/`; рабочий парсер, схемы, профиль и БД не изменены.

Метод: полный файловый манифест с SHA-256; чтение всех `.txt`; первичная проверка текущим парсером; независимый структурный проход без словаря команд; разбор необычных случаев по исходникам; обратное восстановление последовательности значимых токенов. Комментарии учитывались отдельно от исполняемого текста. Документация внутри игры использовалась как пояснение, с проверкой наличия соответствующих конструкций в коде.

## Лексические правила

1. Пробелы, табуляция и переводы строк разделяют элементы. Вложенность задают фигурные скобки; отступы не являются её описанием. Несколько записей могут находиться на одной строке.
2. `#` открывает комментарий вне строки. Закомментированные примеры не считаются употреблениями команд.
3. Двойные кавычки выделяют строковый токен. В корпусе 89 906 таких токенов: 89 402 значения и 504 ключа. Есть 21 многострочная строка в шести файлах. Скобки внутри строки не меняют внешнюю вложенность.
4. Неквотированный атом нельзя ограничивать шаблоном `A-Z/a-z/0-9/_`: встречаются `.`, `:`, `?`, `@`, `$`, `|`, `/`, дефисы и апострофы. Например, `TOX1_FLEET_Avogadro's_Moles` — `common/name_lists/TOX1.txt:55`.
5. Число, `yes/no`, идентификатор и ссылка — разные интерпретации скалярного токена. Исходное написание и наличие кавычек нужно сохранять; предметный тип устанавливать с учётом поля. Наблюдаются целые, отрицательные и десятичные числа; экспоненциальная запись среди неквотированных числовых токенов не обнаружена.

| Оператор вне строк, комментариев и формул | Число употреблений |
|---|---:|
| `=` | 1 102 564 |
| `>` | 3 674 |
| `>=` | 3 105 |
| `<` | 2 178 |
| `<=` | 544 |
| `!=` | 38 |

Отдельный оператор `?=` в исследованном корпусе не обнаружен. Наблюдается **`owner? = { ... }`**, где `?` примыкает к имени перехода, а `=` записан отдельно. Ключей с `?` — 3 018 употреблений в 336 файлах. Это различие следует сохранить при разборе, не нормализуя его без проверки в другой оператор.

## Структурные формы

Подсчёты относятся к исходному тексту до раскрытия вставок. Вложенные элементы считаются отдельно. Примеры в таблице сокращены до формы.

| Форма | Пример | Употреблений | Файлов |
|---|---|---:|---:|
| Ключ, оператор, скаляр | `weight = 10`, `count >= 2` | 660 435 | 2 113 |
| Ключ, оператор, блок | `potential = { ... }` | 451 481 | 2 096 |
| Самостоятельный скаляр | `energy`, `optimize_memory`, `$TRIGGER$` | 62 787 | 761 |
| Анонимный блок | `{ key = specialist_type value = specialist_none }` | 832 | 26 |
| Значение с меткой и блоком | `value = rgb { 235 0 18 0 }` | 187 | 13 |
| Метка с блоком без оператора | `rgb { 142 188 241 }` | 90 | 2 |
| Условный параметризованный фрагмент | `[[PARAM] ... ]`, `[[!PARAM] ... ]` | 53 | 13 |

В строке «метка с блоком без оператора» 89 случаев — `rgb` в `common/colors/00_colors.txt`, один — спорная запись `trait_bg_active_glow { ... }`; см. ограничения. Формы цветов `rgb` и `hsv` наблюдаются как отдельные маркированные значения, а не как наборы обычных команд.

Вложенный блок может содержать именованные записи, скаляры, другие анонимные блоки либо их сочетания. Обнаружены 116 контейнеров, в которых самостоятельные скаляры смешаны с другими формами. Примеры:

- `common/inline_scripts/buildings/nomadic_cost_switcher_with_additional_trigger.txt:3` — обычная проверка и отдельный `$TRIGGER$` внутри одного блока;
- `common/scripted_effects/00_scripted_effects.txt:73` — маркер `optimize_memory` рядом с эффектами;
- `common/technology/00_biogenesis_tech.txt:795` — обычная технология и логическая группа внутри `prerequisites`.

Есть 3 946 пустых блоков. Максимальная наблюдаемая вложенность — 16 при глубине документа 0; сюда включены фигурные блоки и условные параметризованные фрагменты.

**Контейнер должен сохранять последовательность элементов и повторения ключей.** Найдены 35 048 пар «контейнер — повторяющийся ключ», а не столько уникальных контейнеров. Повторения встречаются в `modifier`, `option`, эффектах и событиях; обычный словарь с заменой предыдущего значения теряет информацию. Числовые ключи также нормальны: 7 140 употреблений, например ветви случайного выбора.

На верхнем уровне встречаются все следующие организации: именованные объекты, повторяющиеся оболочки событий с полем `id`, присваивания переменных, списки голых имён, анонимные корневые блоки. Поэтому нельзя требовать от каждого `.txt` единственный объект или одинаковую схему документа.

## Контекст и предметный смысл

Одна структурная форма `name = { ... }` используется для объявления объекта, условия, эффекта, перехода области, таблицы модификаторов и параметров вызова. Формы `OR`, `AND`, `NOT`, `if`, `limit`, `random_list`, `modifier` не требуют отдельных разновидностей скобок, но имеют разный смысл.

Из этого следуют три разных задачи:

1. Прочитать синтаксис, сохранив форму, порядок, повторения, кавычки и координаты.
2. Связать определения, ссылки, вставки и параметры по исходникам.
3. Интерпретировать только необходимые продукту поля и конструкции по явно объявленным правилам.

Компактная грамматика решает первую задачу. Она не доказывает допустимость произвольной команды в произвольной области и не устанавливает все правила встроенных функций движка. Названия пользовательских scripted triggers/effects можно извлечь из файлов; полный контракт встроенной команды может отсутствовать в исходниках.

По именованным определениям и путям файлов получен следующий отдельный инвентарный каталог, без включения этих имён в грамматику:

| Источник | Извлечено |
|---|---:|
| `common/scripted_triggers/` | 1 693 именованных определения, ещё 12 объявлений `@` |
| `common/scripted_effects/` | 1 691 именованное определение, ещё 24 объявления `@` |
| `common/script_values/` | 674 именованных определения, ещё одно объявление `@` |
| `common/scripted_variables/` | 2 917 объявлений `@` |

Это количество исходных определений, а не доказательство их использования или доступности в каждом контексте. Параметры inline-фрагментов собраны как наблюдаемые имена подстановок; обязательность, тип и область применимости из этого автоматически не следуют.

Основа дальнейшего проектирования: отдельно зафиксировать небольшой набор синтаксических форм, отдельно получать каталоги определений из игры, отдельно определить необходимую интерпретацию для технологического справочника. Перечень десятков тысяч встретившихся ключей не нужен как ручной словарь синтаксического парсера. Это вывод исследования, изменение действующего ТЗ пока не выполнено.

## Ограничения и замечания

- `common/named_colors/01_trait_colors.txt:65` содержит `trait_bg_active_glow { ... }`, хотя соседние определения используют `=`. Структурно запись сохранена как метка с блоком. По файлам нельзя установить, является ли это разрешённой формой, терпимостью движка или опечаткой; универсальное правило о необязательности `=` из неё не выводится.
- Ванильный файл не гарантирует отсутствие ошибок или устаревших примеров. Наличие паттерна, пояснение в комментарии и подтверждение движком — разные виды свидетельств.
- Не подтверждена полнота грамматики для будущих версий игры или всех форм, допустимых движком, но не встреченных здесь. Не выполнялись раскрытие всех вставок, вычисление скриптов и моделирование состояния государства.
- Текущий парсер продукта сообщил ошибки для 49 `.txt`, включая документ о кораблях. Кроме явных отказов, он может принять формулу или положительный условный фрагмент как последовательность обычных атомов, потеряв их смысловую границу. Его успешный возврат не равен правильному распознаванию всех форм. Исправления не вносились.
