## Статус

Правила утверждены пользователем вместе с этапом 12 от 2026-11-18 и реализованы. Конфигурация [source_exceptions.json](../config/parser/source_exceptions.json) подключена через `parser.source_exceptions`; каждый случай записывается в отчёт. Реализованы регистронезависимые имена параметров, структурное раскрытие `effect = no` и разрешение смешанного контекста при одном общем объявлении переменной.

Поведение игрового движка для `effect = no` не вычисляется и не подтверждается этим преобразованием. Исходные причины описаны в [исследовании](RESEARCH_STAGE_12_BLOCKERS_RU.md); все семь файлов прошли полный прогон, результаты приведены в [руководстве этапа 12](BACKEND_STAGE_12_RU.md#проверки).

## Условные исключения

Три записи обслуживают четыре корневых документа. Все пути относительны к `STELLARIS_ROOT`.

| Правило | Условия | Преобразование в памяти |
| --- | --- | --- |
| `sttv_event_job_amenities_separator` | Корневой документ и непосредственный источник — `common/pop_jobs/06_event_jobs.txt`; скалярная ссылка точно равна `value:scripted_modifier_mult\|MODIFIER\|pop_job_amenities_mult\|\|` | Удалить только последний `\|`, затем разобрать исправленную ссылку штатным обработчиком |
| `sttv_archive_selected_relic` | Корневой документ — `events/grand_archive_events.txt` или `events/leviathans_events_1.txt`; раскрывается `common/inline_scripts/grand_archive/collection/stage_3_reward_option.txt`; достигнута ссылка `gave_relic_$RELIC$`; `RELIC` отсутствует, `SELECTED_RELIC` передан | Для текущего вызова связать `RELIC` с переданным `SELECTED_RELIC`, сохранив происхождение его значения |
| `sttv_nomads_ethic_random` | Корневой документ — `events/nomads_origin_events.txt`; вызван `pop_group_add_ethic_effect` из `common/scripted_effects/00_scripted_effects.txt`; достигнут `$RANDOM$`, аргумент отсутствует; переданы `POP_GROUP`, `ETHOS`, `PERCENTAGE` | Для текущего вызова добавить `RANDOM = 0` как явно согласованное временное значение |

Достижение ссылки означает обращение к ней после выбора условных фрагментов шаблона. Наличие того же текста в комментарии или отброшенном фрагменте не активирует правило. Корневой документ сохраняется на протяжении вложенных раскрытий. `required_parameters` проверяет наличие аргументов, включая явно переданные значения; исходные аргументы не перезаписываются.

Окончание `||` само по себе недостаточно для исправления: оно может представлять пустое значение аргумента в другой корректной записи. Поэтому удаление символа разрешено только для указанной полной ссылки. Повторное применение к уже исправленной ссылке ничего не меняет.

Для `RELIC` не вводится глобальное соответствие имён. Для `RANDOM` не добавляется значение по умолчанию всему эффекту или всей игре. Несколько подходящих вызовов внутри разрешённых корневых документов обрабатываются отдельно.

## Применение и отчёт

`source_exceptions.json` отделён от [exceptions.json](../config/parser/exceptions.json), который уже содержит разрешённое имя файла inline-шаблона без расширения. Новый файл описывает преобразования данных при импорте; его пути служат условиями совпадения с уже читаемыми источниками, а не разрешением открывать произвольные файлы.

Файл подключён через настройку `parser.source_exceptions`; его формат проверяется, а сам файл учитывается среди конфигурационных входов. Применённые преобразования отражаются в содержимом и идентичности набора. Условия одного правила соединяются через «И», элементы `root_files` — через «ИЛИ». Сопоставление имён параметров использует общую настройку регистра; значения аргументов не переводятся в нижний регистр. Полные значения скалярных ссылок сопоставляются точно.

Преобразования выполняются в памяти до операции, которая иначе завершилась бы соответствующей ошибкой. Сохраняются исходный текст, координаты и происхождение; не создавать впечатление, что исправленный фрагмент прочитан из игры. Игровые файлы и общий кеш исходного шаблона не изменяются. Несовпадение условий оставляет штатную обработку; ошибка в другом месте остаётся видимой.

Каждое применение записывается в отчёт: ID правила, корневой документ, источник и координаты, цепочка вызовов, исходное значение или факт отсутствия аргумента, применённое значение и его источник. Для `RANDOM` источником является правило исключения, для `RELIC` — аргумент `SELECTED_RELIC`. Для полного прогона сохранить число применений каждого правила, включая ноль; отсутствие совпадений само по себе не является ошибкой частичной сборки.

Два подходящих правила, изменяющих одно значение, дают диагностируемый конфликт; порядок файла не выбирает победителя. Повторный прогон с теми же входами и конфигом должен давать тот же результат. После обновления игры несовпавшее правило не расширяется автоматически.

## Регистр параметров

Согласовано сопоставлять имена параметров без учёта регистра: `BONUS`, `bonus` и `Bonus` обозначают один переданный аргумент. При реализации установить `parameter_case_sensitive = false` согласованно для inline-вызовов и именованных вызовов; script values используют те же правила связывания.

Это относится к именам передаваемых аргументов, поиску `$PARAM$`, выбору `[[PARAM]` / `[[!PARAM]`, проверке отсутствия перед использованием default и поиску дублей. Переданные значения, буквальный текст default и текст строк сохраняются как есть. Два аргумента `BONUS` и `bonus` в одном вызове считаются повтором, а не поводом молча выбрать последний.

Изменение решает расхождение `BONUS` / `$bonus$` в цепочке от `first_contact_dlc_operations_events.txt`; отдельное исключение этому файлу не требуется. Это согласованный контракт нашего инструмента, а не вывод о регистре всех конструкций игры.

## Скалярный вызов эффекта

Причина запрета точно установлена: [раздел 7 ТЗ этапа 8](TZ_BACKEND_STAGE_8_RU.md#7-раскрытие-эффектов) отдельно ограничил скалярный вызов эффекта значением `yes`. Проверка реализована в `script/scripted/expansion.py`, в `expand_named`. Она сохранилась независимо от удаления реестра допустимых игровых команд: это ограничение преобразования известного вызова, а не проверка неизвестной команды.

Ванильная `common/scripted_effects/99_advanced_documentation.txt:13` описывает обычный вызов через `yes` и передачу аргументов блоком; поведение `effect = no` там не объясняется. Установить по этой документации, выполняется ли такой эффект движком, нельзя.

**Предложение:** для `effect_name = no` раскрывать найденное определение без аргументов для структурного анализа, сохраняя исходное `no` в существующей записи вызова (`invocation.raw`). Не превращать его в отрицание триггера, не удалять тело и не подменять исходную запись на `yes`. Такое раскрытие показывает содержимое определения, но не утверждает, что движок выполнит его при `no`. Остальные формы скалярного вызова этим предложением не переопределяются.

## Составная статическая переменная

Для `shroud_events.txt` отдельное исключение исходных данных не требуется. Триггер содержит `@po_apply_pop_template_tier$TIER$_nb_pop`. После подстановки `TIER = 1` получается `@po_apply_pop_template_tier1_nb_pop`; существующее глобальное объявление равно `1500`. Аналогично значения 2 и 3 дают `3000` и `5000`.

Части имени происходят из шаблона и аргумента вызывающего события. Наш обработчик хранит оба контекста, но сейчас отвергает их до поиска переменной. Исследование подтвердило, что для всех трёх вызовов оба контекста находят одно и то же глобальное объявление, без локального переопределения.

**Предложение:** сначала собрать имя целиком, затем разрешить его в каждом сохранённом контексте по действующим правилам локальных и глобальных переменных. Подставлять значение, когда все контексты приводят к одному и тому же объявлению и одной цепочке разрешения. Проверять происхождение объявлений, а не только равенство чисел: два разных локальных объявления с одинаковым значением не доказывают общий контекст.

Если хотя бы один контекст не разрешается или определения различаются, сохранить диагностируемую ошибку с результатами поиска, без выбора первого контекста. Происхождение частей токена сохраняется. Для данного примера это позволяет импортировать реальные `1500`, `3000`, `5000`, без констант-исключений для Покрова.

## Проверки

Подготовленный файл проверен по текущим исходникам: найдена одна точная ссылка с лишним разделителем; исправленная ссылка принимается действующим обработчиком script values. У вызывающего шаблона обнаружены пять передач `SELECTED_RELIC` без `RELIC`; в файле кочевников — девять подходящих вызовов без `RANDOM`. Проверены JSON, оглавления и ссылки; неизменность 151 существующего файла кода, настроек и БД подтверждена хешами. [Отчёт проверки](../data/stage12/source_exceptions_review.json) описывает проверку условий, а не работу ещё не подключённых исключений.

При реализации проверить срабатывание каждого правила и близкие случаи, где оно не должно работать: другой файл, шаблон или ссылка, переданный `RELIC`/`RANDOM`, комментарий и отброшенная ветвь. Проверить корректное пустое значение в ссылке script value, повторное применение, конфликт правил и полноту отчёта.

Для регистра проверить вложенные вызовы всех трёх видов, условные фрагменты, default, неизменность значений и дубли имён после нормализации. Для смешанной переменной — три реальных значения `TIER`, единственный контекст, общий глобальный источник, разные локальные объявления и неизвестное имя. Для предложенного `effect = no` — раскрытие без отрицания и сохранение исходного вызова.

После реализации повторить семь полных файлов и полный набор этапа 12. Проверки подготовленного JSON и соответствия правил исходникам не заменяют этот прогон.
