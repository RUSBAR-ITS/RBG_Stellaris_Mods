## Назначение и границы

Документ описывает модель игрового объекта «Технология»: состав полей, их назначение, типы, ссылки и вложенные структуры. Основа — установленная **Stellaris Cygnus v4.5.4 (1b4f)**, проверка от **2026-11-15**, 679 базовых определений и 206 блоков вариантов.

Ниже перечислены **все 25 различных полей верхнего уровня, найденных в этих определениях**, и все 9 полей, найденных внутри `technology_swap`. Это описание изученных данных; наблюдаемая кратность и набор значений не объявляются пределами движка для других версий или модов.

Названия типов служат обозначениями в документе, а не именами программных классов. Сериализация текущего этапа описана в [модели JSON-базы](DATABASE_MODEL_RU.md), реализация сборщика — в [руководстве](BACKEND_STAGE_1_RU.md). Вложенные условия и эффекты используют общий скриптовый язык игры; документ описывает их структуру, а не полный словарь всех игровых триггеров и модификаторов.

## Объект и его идентификатор

Источник технологий определяется соединением `STELLARIS_ROOT` и `TECH_PATH` из [global_variables.json](../global_variables.json). Сейчас это `E:/SteamLibrary/steamapps/common/Stellaris/common/technology`.

Определение имеет форму `technology_id = { ... }`. Например, `tech_mega_engineering` — имя внешнего блока и идентификатор объекта. Отдельного поля `id` внутри исходного определения нет. При описании объекта идентификатор следует учитывать отдельно от его содержимого.

Технология имеет:

- идентификатор, по которому на неё ссылаются другие определения;
- содержимое блока: скалярные поля, списки и вложенные блоки;
- происхождение: файл и положение определения в нём;
- связанные данные: локализацию, изображение, категории и определения используемых переменных.

Суффикс ID, локализованное имя и имя файла не задают `tier` или число повторений. Вариант с собственным `name` остаётся частью базовой технологии. Состояние «исследована государством» относится к партии, а не к статическому определению.

## Обозначения типов

| Тип | Содержимое и пример |
| --- | --- |
| `Identifier` | Строковый идентификатор, например `tech_zero_point_power`; при использовании как ссылки проверяется существование цели |
| `String` | Текстовый атом или строка в кавычках; сам по себе не означает локализованный текст |
| `LocalizationKey` | Строковая ссылка на запись локализации, например `TECH_UNLOCK_COLOSSUS_CONSTRUCTION_TITLE` |
| `Boolean` | В игровом синтаксисе `yes` или `no`; это смысловой логический тип, не буквальные JSON `true` / `false` в исходнике |
| `Integer` | Целое число; в некоторых полях встречается запись в кавычках, например `levels = "5"` |
| `Number` | Целое или дробное число, в том числе отрицательное; ограничения зависят от конкретного поля |
| `VariableReference` | Ссылка вида `@tier5cost3`; значение берётся из локального определения или `common/scripted_variables/` |
| `NumberValue` | Число либо ссылка на числовое значение. В прямых числовых полях технологий найдены литералы и `@...`; внутри подключаемых вычислений есть также `value:...`, требующие вычисления в игровом контексте |
| `List<T>` | Упорядоченный список элементов типа `T`, записанный игровым блоком `{ ... }`; допускается пустой блок, если он встречается в источнике |
| `ScriptBlock` | Упорядоченное содержимое скриптового блока с повторяющимися именами, операторами и вложенными блоками |
| `TriggerBlock` | Скриптовое выражение условий, зависящее от области видимости и состояния игры |
| `CalculationBlock` | Скриптовые правила получения или изменения числового значения |
| `ModifierBlock` | Игровые модификаторы и параметры их описания |
| `UnlockDescriptionBlock` | Описания открываемых возможностей и настройки их показа |
| `PrerequisiteExpression` | Логическое выражение ссылок на предшествующие технологии |
| `TechnologySwap` | Условный вариант базовой технологии с полями из отдельной таблицы ниже |

Тип поля, исходная запись и вычисленное значение — разные сведения. Например, `@tier5cost3` разрешается в 24000 в изученной версии, но сохранение только числа потеряет ссылку на источник значения. Статическая `@...` и контекстное `value:...` также не взаимозаменяемы.

## Вложенные структуры

### Требования prerequisites

Внешний блок трактуется как совместное выполнение требований. В изученных источниках его элементы — ID технологий и вложенные группы `OR`. Групп `OR` может быть несколько; внутри каждой находятся альтернативные ID.

Для `tech_mega_engineering` выражение имеет вид:

```text
(tech_starbase_5 OR tech_arkship_tier_3)
AND tech_zero_point_power
AND (tech_battleships OR tech_stingers)
```

Это три совместных требования, а не обязательное исследование всех пяти технологий. Форма с явным логическим `AND` здесь объясняет смысл; в данном исходнике совместность выражена внешним блоком, а не буквальным полем `AND`.

Пустой блок и отсутствие блока не задают предшественников, но их исходная форма различается. `has_technology` внутри веса или условий нельзя автоматически переносить в это выражение. Тип `PrerequisiteExpression` не означает, что внутри `prerequisites` разрешён любой общий игровой триггер.

### Условия TriggerBlock

Используются в `potential`, `starting_potential`, `technology_swap.trigger` и условных частях вычислений. Условие не является заранее известным `Boolean`: результат возникает при проверке государства и состояния партии.

Состав включает проверки вида `has_origin = origin_storm_chasers`, логические блоки `OR`, `NOT`, `NOR`, числовые сравнения, вложенные области видимости и вызовы scripted triggers. Например, `any_neighbor_country = { has_technology = tech_titans }` проверяет соседнее государство, а не владельца текущей технологии.

Имена условий и типы их аргументов определяются игровым скриптовым языком. При сохранении структуры существенны операторы `=`, `<`, `>`, `<=`, `>=`, порядок записей, повторяющиеся имена и вложенность. Значение `no` в вызове триггера также нельзя отбрасывать.

### Вычисления CalculationBlock

Этот смысловой тип используется для стоимости, модификаторов веса и оценки ИИ; набор полей зависит от конкретного места, а не является одинаковым контрактом для всех блоков.

| Элемент | Тип и роль |
| --- | --- |
| `factor` | `NumberValue`: множитель или исходное значение в соответствующем контексте вычисления |
| `base`, `weight` | Числовые параметры исходной оценки; встречаются на верхнем уровне `ai_weight` |
| `modifier` | Повторяемый блок числового изменения и условий его применения; в изученных вычислениях используются `factor` и `add` |
| `inline_script` | Строка с путём вставки либо блок с `script` и именованными параметрами; вставка содержит дополнительные правила |

В десяти блоках `cost` из `00_cosmic_storm_tech.txt` непосредственно записаны `factor = @...` и `inline_script = { script = technologies/cosmic_storms_technologies_cost_modifiers }`. Подключаемый файл содержит условные множители, например 0.75 и 1.2.

Во вставке `technologies/cosmic_storms_technologies_weight_modifiers` встречается `factor = value:storm_callers_councilor_tech_discovery_chance_multiplier`. Такое значение требует вычисления игрового script value; его нельзя разрешить как обычную константу `@...`.

Строка пути inline-вставки и параметры — часть исходной модели. Окончательный числовой результат без раскрытия вставок и контекста не гарантирован. Правила порядка арифметических операций движка данным документом не устанавливаются.

### Эффекты ModifierBlock

Основные элементы — пары «идентификатор модификатора = числовое значение», например `ship_armor_mult = 0.05` или `envoys_add = @...`. Конкретные имена принадлежат каталогу игровых модификаторов; их перечень не фиксируется как набор полей каждой технологии.

Кроме них найдены параметры описания:

| Поле | Тип | Назначение |
| --- | --- | --- |
| `description` | `LocalizationKey` | Ссылка на описание блока |
| `description_parameters` | Блок именованных значений | Аргументы описания; пример `POINTS = @tech_gene_tailoring_POINTS` |
| `custom_tooltip` | `LocalizationKey` | Ссылка на пользовательское описание эффекта |
| `show_only_custom_tooltip` | `Boolean` | Управление показом пользовательского описания вместо автоматически составленного списка |

Числа имеют разные единицы: прибавка количества, относительный коэффициент и другие величины определяются модификатором. Нельзя превращать каждое `0.05` в проценты без знания его назначения. Не все эффекты технологии обязательно находятся в `modifier`: другие игровые объекты могут открываться ссылкой на её ID.

### Описания UnlockDescriptionBlock

В базовых определениях найдены элементы `component`, `ship`, `custom`, `diplo_action` и `hide_prereq_for_desc`.

| Элемент | Тип | Назначение |
| --- | --- | --- |
| `component`, `ship`, `custom`, `diplo_action` | Повторяемые блоки с `title` и необязательным `desc` | Описание открываемой возможности соответствующего вида |
| `title` | `LocalizationKey` | Заголовок описания |
| `desc` | `LocalizationKey` | Дополнительный текст описания, если задан |
| `hide_prereq_for_desc` | `Identifier` | Скрытие автоматически формируемой группы описаний; найдены значения `component`, `ship` |

Это данные показа. Из записи `ship = { title = ... }` нельзя вывести, какой корабль фактически разрешён к постройке: для этого изучаются определения кораблей и их условия. Повторы блоков и нескольких `prereqfor_desc` сохраняются.

### Группы выбора исследований

Связанные поля имеют разную структуру:

```text
weight_groups = { repeatable }
mod_weight_if_group_picked = { repeatable = 0.01 }
```

Первое — список меток, второе — коэффициенты по меткам. В обоих полях найден также пустой блок у `tech_repeatable_lcluster_clue`. Эти группы не являются категориями исследования, условиями получения или связями предшественников. Точный алгоритм применения групп при выборе вариантов исследования в игре здесь не воспроизводится.

| `category` | `List<Identifier>` | Замена категорий исследования; наблюдаемые варианты используют `biology` или `psionics` | 11 / 1 |
| `prereqfor_desc` | `UnlockDescriptionBlock` | Описания открываемых возможностей для варианта; возможны повторения | 35 / 2 |

Пример: `tech_titans` содержит вариант `tech_biogenesis_titans` с `country_uses_bio_ships = yes`, областью `society`, категорией `biology`, `inherit_icon = no` и `inherit_effects = yes`.

Имя варианта не является надёжным уникальным ключом. Для различения записей существенны базовая технология и положение блока в её списке вариантов. Шаблон игры описывает выбор первого подходящего варианта и замену всего списка категорий. Эти сведения взяты из документации игры; значения по умолчанию для отсутствующих флагов наследования и поведение при пересечении условий в игре не проверялись.

## Связанные и производные данные

Следующие сведения нужны для понимания объекта, но не являются самостоятельными корневыми полями игрового определения:

| Данные | Тип / происхождение |
| --- | --- |
| ID | `Identifier`, имя внешнего блока |
| Файл и положение | Путь и номера строк определения; техническое происхождение |
| Версия источника | Версия игры, считанная из `launcher-settings.json` |
| Ключ названия | Обычно ID базовой технологии; для варианта используется его имя |
| Ключ описания | Для базовой технологии `<ID>_desc`; разрешение описаний вариантов требует учёта конкретного варианта |
| Текст названия и описания | Локализация по ключам и настроенному приоритету источников; язык и источник текста учитываются отдельно |
| Изображение | Для базовой технологии `gfx/interface/icons/technologies/<icon>.dds`, где `<icon>` — явное `icon` либо ID; у варианта учитывается наследование |
| Разрешённые значения `@...` | Результат сопоставления переменных с их определениями; исходная ссылка сохраняет самостоятельный смысл |
| Обратные связи | Технологии, которые ссылаются на текущую в своих `prerequisites`; получаются из других объектов |
| Открываемые объекты | Связи из определений компонентов, зданий и других объектов, а также `feature_flags`; `prereqfor_desc` не является полным каталогом |
| Доступность, выбранный вариант, цена и шанс сейчас | Вычисляемые значения, зависящие от государства и партии; не постоянные свойства исходного объекта |

Эта таблица описывает происхождение данных, не назначая им окончательные имена полей JSON. Представление технологии не зависит от выбора между графом и другим интерактивным интерфейсом.

## Отсутствующие и повторяющиеся поля

`area`, `tier` и `category` встречаются по одному разу у всех 679 технологий. Это подтверждает полноту данного набора, но не доказывает требования движка к любому возможному источнику.

У остальных полей отсутствие — отдельное состояние. Оно не заменяется автоматически на `0`, `false`, пустую строку или список. Например, `cost` отсутствует у пяти технологий, а явный `cost = 0` встречается в других определениях. Пустой `prerequisites = { }` сохраняется как явно заданный блок.

На верхнем уровне повторяются `technology_swap`, `weight_modifier`, `prereqfor_desc`, а также отдельные `start_tech`, `is_dangerous` и `weight`. Встречаются и одинаковые, и противоречащие друг другу значения.

У `tech_orbital_arc_furnace`, `tech_dyson_swarm`, `tech_dyson_gun` два значения `weight` различаются: 0 и 70, 0 и 70, 0 и 50 соответственно после разрешения переменных. Исходная модель содержит обе записи в исходном порядке. Выбор первого или последнего значения без подтверждения поведения движка не является разрешением неоднозначности.

Поэтому структура исходного блока не эквивалентна обычному JSON-объекту с одним значением на имя. Предлагаемый способ хранения повторов приведён в модели JSON-базы. Неизвестное поле в новом источнике требует изучения и дополнения описания; текущий список не является основанием молча удалять его.

## Пример определения

Сокращённый фрагмент `common/technology/00_megastructures.txt:1`; остальные поля исходной технологии здесь опущены:

```text
tech_mega_engineering = {
    area = engineering
    cost = @tier5cost3
    tier = 5
    category = { voidcraft }
    prerequisites = {
        OR = {
            tech_starbase_5
            tech_arkship_tier_3
        }
        tech_zero_point_power
        OR = {
            tech_battleships
            tech_stingers
        }
    }
    weight = @tier5weight3
    is_rare = yes
}
```

Здесь ID берётся из имени блока; `area` — идентификатор области, `category` — список, `tier` — целое число, `cost` и `weight` — ссылки на переменные, `is_rare` — логическое значение, `prerequisites` — составное выражение требований. Полученное разрешением переменной значение стоимости 24000 не меняет тип исходной записи `cost`.
