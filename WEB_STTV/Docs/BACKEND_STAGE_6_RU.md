## Статус и назначение

Реализовано утверждённое [ТЗ шестого этапа](TZ_BACKEND_STAGE_6_RU.md). Бэкэнд читает выбранные скрипты, разбирает их, раскрывает вложенные `inline_script` и сохраняет синтаксические деревья в JSON. Все источники доступны только для чтения.

Профиль игровых команд, реестр, анализатор рекомендаций и закрытая конверсия технологий удалены. Локализация и вычисления не входят в эту сборку. Игровые имена сохраняются независимо от их наличия в прежнем профиле.

Прежние руководства и [предметная модель БД](DATABASE_MODEL_RU.md) являются историческими. Новый формат имеет идентификатор `sttv.parse_database`, версию `1` и не совместим с прежними предметными форматами 1 и 2.

## Запуск и чтение базы

Используются Python и зависимость из [requirements.txt](../src/backend/requirements.txt): `jsonschema==4.26.0`. В текущем окружении подготовлена среда `WEB_STTV/data/.venv`. Команда из корня репозитория:

```powershell
& .\WEB_STTV\data\.venv\Scripts\python.exe -B .\WEB_STTV\src\backend\main.py
```

CLI принимает `--variables` и `--config`; по умолчанию выбирает `global_variables.json` и `config/backend.json` относительно каталога продукта. Рабочий каталог процесса не влияет на разрешение этих путей. Успех возвращает код 0 и JSON-отчёт в stdout; ошибка — код 1 и отчёт в stderr.

Для вызова из Python добавить `WEB_STTV/src/backend` в `PYTHONPATH`:

```python
from pathlib import Path
from sttv.builder import build
from sttv.database.storage import read_database

product = Path("D:/Repos/RBG_Stellaris_Mods/WEB_STTV")
report = build(product / "global_variables.json", product / "config/backend.json")
database = read_database(product / "data/database.json")
```

`read_database(path)` проверяет сохранённую структуру и метаданные. Ему не нужны игра, Workshop, конфигурация парсера или повторный разбор. Он возвращает обычные словари и массивы, без восстановления объектов парсера.

## Конфигурация и источники

[backend.json](../config/backend.json) содержит три раздела:

- `sources`: массив настроек `variable`, `pattern`, `recursive`, `encoding`. По умолчанию выбирается `TECH_PATH`, `*.txt`, рекурсивный обход и `utf-8-sig`.
- `parser`: выбор пяти конфигов из `config/parser/` — лексика, конструкции, логические операторы, inline-вставки и исключения. Для каждого поддерживаются базы `product` и `work`.
- `outputs`: `database.json` и `reports/build_report.json`, относительно `WORK_DIR`.

Обязательны `STELLARIS_ROOT`, `WORK_DIR`, `INLINE_SCRIPTS_DIR`, `SCRIPTED_EFFECTS_DIR` и переменные из выбранных источников. Workshop и локализация остаются в общем файле переменных для будущего обогащения, но не обязательны для текущей операции.

Источники находятся внутри `STELLARIS_ROOT`. Выборка включает `category` и `tier` как обычные файлы. Физически совпадающие файлы обрабатываются один раз; противоречащие кодировки одного файла вызывают ошибку. Порядок документов определяется относительным путём. Пустой скрипт сохраняется с пустым `items`; отсутствие выбранных файлов считается ошибкой.

Шаблоны в `INLINE_SCRIPTS_DIR` исключаются из самостоятельной выборки. Их чтение происходит только по достигнутым вызовам. Кеш шаблонов действует в пределах одной операции; следующая сборка читает актуальные файлы.

`SCRIPTED_EFFECTS_DIR` задаёт библиотеку именованных эффектов, по умолчанию `common/scripted_effects` относительно `STELLARIS_ROOT`. Каталог со всеми подпапками исключается из самостоятельной выборки общим фильтром сборщика и корпусного аудита. Вызовы эффектов остаются обычными узлами дерева; их раскрытие пока не реализовано. Путь должен находиться внутри игры, но существование исключённой библиотеки не требуется, если она не выбрана явно как источник.

`WORK_DIR` по умолчанию — `data`, также поддерживается другой относительный или абсолютный путь внутри репозитория. Запись не может пересекаться с источниками, кодом, конфигурацией и другими защищёнными материалами. Исходные TXT-файлы в рабочую папку не копируются.

Точечное исключение в [constructs.json](../config/parser/constructs.json): `trait_bg_active_glow` добавлен в `tagged_blocks` рядом с `rgb` и `hsv`. Это позволяет сохранить встреченную в игре запись без `=` как `tagged_block`. Отсутствующий оператор не дописывается; произвольные другие имена без оператора по-прежнему отклоняются. Это согласованное исключение нашего парсера, а не подтверждение допустимости такого объявления движком.

Файл [exceptions.json](../config/parser/exceptions.json) задаётся через `parser.exceptions` в `backend.json` и проверяется схемой `parser_exceptions.schema.json`. В `inline_script_files` ключ — имя вызова без автоматически добавляемого расширения, `file` — точное имя файла относительно `INLINE_SCRIPTS_DIR`, `reason` — причина исключения:

```json
{
  "format_version": 1,
  "inline_script_files": {
    "traditions/tr_purity_imperfection_remediation_wilderness": {
      "file": "traditions/tr_purity_imperfection_remediation_wilderness",
      "reason": "The installed vanilla template is shipped without the .txt extension."
    }
  }
}
```

Сопоставление точное после нормализации разделителей пути и регистра для Windows; дубли нормализованных имён отклоняются. Исключение имеет приоритет перед обычным добавлением `.txt`. При его отсутствии действует прежнее правило расширения. Если явно указанный файл отсутствует, операция завершается ошибкой без поиска альтернатив. Исключения не поддерживают маски, абсолютные пути, `..`, потоки NTFS или выход за `INLINE_SCRIPTS_DIR` после разрешения файловых ссылок. Файл только читается как текст и разбирается; в истории, координатах и хешах сохраняется фактический путь. Причина исключения не участвует в аналитике.

Конфиг исключений обязателен; для отсутствия исключений используется пустой `inline_script_files`. Отсутствующий или некорректный конфиг блокирует сборку. Сам файл конфига защищён от перезаписи результатами. Точечный синтаксический допуск `trait_bg_active_glow` остаётся в `constructs.json`.

## Сохраняемая структура

Корневой объект содержит `format`, `format_version`, `documents`. Каждый документ содержит `source`, `items`, `metadata`. Полное описание полей: [формат результата в ТЗ](TZ_BACKEND_STAGE_6_RU.md#5-формат-сохраняемого-json).

Семь видов узлов: `scalar`, `formula`, `block`, `tagged_block`, `conditional`, `assignment`, `logical_operation`. Узел имеет `kind`, свои синтаксические поля, `span` и `origin`. Сохраняются порядок, повторные записи, регистр, кавычки, параметры, формулы и исходные координаты. Числа, `yes`/`no` и `@name` остаются текстом внутри скалярных узлов.

Технология пока является обычной записью дерева. База не вычисляет стоимость, доступность и связи, не собирает названия и не объединяет повторяющиеся определения.

После раскрытия узлов вызова в дереве нет. История находится в `document.metadata.inline_scripts`. `insertion.container` указывает на массив узлов внутри того же документа; `index` и `count` задают диапазон вставки. Сохраняются аргументы, вложенные вызовы и вставки нулевой длины. Метаданные не участвуют в частотной статистике.

Полный исходный текст, токены, отдельные комментарии и пробельное оформление не сохраняются. `origin` сохраняет сведения о шаблонах, подстановках и фрагментах составленного текста. База предназначена для анализа дерева; побайтное восстановление исходника не предусмотрено.

## Модули и схемы

| Модуль | Ответственность |
| --- | --- |
| `sources/` | Конфигурация, защита путей, выбор файлов, чтение и хеши |
| `script/` | Лексер, парсер, синтаксические узлы, обход и сериализация |
| `script/inlining/` | Шаблоны, аргументы, подстановка и рекурсивное раскрытие |
| `database/` | Контейнер документов, проверки истории, чтение и публикация |
| `common/` | JSON, диагностика, пути и запись через временный файл |
| `schema_generation/` | Генерация восьми структурных схем приложения |

Используются `backend.schema.json`, `database.schema.json`, `report.schema.json` и пять `parser_*.schema.json`, включая новую схему исключений. Схема базы описывает виды узлов и метаданные; допустимые игровые имена в ней не перечисляются. Генератор не читает игру. Из корня репозитория:

```powershell
$env:PYTHONPATH = "$PWD/WEB_STTV/src/backend"
& .\WEB_STTV\data\.venv\Scripts\python.exe -B -m sttv.schema_generation
```

Исследования и `language/keywords/` сохранены, но не являются входом сборщика. В рабочей папке могут оставаться старые отчёты и реестр предыдущих этапов; текущий код их не читает и не обновляет.

## Ошибки и публикация

Синтаксические ошибки, недоступные источники, ошибки раскрытия, повреждённые узлы и ссылки истории блокируют публикацию. Неизвестное игровое имя, повтор поля или невычисленная обычная переменная сами по себе не являются ошибкой.

Предыдущая успешная база сохраняется при ошибке обработки. Подготовленный JSON проверяется, записывается во временный файл, перечитывается и заменяет целевой файл. База и отчёт публикуются отдельно: при ошибке отчёта после замены базы операция возвращает ошибку с `database_written: true`.

Отчёт версии 2 содержит число выбранных, разобранных и ошибочных файлов, число узлов, статистику inline-вставок, диагностику и SHA-256 источников. `sources` использует пути относительно `STELLARIS_ROOT`, `inline_sources` — относительно `INLINE_SCRIPTS_DIR`. Число узлов включает скалярные ключи и значения, но исключает историю.

## Проверки

Первоначальные результаты находятся в `data/stage6/`; повторный корпусный аудит после исключения scripted effects пишет отчёт и частотные списки в `data/stage6/without_scripted_effects/`. Исходные списки `data/text_frequency/` сохранены. Автоматизированные проверки запускаются из корня репозитория:

```powershell
$env:PYTHONPATH = "$PWD/WEB_STTV/src/backend;$PWD/WEB_STTV/src/backend/tests"
& .\WEB_STTV\data\.venv\Scripts\python.exe -B -m unittest discover -s WEB_STTV/src/backend/tests -v
& .\WEB_STTV\data\.venv\Scripts\python.exe -B WEB_STTV/src/backend/tests/database/audit_build.py
& .\WEB_STTV\data\.venv\Scripts\python.exe -B WEB_STTV/src/backend/tests/script/audit_corpus.py
```

- До изменений прошли 111 тестов; после удаления прежних механизмов и добавления новых проверок прошли 78 актуальных тестов.
- Технологический набор: 35 файлов, 67 513 узлов, 301 раскрытый вызов из 10 шаблонов; ошибок и предупреждений нет.
- Все поля сохранённых деревьев сопоставлены с объектами парсера независимо от сериализатора. Повторная сборка дала тот же SHA-256. Источники и шаблоны не изменены.
- Размер базы — 107 520 690 байт, около 102,5 MiB. Контрольная сборка заняла 62,181 секунды в текущем окружении при параллельном корпусном аудите; это измерение, не гарантия времени.
- Общий аудит `common/` и `events/`: 1 583 файла и 3 681 397 узлов прошли JSON-запись, чтение и проверку истории. Каталог из 631 шаблона исключён из самостоятельных входов; два документационных TXT исключены явно. Остались прежние 22 неуспешных входа; их файлы и коды ошибок совпали с пятым этапом. Частотный и два скалярных списка совпали побайтно. Подробности находятся в `data/stage6/corpus_report.json` и `acceptance_report.json`.

- После исключения scripted effects прошли 80 тестов. Повторный аудит: 1 542 успешных файла, 3 510 653 узла и 20 прежних неуспешных входов. Исключены 43 файла эффектов и 631 inline-шаблон; два документационных TXT по-прежнему пропущены. Новых ошибок нет, выборка технологий не изменилась. Исходники, шаблоны и прежние исследовательские списки сохранены. Результаты: `data/stage6/without_scripted_effects/corpus_report.json`.

- После добавления исключения `trait_bg_active_glow` прошли 17 целевых тестов синтаксиса и конфигурации. Реальный `01_trait_colors.txt` разобран, его JSON проверен схемой и повторным чтением; значения цвета сохранены. Ненастроенные имена без `=` отклоняются. Полный аудит заново не выполнялся; прежний корпусный отчёт сохранён. Точечный отчёт: `data/stage6/known_input_issues/validation_report.json`.

- После подключения файла исключений прошли все 87 тестов. Три файла традиций (`01_cloning.txt`, `01_mutation.txt`, `01_purity.txt`) прошли полный разбор, раскрытие, JSON-схему и проверку истории: 75 вызовов из 16 шаблонов, четыре обращения к разрешённому файлу без расширения, ошибок раскрытия нет. Проверены точность исключений, отсутствие поиска альтернатив, ошибки конфигурации, сохранение происхождения, циклы и запрет выхода за корень шаблонов. Игровые исходники и шаблоны не изменены; полный корпус повторно не запускался. Отчёт: `data/stage6/inline_exceptions/validation_report.json`.

## Ограничения и следующие этапы

Полная база загружается в память. Объём JSON обусловлен подробными деревьями и происхождением узлов; сжатие, индексы и разделение на несколько файлов не добавлялись.

Известные ограничения синтаксиса и раскрытия пятого этапа сохраняются. Корпусный аудит может завершиться частично и не публикует частичную рабочую базу. Успешная сборка технологического набора не означает поддержку всех скриптов игры.

Обогащение, названия RU/EN, вычисления, связи, интерфейс и portable-поставка требуют следующих ТЗ. Проверка в игре для этой операции не нужна: она читает файлы и не изменяет игру или моды.
