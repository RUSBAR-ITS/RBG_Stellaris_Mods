## Результат

Реализованы [основное ТЗ](TZ_BACKEND_STAGE_21_RU.md) и [дополнение о получении](TZ_BACKEND_STAGE_21_ACQUISITION_RU.md). Версия интерфейса — **0.0.13**, реализации обогащения дерева — **1.3.0**. Подготовленный набор: **`data/stage21_acquisition/database_set`**.

Набор содержит 30 видов: к предыдущим 25 добавлены `ascension_perks`, `traditions`, `tradition_categories`, `crisis_paths`, `crisis_levels`. Два кризисных справочника содержат 5 путей и 25 уровней. Их названия и доступные описания локализуются по прежним RU/EN-приоритетам; отсутствующий текст не сочиняется.

У всех 25 уровней найдены названия и описания на обоих языках. У пяти путей нет собственных строк по их ID/стандартным ключам: сохранены признаки отсутствия локализации, без подмены названием бонуса или валюты.

Косвенные ограничения прослеживаются через связанные игровые объекты. Выдача и открытие технологии анализируются отдельно от её обычного предложения для исследования. Возможность получения не означает владение сейчас. `has_technology` становится ложным только при доказанной невозможности всех путей; неполные сведения сохраняют `unknown`.

## Запуск

Из корня репозитория, PowerShell:

```powershell
$env:PYTHONPATH = (Resolve-Path WEB_STTV/src/backend).Path
WEB_STTV/data/.venv/Scripts/python.exe -X utf8 -B -m sttv.service
```

В другом терминале, из `WEB_STTV`:

```powershell
$env:PATH = (Resolve-Path data/frontend-tools/node-v24.22.3-win-x64).Path + ';' + $env:PATH
npm run dev
```

Открыть `http://127.0.0.1:5173/`, явно выбрать каталог `data/stage21_acquisition/database_set`. Сервис настроен на `data/stage21_acquisition/variables.json` в `config/service.json`. Нужны новый набор и новый интерфейс: манифест имеет `format_version = 2`; прежний формат не поддерживается.

Ни старт приложения, ни обновление страницы, ни «Применить» не собирают БД. Подготовку выполняет существующая Python-функция `sttv.database_sets.operation.build_database_set(variables, library_mode='reuse', prepare_images=True)`; для подготовки библиотек с нуля — `library_mode='rebuild'`. Полный аудит отдельно: `sttv.storage.audit.audit(manifest_path)`. Набор по старым правилам следует явно пересобрать, а не исправлять его манифест вручную.

Сервисы в ходе этой итерации не запускались. Команды выше предназначены для запуска пользователем.

## Данные и конфигурация

| Путь | Назначение |
| --- | --- |
| `config/enrichment/dlc.json`, `dlc/*.json` | Предикаты, источники объектов, контексты, логика, лимиты |
| `config/enrichment/acquisition/sources.json` | Корни технического индекса, формат, адрес, подключение групп правил |
| `config/enrichment/acquisition/effects.json` | Шесть команд получения, поля целей, области и основание семантики |
| `config/enrichment/acquisition/entries.json` | Входы, условия, вызовы событий и порядок кризисных уровней |
| `config/enrichment/targets/crisis_*.json` | Правила локализации кризисных справочников |
| `schemas/acquisition_*.schema.json` | Генерируемые схемы индекса и его конфигурации |

Индекс охватывает 1509 исходных TXT из `common`, `events`, `prescripted_countries`, за исключением библиотек вставок. Для 586 файлов переиспользован результат подготовки обычных БД; 923 обработаны дополнительными заданиями того же пула. JSON сохраняется с отступами и переносами, отдельным файлом на источник. Объёмы и время записаны в отчёте сборки; это результаты данного корпуса, а не константы.

Окончательная сборка с переиспользованием библиотек заняла 581,253 с, включая 84,814 с подготовки индекса. Индекс занимает 307 244 108 байт (293,011 МиБ). Опубликованы 619 обычных документов и 822 уникальных PNG; ошибки разбора исполняемых входов отсутствуют. Это замеры текущего компьютера, не изолированный сравнительный тест производительности.

`common/HOW_TO_MAKE_NEW_SHIPS.txt` содержит английскую инструкцию с примерами, а не исполняемый скрипт. Он объявлен в `sources.json` документацией с точным SHA-256 и основанием. Его покрытие отмечено отдельно; при изменении байтов классификация перестаёт действовать и файл проходит обычный парсер. Общего правила пропуска непонятных TXT нет.

Манифест содержит раздел `acquisition`: состав источников, хеши, индексы целей/вызовов, покрытие и ревизии конфигурации, реализации, библиотек и подготовки. Это служебный индекс, не 31-й пользовательский каталог. Публикация обычных документов и индекса атомарна. Не прочитанные документы не считаются проверенными; полный аудит проверяет их отдельно.

## Вычисление и кеш

Обычный путь учитывает `potential`, пререквизиты и вес; начальный — также `starting_potential`. Специальные выдачи не наследуют автоматически запреты обычного пути. Поддержаны прямые выдачи, варианты исследования, прогресс, случайные варианты и два вида копирования с подтверждёнными ограничениями. Сохраняются альтернативы, вызовы, получатель и адрес эффекта.

Обратные вызовы соединяют бонус/традицию, событие, `on_action`, активацию кризиса и упорядоченные уровни. Ветви эффектов обрабатываются по условиям исполнения. Неизвестное изменение состояния, область, вход, динамическая цель или цикл не превращаются в доказанный запрет.

Граф строится для нужных технологий и их зависимостей. Сервис сохраняет один подготовленный граф между применениями DLC; изменение набора, правил или вариантов отменяет его использование. Повторное чтение проверяет целостность, а неизменившиеся проверенные зависимости переиспользуются. Обработка не читает исходники игры. Фронтенд проверяет состав набора, но для обычного дерева не читает содержимое индекса получения.

Отчёт `dlc_analysis` содержит общие узлы графа, состояния получения/владения, специальные маршруты, причины неопределённости и покрытие. Доказательство DLC-причины сравнивается с результатом при неизвестных DLC. Нулевой исходный вес сам по себе не скрывает карточку.

Рабочие результаты находятся в `data/stage21_acquisition/`:

| Файл | Проверка |
| --- | --- |
| `reports/database_set.json` | Подготовка 30 видов, индекс, изображения, время и память сборки |

| `audit.json` | Полный аудит опубликованного снимка |
| `frontend_acceptance.json` | Открытие контрольных комбинаций загрузчиком, RU/EN-сетка, локализация кризисов |

Матрица проверяет скрытие оружия ткачей без BioGenesis. Во всех 43 профилях без Machine Age шесть технологий Латэ скрыты собственным DLC-условием; ракеты и торпеды сохраняются благодаря другим ветвям ИЛИ. Контрольные результаты: все DLC — 678 видимых технологий; ни одного — 448. В БД остаются все 679 объектов.

Последний прогон матрицы: 179 299 узлов, 8,644 с построения графа, 0,278–1,647 с на вычисление профиля без повторного чтения документов. Выборочно прочитано 440 из 2128 объявленных обычных и технических документов; остальные явно не проверены этим прогоном. Выборочный пик рабочей памяти процесса — около 989 МиБ. Матрица использовала закреплённый снимок, пока отдельная проверка публиковала новые комбинации; время не следует трактовать как изолированный benchmark.

Контрольные применения через сервис без HTTP:

| Профиль | Видимые технологии | Полная операция с отчётом, с | Действие |
| --- | --- | --- | --- |
| Ни одного DLC | 448 | 73,600 | Расчёт и публикация |
| `dlc002`, `dlc036` | 507 | 82,930 | Расчёт, переиспользован граф |
| Все DLC | 678 | 88,444 | Расчёт, переиспользован граф |
| Повтор всех DLC | 678 | 35,018 | Готовая комбинация, записано 0 документов |

Во время этих операций чтение каталога игры блокировалось проверкой. Пик рабочей памяти координатора — около 1191 МиБ, дерева процессов — около 2001 МиБ. Полное применение включает отдельную подготовку доказательств выбора родителей, публикацию и большой диагностический отчёт, поэтому не равно времени вычисления DLC-графа.

Все три результата открыты фронтенд-загрузчиком за 4,5–4,7 с каждый. Первичная загрузка проверила только 35 технологических документов, не читая индекс получения. Сетки RU/EN совпали с опубликованной видимостью и не содержат наложений карточек. По отдельному запросу проверены локализованные уровни кризиса и явное отсутствие строк путей.

Полный аудит опубликованного снимка прошёл за 327,975 с: проверены все 2128 документов (619 обычных и 1509 технических) и 822 изображения, ошибок нет. Обычные документы занимают 11 531 945 655 байт; основная часть — события. Этот полный обход не выполняется при обычном открытии или каждом применении DLC.

Проверка типов и production-сборка прошли; 71 обычный frontend-тест пройден, 4 проверки реальных данных пропущены в общем запуске. Новая проверка реального набора запущена отдельно и прошла. 41 схема совпадает с генератором; ссылки и оглавления 14 изменённых документов проверены. Направленные Python-проверки получения, хранения, кеша и пересчёта прошли, включая 21 сценарий семантики получения.

Модульные проверки покрывают ветви, выдачи без обычных пререквизитов, нулевой вес, динамические цели, чужого получателя, порядок уровней, циклы, неполное покрытие, изменение состава/правил, повреждение файлов и отмену. Проверка загрузчика выполняется без браузерного окна и не является визуальной приёмкой. Производственная сборка интерфейса проверяется отдельно.

## Ограничения и проверка движка

Полнота разбора файлов не равна полноте исполнения всех правил игры. Неизвестные способы и условия присутствуют в отчёте; симуляция партии не выполняется. Конкретные ID космогенезиса не зашиты в правила.

Штатная цепочка через `ap_cosmogenesis` и уровни кризиса подтверждена, но найденные случайные выдачи с `ignore_rare = no` не позволяют доказать невозможность получения `tech_cosmogenesis_world` / `tech_cosmogenesis_escort` всеми способами. Например, `events/shroud_events.txt:1247`. Локальная документация `add_random_research_option` не устанавливает проверку `potential` и нулевого веса. Для этих путей сохранена неизвестность; это не утверждение, что игра действительно выдаёт такие технологии.

Для проверки движка нужен отдельный контролируемый тест в игре: сопоставить случайный выбор с редкой технологией при положительном/нулевом весе, истинном/ложном `potential`, выполненных/невыполненных пререквизитах и `ignore_prereqs = yes/no`; проверить как успех, так и `fail_effects`. Отсутствие выпадения в нескольких попытках не доказывает запрет. Тестовый мод и правки игры не создавались; такой тест требует отдельной задачи. Также пользователю остаётся визуальная проверка смены DLC в интерфейсе.
