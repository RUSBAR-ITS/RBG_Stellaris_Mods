## Статус и место в отборе

Согласовано пользователем 2026-11-18. Критерий размещается после ранее согласованных критериев функционального родства. С последующим добавлением [родства через лимиты объектов](CHAIN_CAPACITY_AFFINITY_RU.md) текущий порядок соседних этапов: косвенное функциональное родство → родство через производственные бонусы → лимиты объектов → фильтр по империи → старшинство по игровому уровню.

Это решение для будущего ТЗ. Текущая итерация меняет документацию; код продукта и исследовательский расчёт предыдущего прохода не меняются.

## Основание связи

Если собственный модификатор технологии `T` улучшает производство экономической категории, а оставшийся кандидат `P` открывает объект, предоставляющий профессии этой категории, это подтверждает функциональное родство.

Проверяемая последовательность:

1. У `T` есть производственный бонус в собственном `modifier`.
2. Бонус сопоставлен с конкретной экономической категорией по её ID и правилам образования модификатора.
3. Производство профессии относится к этой категории через `resources.category`.
4. Здание или другой поддерживаемый объект предоставляет эту профессию; связь подтверждена его игровыми полями.
5. `P` открывает этот объект согласно игровым требованиям.

Для этого критерия самой `T` не требуется открывать объект: исходным свидетельством служит её собственный бонус. Названия технологий и заранее заданные пары ID не используются для выбора.

## Условия и подтверждения

- Сопоставляются конкретная экономическая категория и улучшение её производства. Стоимость и потребление ресурсов сами по себе не подтверждают эту связь.
- Принадлежность модификатора категории проверяется по данным и правилам его образования. Произвольное сходство строк не заменяет эту проверку.
- Сохраняются контекст и знак бонуса, условия предоставления профессий и доступа к объекту. Условное свидетельство не объявляется безусловным; вычисление текущего состояния игровой империи не требуется.
- Для выбранного представления технологии используются его действующие эффекты с учётом `technology_swap` и `inherit_effects`.
- Подтверждение содержит модификатор, категорию, профессию, предоставляющий её объект, технологию-кандидата и ссылки на источники каждого звена.

## Отбор кандидатов

Правило применяется только к текущему набору кандидатов `C`, если в нём больше одной технологии.

1. Собрать множество `M` кандидатов с подтверждённой производственной связью.
2. При одном кандидате в `M` выбрать его и завершить отбор.
3. При нескольких кандидатах заменить `C` на `M` и перейти к критерию лимитов объектов.
4. Если `M` пусто, сохранить `C` и перейти к критерию лимитов объектов.

Исключённые ранее кандидаты не возвращаются. Число профессий, зданий или подтверждений не даёт кандидату дополнительных голосов. Все исходные игровые пререквизиты сохраняются.

## Пример металлургического производства

Проверено по текущим данным Stellaris 4.5.4:

| Звено | Подтверждение |
| --- | --- |
| Металлокерамические сплавы (`tech_advanced_metallurgy_1`) | Собственный бонус `planet_metallurgists_produces_mult = 0.05`. |
| Экономическая категория `planet_metallurgists` | Определение содержит `generate_mult_modifiers = { produces upkeep }`, подтверждая образование производственного модификатора. |
| Профессия `foundry` | Её `resources.category` равна `planet_metallurgists`. |
| Здание `building_foundry_2` | После раскрытия вставки добавляет профессию через `job_foundry_add` внутри `triggered_planet_modifier`; условия этого блока сохраняются. |
| Голографические литейные формы (`tech_alloys_1`) | Указаны в требованиях здания. |

Другой кандидат — Металлокерамические материалы (`tech_ship_armor_2`) — не подтверждает эту производственную связь. Ожидаемый результат применения правила в разобранном случае: **Металлокерамические сплавы → Голографические литейные формы**.
