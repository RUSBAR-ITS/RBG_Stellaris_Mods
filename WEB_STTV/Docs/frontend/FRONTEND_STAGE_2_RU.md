## Запуск и открытие

Реализация [этапа 2 фронтенда](TZ_FRONTEND_STAGE_2_RU.md), версия интерфейса `0.0.2`. Запуск из `WEB_STTV`: `npm run dev` при наличии Node.js 24 и установленных зависимостей. Адрес: `http://127.0.0.1:5173/`. В текущем окружении можно использовать локальный Node.js:

```powershell
& .\data\frontend-tools\node-v24.22.3-win-x64\node.exe .\node_modules\vite\bin\vite.js --host 127.0.0.1
```

Нажать **«Открыть набор БД»** и выбрать одновременно:

- `data/databases/technologies.json`;
- `data/databases/components.json`;
- `data/databases/buildings.json`.

Порядок и имена файлов не важны: роли определяются по содержимому. Все три файла должны принадлежать одной сборке версии 5. Если нужно обновить данные, отдельно выполнить [команду бэкэнда](../BACKEND_STAGE_11_RU.md#запуск). Запуск страницы и её обновление не создают и не открывают БД.

Один Worker последовательно читает файлы; панель состояния показывает этап и номер файла. Поле появляется после подготовки всего набора. Отмена диалога сохраняет текущий набор; отмена начавшейся операции освобождает его. Повтор после ошибки использует весь прежний выбор из трёх файлов. Новая операция очищает прежнее поле.

## Подготовленные данные

Полные деревья остаются в Worker. Основной поток получает каталоги технологий, компонентов и зданий; общий индекс RU/EN; исходные технологические связи; отдельные требования объектов и их явные улучшения.

Адрес узла — `{ database, pointer }`, идентичность объекта — `{ database, id }`. Одинаковые ID и пути разных БД не смешиваются. Происхождение локализации, наследование и ссылки общих описаний компонентов также квалифицированы ролью БД. Условные описания зданий доступны по отдельным ID строк; активное условие не вычисляется.

`upgradeEvidence` объединяет свидетелей одной пары технологий. Свидетель появляется только при явном улучшении объектов, единственном прямом технологическом требовании каждого из них и наличии исходной связи между этими технологиями. Альтернативные или отрицательные требования объектов сохраняются, но не превращаются в предположение о единственном продолжении.

## Ошибки и отчёт

Открытие останавливается при неправильном количестве файлов, повторе роли, разных идентификаторах набора, старом формате, повреждённом JSON, отсутствующем нужном обогащении, дубле объекта, конфликте переводов или неразрешимой используемой ссылке. Частичный набор не показывается.

Кнопка **«Сохранить отчёт»** экспортирует `sttv.frontend_diagnostics` версии 2: все выбранные файлы, известные роли и идентификаторы, количества объектов/связей, предупреждения и причину ошибки. Подробности включают квалифицированные ссылки на проблемные узлы. Недостающие переводы остаются предупреждениями.

Фронтенд проверяет данные, нужные для преобразования; полный валидатор AST и игровых команд в браузер не переносится.

## Проверки

Проверены TypeScript, production-сборка, 26 модульных сценариев и 12 браузерных сценариев, включая полный игровой набор в собранном интерфейсе. Набор содержит 679 технологий, 1506 компонентов, 498 зданий и 21 условное описание здания.

Получены 615 исходных технологических связей, 1581 связь требований объектов и 720 улучшений объектов. Выделены 138 пар технологий с 503 свидетелями; подтверждены все 16 случаев и 60 свидетелей из прежнего исследования неоднозначных цепочек. Передаваемый основному потоку результат занимает около 9,0 МБ JSON вместо полных деревьев.

Рабочие отчёты: `data/stage11/frontend_catalog_report.json`, `data/frontend-tests/browser-report.json`, `data/frontend-tests/real-database.json`; снимки интерфейса — `data/frontend-tests/real-*.png`. В отчёте фронтенда 170 предупреждений об отсутствующих описаниях: 85 компонентов × два языка. Четыре нераскрытые ссылки локализации сохранены в происхождении строк; подробности находятся в отчёте бэкэнда. Ошибок преобразования полного набора нет.

## Границы этапа

Сохраняется действующая раскладка карточек технологий. Каталоги зданий и компонентов пока служат данными для будущего определения цепочек; отдельные экраны и новый алгоритм сортировки в этот этап не входят. Сохраняются язык, темы, тултипы, ручные варианты и отсутствие линий связей. Portable-поставка и сохранение состояния между запусками остаются отдельными задачами.
