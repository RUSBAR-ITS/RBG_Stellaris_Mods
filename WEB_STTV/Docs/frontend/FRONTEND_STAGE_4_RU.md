## Запуск и выбор каталога

Реализовано [ТЗ этапа 4](TZ_FRONTEND_STAGE_4_RU.md) совместно с [этапом 17 бэкенда](../BACKEND_STAGE_17_RU.md). Из `WEB_STTV` запустить `npm ci`, затем `npm run dev`; открыть `http://127.0.0.1:5173/`.

На текущем компьютере Node.js доступен в рабочем каталоге:

```powershell
$env:PATH="$PWD/data/frontend-tools/node-v24.22.3-win-x64;$env:PATH"
$env:npm_config_cache="$PWD/data/npm-cache"
npm run dev
```

Нажать «Открыть набор БД» и выбрать **папку `data/stage17/database_set`**. Она содержит проверочный набор этой итерации. Обычный путь будущих сборок — `data/database_set`; он задаётся в `config/storage.json`. Выбирать нужно корень с `manifest.json`, а не папку `documents`, отдельные JSON или отчёты.

Старт и обновление страницы не открывают набор и не запускают сборщик. После обогащения на бэкенде каталог нужно выбрать заново. Отмена, повтор, смена набора и сохранение отчёта остаются в меню. Браузер без поддержки выбора каталога получает отдельное сообщение RU/EN.

## Загрузка и ссылки

Сначала Worker читает манифест и проверяет наличие всех заявленных файлов. Затем загружает виды из `config/frontend/opening.json`; по умолчанию только технологии. Другие файлы, включая непривязанные старые версии, не читаются ради регистрации набора. У каждого вида и документа есть состояние загрузки; отчёт отдельно показывает проверку хешей.

SHA-256 вычисляется через `@noble/hashes` 2.4.0 одновременно с потоковым разбором UTF-8. Полный AST и история не передаются в основной поток; названия, описания, варианты и компактные каталоги сохраняются. Показ карточек не означает проверки всех остальных видов.

Внутренний контроллер предоставляет `loadDatasets(kinds)`, `resolveObjects([{database,id}])` и `resolveNodes([{database,document_id,pointer}])`. Последний загружает индексируемые корневые объекты, в том числе анонимные переходы терраформирования. Все фрагменты одного `on_actions` возвращаются вместе. Нужный документ определяется по индексу, повторные запросы в одном снимке не перечитывают его.

Запросы несут ID операции, ID запроса и ревизию снимка. Ошибка подгрузки сохраняет готовые технологии; частичные результаты не публикуются. Отчёт версии 3 содержит корень, ревизии, индексные количества, состояния загрузки, охват хеширования, байты, время и диагностику со ссылками на документы.

## Проверки

Проверены сборка и TypeScript; прошли 37 синтетических тестов. Две проверки реальных файлов запускаются отдельно и также прошли. Проверяются адаптеры, потоковый JSON и хеширование на границах UTF-8, отмена, устаревшие ответы, повтор, фрагменты, анонимные объекты, повреждение неиспользуемых файлов и сохранение предыдущих данных при ошибке подгрузки.

Все 14 браузерных сценариев прошли на Chromium, включая настоящий набор, меню, язык, тему, варианты, тултипы, прокрутку, отчёт, отмену и большой документ при запрещённых `File.text()` и `File.arrayBuffer()`. Проверочный поток и хеш не требуют полной строки файла.

Реальное начальное открытие подготовило 679 технологий: 35 из 450 документов проверены, 415 не прочитаны. Отдельный замер загрузчика Node.js — 2,601 с; браузерное открытие — 4,105 с, из них чтение документов — 3,526 с. Последующая явная загрузка всех видов в проверке заняла суммарно 164,587 с, прочитала 11 049 350 511 байт и сохранила 1506 компонентов, 498 зданий, остальные 12 каталогов и все 60 контрольных свидетельств улучшений. Это разные сценарии; полная подгрузка при обычном открытии не выполняется.

Браузер сообщил 37 300 000 байт используемой JS-кучи основного потока после открытия; память Worker этим показателем не измеряется. Документ событий размером 732 381 133 байта прочитан за 14,202 с, байтовый хеш совпал. Это отдельные замеры на текущем компьютере без очистки кэша ОС.

Отчёты: `data/stage17/browser_real_set.json`, `frontend_catalog_report.json`, `large_stream_probe.json`; журналы проверок находятся в том же рабочем каталоге.

## Ограничения

Старый выбор 15 монолитных файлов удалён. Доступ к папке между запусками не сохраняется, записи в БД из браузера нет. Сетка, сортировка и использование сохранённых родителей для размещения карточек остаются отдельным этапом. Непроверенные файлы могут содержать ошибку, которая обнаружится при запросе или полном аудите бэкенда.
