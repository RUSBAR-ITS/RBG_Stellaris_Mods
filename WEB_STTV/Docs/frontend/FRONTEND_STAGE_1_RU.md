## Результат

Реализован первый интерфейс по согласованным документам из [справочника элементов](UI_ELEMENTS_RU.md), ТЗ [открытия БД](TZ_DATABASE_OPENING_RU.md), [адаптера](TZ_DATABASE_ADAPTER_RU.md), [результата Worker](TZ_WORKER_RESULT_RU.md), [локализации](TZ_LOCALIZATION_RU.md) и [оформления](TZ_STYLING_DICTIONARY_RU.md). Версия пакета фронтенда — `0.0.1`.

Показываются карточки с названием и тултипом «название + описание», RU/EN, дневная и ночная темы, ручной выбор вариантов, области науки и столбцы уровней. По решению пользователя линии связей пока не рисуются; дерево требований и связи сохранены в подготовленном каталоге. Есть сворачиваемое меню, отдельная панель состояния, отмена обработки, повтор после ошибки и сохранение диагностического отчёта.

## Запуск

Команды выполняются из `WEB_STTV`. Для обычной среды разработки нужны Node.js 24 и зависимости из `package-lock.json`:

```powershell
npm ci
npm run dev
```

Открыть `http://127.0.0.1:5173/`. Остановить сервер — `Ctrl+C` в его терминале. Порт фиксирован: занятый порт вызывает ошибку запуска. Python-служба для просмотра не нужна.

В текущем рабочем каталоге уже подготовлены зависимости и локальный Node.js, без системной установки. Можно сразу запустить:

```powershell
Set-Location D:\Repos\RBG_Stellaris_Mods\WEB_STTV
& .\data\frontend-tools\node-v24.22.3-win-x64\node.exe .\node_modules\vite\bin\vite.js --host 127.0.0.1
```

Этот экземпляр Node.js — рабочий инструмент в игнорируемом `data/`, не portable-поставка продукта. Для другой копии проекта используется обычный способ выше.

Сборка: `npm run build`. Результат — `data/frontend-build/`; проверить собранную версию можно через `npm run preview`. Открытие `index.html` через `file://` не является способом запуска: Worker и модули загружаются через локальный сервер Vite. В готовой сборке шрифт и иконки локальные; внешние CDN для интерфейса не используются.

## Использование

1. Нажать **«Открыть БД»** и выбрать готовый JSON. Текущая проверенная база: `data/stage10/database.json`.
2. Дождаться сообщения о числе загруженных технологий. Отмена в файловом диалоге оставляет прежний каталог; отмена начавшейся обработки возвращает пустое начальное состояние.
3. Навести указатель на карточку для описания. Если описание выше окна, прокручивать колесо над карточкой: прокручивается тултип. Уход указателя скрывает его.
4. Нажать карточку с вариантами. Стрелки перемещают активный пункт, `Enter` подтверждает, `Escape` отменяет выбор. Варианты с совпадающими названиями получают локализованный суффикс с номером исходного варианта.
5. Менять язык и тему в меню. Скрытое меню оставляет внизу только кнопку раскрытия. Колесо прокручивает поле вертикально, `Shift` + колесо — горизонтально; полосы поддерживают перетаскивание, щелчок по дорожке и клавиатуру.
6. При необходимости нажать **«Сохранить отчёт»**. Браузер сохраняет JSON текущей завершённой попытки с её номером, именем и размером файла, ошибкой и предупреждениями. Полная БД в него не включается.

Запуск и обновление страницы не открывают файл и не вызывают генератор. Пересборка и обогащение БД остаются отдельными операциями бэкэнда. Настройки и выбранные варианты хранятся только в текущем сеансе; после обновления снова RU, ночная тема и раскрытое меню.

## Устройство реализации

| Каталог | Назначение |
| --- | --- |
| `src/frontend/app/` | Состояние приложения, подключение Worker, сообщения и выгрузка отчёта |
| `src/frontend/workers/` | Чтение JSON, протокол и управление жизненным циклом попыток |
| `src/frontend/data/` | Извлечение технологий, дерево требований, связи и раскладка |
| `src/frontend/localization/` | Индекс строк, происхождение и общий поиск по источнику/языку/ID |
| `src/frontend/locales/` | Встроенные словари RU/EN |
| `src/frontend/ui/` | Базовые, составные элементы, контейнеры и полосы прокрутки |
| `src/frontend/views/` | Сборка основного окна из UI-элементов |
| `src/frontend/styles/`, `assets/` | Словари оформления, общие стили, локальные Inter и SVG-иконки |
| `tests/frontend/` | Модульные и браузерные проверки |

Чтение файла, `JSON.parse` и адаптер работают в Worker. Полное дерево остаётся там до замены БД, отмены, ошибки или закрытия страницы. В основной поток передаются только `technologies`, `links`, `localization` и `diagnostics`. Новая попытка прекращает предыдущий Worker; принимается один конечный ответ от актуального Worker с актуальным `operationId`.

Адаптер использует прямые файлы `common/technology/*.txt`, не превращая вспомогательные определения из подкаталогов в технологии. Он проверяет формат/версию и обрабатывает невозможность собственных преобразований. Полный обход по JSON Schema бэкэнда во фронтенде не повторяется.

Индекс строк адресуется `source → language → id`. Для БД ID — `requested_key`, значение — сохранённый `text`. Одинаковые тексты объединяют происхождение; разные значения, отличные от `null`, под одним адресом блокируют подготовку. `null` означает отсутствие, пустая строка допустима. Отсутствие перевода даёт маркер `⟦ID⟧` и предупреждение; другой язык не подставляется.

## Конфигурация и оформление

| Файл | Что настраивает |
| --- | --- |
| `config/frontend/adapter.json` | Формат/версию БД, каталог технологий, поля и порядок областей |
| `config/frontend/interface.json` | Начальные настройки, размеры карточек, меню, отступов, прокрутки и оверлеев |
| `config/frontend/localization.json` | Языки, источник по умолчанию, читатели и пути источников текста |
| `config/frontend/diagnostics.json` | Соответствие диагностических кодов встроенным ID сообщений |
| `src/frontend/styles/dictionary.css` | Общая палитра обеих тем, типографика, локальный шрифт |
| `src/frontend/styles/elements.css` | Назначения собственных переменных элементов |

Конфиги включаются в сборку. Изменение файла при разработке обрабатывает Vite; для готовой сборки требуется повторный `npm run build`. Элементы используют собственные CSS-переменные; цвета и шрифты назначаются в словарях. Тексты интерфейса находятся в отдельных JSON, технические сообщения отчёта — на английском.

## Детали отображения

Карточка — `208 × 64` CSS px, межстолбцовый интервал — `24`, между карточками — `12`, внутренний отступ поля — `12`. Перед уровнем 0 есть только этот обычный отступ, без дополнительного пустого столбца. Меню — `244` px; свёрнутое — `53` px, включая кнопку `36`, отступы и границу. Значения находятся в конфиге.

Внутри каждого столбца применяется устойчивый топологический порядок: доступные для размещения карточки сравниваются по числу требований, затем по отсортированному набору непосредственных предшественников, затем по ID. Порядок наборов — лексикографический по их JSON-представлению. Зависимость в том же столбце и области имеет приоритет над этими критериями. Отдельного выравнивания семейств между соседними столбцами пока нет.

Геометрия не зависит от языка и темы. Вариант может перенести карточку в другую область, сохраняя базовые `tier` и требования. После переноса фокус возвращается к той же технологии без принудительной прокрутки. Тултипы и списки создаются поверх окна через портал; их положение ограничивается границами окна, они не расширяют поле.

## Проверки

```powershell
npm run build
npm test
$env:PLAYWRIGHT_BROWSERS_PATH = "$PWD/data/frontend-tools/browsers"
npx playwright install chromium
npm run test:browser
```

Для интеграционных проверок нужна существующая `data/stage10/database.json`; тесты её не генерируют. Chromium в текущем рабочем каталоге уже установлен. В среде без системного Node.js перед командами добавить локальную папку Node.js в `PATH` текущего терминала.

Проверены типы и production-сборка, 16 модульных сценариев и 10 браузерных сценариев Chromium. Проверки охватывают реальные данные, требования и порядок, варианты, происхождение переводов и конфликты, устаревшие ответы Worker, отмену/повтор, выгрузку отчёта, RU/EN, обе темы, длинный буквальный текст, клавиатуру, прокрутку и сброс после обновления страницы.

Реальный результат: 679 технологий, 206 вариантов, 615 связей, 3 400 уникальных адресов строк суммарно на двух языках; ошибок и предупреждений нет. JSON подготовленного каталога — 2 308 044 байта, исходная БД — 140 937 166 байт. Это размеры сериализованных данных, не измерение потребления памяти браузером. В контрольном запуске открытие и первый показ заняли около секунды; время зависит от среды и не является гарантией.

Отчёт браузера — `data/frontend-tests/browser-report.json`, замер — `real-database.json` в том же каталоге. Там же сохранены снимки `real-night.png`, `real-day.png`, `real-tooltip.png`, `real-variants.png`; внешний вид проверен по снимкам. Исходники игры и файлы БД не изменялись.

## Ограничения

- Линии, изображения технологий, поиск, вычисление игровых условий, автоматический выбор вариантов, генерация БД из UI, сохранение состояния между запусками и portable-поставка относятся к следующим этапам.
- Игровая разметка и динамические подстановки показываются буквальным текстом; HTML не выполняется.
- По дополнительному согласованию пользователя `NOT`, `NAND`, `NOR` в технологических требованиях останавливают открытие с `invalid_database` и причиной в отчёте. Их подсчёт и раскладка ещё не определены.
- Проверен Chromium на Windows. Другие браузеры отдельно не проверялись. Эта проверка справочника не требует запуска Stellaris.
