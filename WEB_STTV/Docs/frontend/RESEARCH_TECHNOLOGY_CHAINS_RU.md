## Область исследования

Исследование от 2026-11-17 по запросу пользователя после проверки первого интерфейса. Вход — существующая `data/stage10/database.json`. Изучаются базовые технологии и их `prerequisites`; условия доступности и игровые состояния не вычисляются. Варианты `technology_swap` остаются представлениями основной технологии, а не отдельными вершинами цепочки.

Это результаты анализа и предложения для обсуждения. Сортировка и код продукта в этой итерации не менялись; новых правил группировки этим документом не утверждается.

## Что сейчас делает сортировка

`sttvLayout` в `src/frontend/data/layout.ts` независимо собирает каждый столбец каждой области. `sttvOrderColumn` соблюдает зависимости внутри столбца, затем сравнивает число требований, набор предшественников и ID. Между соседними столбцами нет общего назначения строки цепочке.

Поэтому даже последовательные технологии одного семейства могут оказаться на разных высотах: порядок внутри своего столбца корректен, но развитие семейства не выровнено между столбцами. Это объясняет наблюдаемую пользователем проблему.

## Структура связей

Связь в таблице означает упоминание ID в `prerequisites`, включая альтернативы. Она не обязательно означает отдельное обязательное условие.

| --- | ---: |
| Базовые технологии | 679 |
| Представления-варианты | 206 |
| Уникальные пары «предшественник → технология» | 615 |
| Технологии без технологических предшественников | 178 |
| Технологии с одним непосредственным предшественником | 412 |
| Технологии с несколькими непосредственными предшественниками | 89 |
| Технологии с `OR` в требованиях | 19 |
| Группы `OR` в исходных требованиях | 21 |
| Технологии, упомянутые требованиями нескольких других технологий | 115 |
| Изолированные технологии без входящих и исходящих связей | 115 |
| Связные компоненты при игнорировании направления | 156 |
| Размер крупнейшей компоненты | 393 технологии |
| Связи между базовыми представлениями разных областей | 91 |
| Связи внутри одного `tier` | 193 |
| Связи от большего `tier` к меньшему | 13 |

Граф не содержит направленных циклов; все упомянутые технологические ID разрешаются. Из 89 технологий с несколькими предшественниками 19 используют альтернативы `OR`, остальные 70 имеют только одновременные требования. Из 156 компонент 115 — одиночные вершины; остаётся 41 связанный участок из нескольких технологий.

Принадлежность одной связной компоненте слишком широка для семейства: объединение всей крупнейшей компоненты дало бы одну группу из 393 технологий.

## Примеры цепочек

| Семейство | Последовательность по фактическим зависимостям | `tier` |
| --- | --- | --- |
| Лазеры | Красные → Синие → УФ → Рентгеновские → Гамма-лазеры; `tech_lasers_1…5` | `0 → 1 → 2 → 3 → 4` |
| Щиты | Отражатели → Улучшенные отражатели → Щиты → Улучшенные щиты → Гиперщиты; `tech_shields_1…5` | `0 → 1 → 2 → 3 → 4` |
| Реакторы | Ядерный → Термоядерный → Холодного синтеза → Антиматерии → Нулевой точки → Энергия тёмной материи | `0 → 1 → 2 → 3 → 4 → 5` |
| Ракеты | `tech_missiles_1 → tech_missiles_2 → tech_missiles_3 → tech_missiles_4 → tech_missiles_5` | `0 → 1 → 2 → 3 → 4` |
| Добывающие станции | `tech_space_mining_1 → … → tech_space_mining_5` | `1 → 1 → 2 → 2 → 3` |
| Космические базы | `tech_starbase_1 → … → tech_starbase_5` | `0 → 0 → 2 → 3 → 4` |

Реакторная цепочка подтверждается `prerequisites`, хотя последовательных номеров в ID нет: `tech_fission_power → tech_fusion_power → tech_cold_fusion_power → tech_antimatter_power → tech_zero_point_power → tech_dark_matter_power_core`.

Опорные места в сохранённых данных: лазеры — `common/technology/00_phys_weapon_tech.txt`, строки 8, 30, 85, 140, 195; реакторы — `00_phys_tech.txt`, строки 1487, 1521, 1575, 1627, 1679, затем `00_fallen_empire_tech.txt:43`; станции — `00_eng_tech.txt:2384` и далее. Это координаты происхождения из БД, не повторная проверка установленной игры.

## Продолжение семейства и дополнительные требования

У `tech_lasers_2` четыре непосредственных зависимых технологии: `tech_lasers_3`, `tech_plasma_1`, `tech_disruptors_1`, `tech_repeatable_weapon_type_energy_fire_rate`. Продолжение лазерного семейства — очевидный кандидат `tech_lasers_3`, но граф сам по себе не помечает эту связь как основную, а остальные как боковые.

У `tech_missiles_2` два одновременных требования:

```text
tech_missiles_1 + tech_fusion_power → tech_missiles_2
```

Для семейства ракет связь с `tech_missiles_1` выглядит продолжением, а связь с `tech_fusion_power` — дополнительным условием из реакторного семейства. Это интерпретация для отображения; обе игровые зависимости равноправно сохраняются.

Аналогично `tech_basic_science_lab_3` требует `tech_basic_science_lab_2` и `tech_colonial_centralization`. Мегапроектирование объединяет реактор нулевой точки и две группы альтернатив, после чего открывает десять других технологий. Такие узлы нельзя автоматически отнести к единственной линии по одному лишь числу связей.

В верхнеуровневых полях 679 технологий не найдено отдельного явного поля семейства или главного предшественника. `area`, `category`, ID и названия дают дополнительные признаки для анализа, но `prerequisites` не различает продолжение серии и внешнее условие.

## Ограничения уровней и идентификаторов

Номер в ID и `tier` различаются. У добывающих станций пять последовательных технологий размещаются в трёх уровнях; у космических баз первые две имеют `tier=0`. Даже среди связей внутри числовых семейств 41 соединяет технологии одного уровня. Поэтому цепочку нельзя всегда уложить в единственную горизонтальную строку с одной карточкой на столбец.

Из 13 связей в сторону меньшего `tier` пример — `tech_antimatter_power` (`3`) → `tech_reactor_boosters_3` (`1`). Это не направленный цикл. Сам по себе переход в меньший уровень не доказывает ошибку данных; `tier` не является глубиной графа.

Совпадение ID без последнего числа также не доказывает линейную последовательность:

- `tech_akx_worm_1` и `tech_akx_worm_2` совместно требуются для `tech_akx_worm_3`. Все имеют `tier=3`, второй относится к социологии, остальные — к физике. Это объединение двух ветвей, а не `1 → 2 → 3`.
- Между `tech_crystal_armor_1` и `tech_crystal_armor_2` нет связи через `prerequisites` в этой БД.
- `tech_cosmogenesis_crisis_1…5` также не образуют такую последовательность через `prerequisites`.

Области в статистике относятся к основным представлениям. Ручная смена варианта может поменять отображаемую область; базовые ID и зависимости остаются прежними.

## Автоматически выделенные кандидаты

Проверены два простых способа отбора без изменения продукта:

1. **Линейные фрагменты по структуре.** Оставить связь, если у её начала ровно один зависимый узел, а у конца ровно один предшественник. Получены 94 максимальных фрагмента из 242 технологий. Метод обрывает обычные семейства на боковых ветках: например, не сохраняет всю лазерную цепочку.
2. **Числовые семейства плюс реальные связи.** Сгруппировать ID по общей части до последнего `_число`, затем рассмотреть только существующие связи внутри группы. Найдены 98 многотехнологических групп и 182 внутригрупповые связи. Две группы не имеют связей, одна объединяет два входа; оставшиеся 95 образуют линейные кандидаты из 275 технологий. Внешние требования при этом не удаляются.

Объединённое покрытие этих двух выборок — 335 уникальных технологий. Это покрытие кандидатов, а не готовое разбиение: выборки пересекаются, тематическую правильность и границы семейств ещё нужно определить. Отсутствие технологии в выборках не означает отсутствие цепочки; реакторы — пример связи без числового шаблона.

## Вывод для следующего обсуждения

Для отображения имеет смысл отдельно определить принадлежность к цепочке и продолжение внутри неё, сохранив полное дерево требований. Это позволит располагать лазерные технологии рядом по уровням, оставляя плазму отдельной соседней ветвью и не присоединяя реакторы к ракетам из-за дополнительного условия.

Начать можно с проверенных числовых семейств, затем разобрать ненумерованные последовательности и неоднозначные объединения. Для одинакового уровня потребуется размещение нескольких карточек одной цепочки вертикально внутри соответствующего столбца. Конкретные правила выбора основного продолжения, принадлежности нескольким семействам и геометрии предстоит обсудить и утвердить.
