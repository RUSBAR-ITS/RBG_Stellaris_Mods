## Результат и запуск

Реализовано утверждённое [ТЗ этапа 8](TZ_FRONTEND_STAGE_8_RU.md). Карточка показывает игровую иконку, полное название, категории, игровой уровень, стартовый признак, базовые стоимость/вес и конечное число повторений. Фон соответствует области науки; редкая рамка фиолетовая, опасная красная, опасность имеет приоритет.

Из `WEB_STTV` выполнить `npm run dev`, затем открыть `http://127.0.0.1:5173/`. На текущем компьютере:

```powershell
$env:PATH="$PWD/data/frontend-tools/node-v24.22.3-win-x64;$env:PATH"
npm run dev
```

Нажать «Открыть набор БД» и выбрать **`data/stage17/database_set`**. Он уже дополнен изображениями. Для другого набора предварительно выполнить [подготовку ресурсов](../BACKEND_STAGE_18_RU.md#запуск). Без неё интерфейс просит подготовить изображения; генератор автоматически не запускается.

Готовая комбинация по-прежнему задаётся `combination_id` в `config/frontend/tree_layout.json`. Поддержаны `reference_default` и `reference_variants`; интерактивное переключение пока отложено.

## Карточка и геометрия

- Отсутствующие стоимость/вес скрывают весь ряд; явно заданный ноль виден.
- Для блока `cost` показывается исходный `factor`. Имперские множители и стоимость повторного исследования не вычисляются.
- «Уровень N» использует игровой `tier`, даже если технология размещена в столбце 6. «Уровни: N» показывается только для конечного `levels > 1`.
- Выбранное представление определяет название, описание, иконку, область и категории. Базовые числа и признаки берутся из основной технологии.
- Название и категории переносятся без обрезки. Тултип сохраняет название и описание; игровые коды форматирования остаются обычным текстом.

Ширина карточки — 520 px, минимум высоты — 158 px. Прежний минимум 188 px создавал избыточное пустое место. Новый минимум вмещает иконку 112 px, внутренние отступы по 14 px, внутреннюю границу по 1 px, полосу рамки по 6 px и внешний контур по 2 px. Скрытая измерительная композиция использует те же UI-элементы и фактические шрифты. Максимальная необходимая высота назначается всем карточкам; затем рассчитываются геометрия и SVG. Смена языка повторяет измерение. Загрузка изображения не меняет размеры. У карточек с коротким содержимым остаётся место до общей высоты, необходимой самым высоким карточкам.

Цвет редкости или опасности заполняет всю рамку между внутренней поверхностью и внешней границей карточки. Внутренняя поверхность сохраняет цвет области науки; у обычной технологии рамка совпадает с ним. Это исправляет прежнее окрашивание только внешнего контура.

На этапе 8 масштаб равнялся 100%. В последующем [этапе 9, версии 0.0.10](FRONTEND_STAGE_9_RU.md) реализована настройка масштаба с начальным значением 50%.

Сохранены логические места, родительские связи, мостики, точки на углах и подсветка родителя/детей. В обеих темах метрики шрифтов одинаковы, поэтому смена темы не требует новой раскладки.

## Модули и настройки

| Путь | Назначение |
| --- | --- |
| `config/frontend/card.json` | Иконка 112 px, значок стоимости 20 px, отступы, рамка и свечение |
| `config/frontend/interface.json` | Общая ширина, минимум высоты и промежутки |
| `config/frontend/adapter.json` | Поля исходных характеристик |
| `data/presentation.ts` | Извлечение чисел, признаков, категорий и ссылки на иконку |
| `storage/assets.ts` | Реестр ресурсов, проверка при чтении, кэш и категории |
| `ui/base/ResourceImage.tsx` | Общий элемент изображения, декодирование, URL и заглушка |
| `ui/composite/CardContent.tsx` | Общая строка характеристик и содержимое карточки |
| `ui/composite/CardMeasurement.tsx` | Измерение полной высоты текста |
| `styles/dictionary.css`, `styles/elements.css` | Палитры и роли цветов/шрифтов |

Все пути к коду в таблице отсчитываются от `src/frontend/`, кроме явно указанных `config/`. Заголовок — Inter 17/23 px, 600; детали — 13/20 px, 400. Цветовые литералы находятся только в словаре. Геометрические величины карточки передаются из конфигов через CSS-переменные.

## Изображения и диагностика

Worker читает только ресурсы выбранных представлений и нужные значки стоимости. Проверяет размер, SHA-256, заголовок PNG и размеры; повторное обращение использует кэш. UI создаёт один объектный URL и выполняет предварительное декодирование один раз для уникального ресурса открытого набора. Карточки используют тот же URL; при замене набора URL освобождаются.

Отсутствующее/повреждённое изображение даёт нейтральную заглушку и `image_unavailable` в сохраняемом отчёте, включая ошибки браузерного декодирования. Некорректные необязательные числа скрываются с `card_value_invalid`; отсутствующие числа предупреждением не считаются. Противоречивые обязательные признаки или непригодные данные раскладки завершают открытие ошибкой. Повторные одинаковые `is_dangerous = yes`, встречающиеся в ванильной БД, допускаются.

Отсутствующая подготовка ресурсов даёт `assets_not_prepared`. Для просмотра причин используется существующая кнопка «Сохранить отчёт». Браузер не обращается к абсолютным адресам установленной игры.

## Проверки

TypeScript и production-сборка прошли. Пройдены 65 модульных проверок; ещё 3 проверки требуют явно заданной реальной БД и в обычном запуске пропускаются. Отдельная проверка двух реальных комбинаций на RU/EN прошла: 679 технологий, 464/463 локальных связей, исходный порядок и данные не изменены.

В браузере пройдены 24 проверки: 23 общих и 1 отдельная проверка кэша/декодирования изображений. Один прежний тест большого монолитного файла пропущен: его отдельный вход не задавался. Проверены реальные и искусственные карточки, обе темы, длинные названия, нулевые/отсутствующие значения, тултипы, клавиатура, прокрутка, сворачивание меню, изменение окна, подсветка и мостики. Все 679 выбранных реальных иконок загрузились.

Результаты — `data/stage18/`, снимки — `data/frontend-stage8/`: `real-ru-night.png`, `real-en-night.png`, `synthetic-night.png`, `synthetic-day.png`. Последние проверяют также искусственное длинное название и приоритет красной рамки.

После исправлений версии 0.0.9 прошли производственная сборка с TypeScript и 10 браузерных проверок карточек, связей, тултипов и сетки; 2 сценария подмены конфигурации разработки пропущены при проверке производственной сборки. Проверен реальный набор из 679 технологий на RU/EN. Снимки `data/frontend-stage8/` обновлены. Для просмотра достаточно обновить страницу и открыть тот же набор БД; пересборка данных не нужна.

## Проверка пользователем

Оценить читаемость размера карточки и иконок, палитру обеих тем и удобство просмотра увеличенного поля. Изображения сохраняют исходные игровые пиксели; дополнительной детализации при увеличении не создаётся. Проверка в игре не нужна. Варианты, дополнительные связи и оценка условий империи остаются последующими этапами.
