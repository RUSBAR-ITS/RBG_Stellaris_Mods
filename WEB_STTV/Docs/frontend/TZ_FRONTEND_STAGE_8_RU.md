## 1. Статус и границы

**Утверждено пользователем и реализовано 2026-11-19.** Запуск и результаты — в [руководстве 0.0.9](FRONTEND_STAGE_8_RU.md). Пользователь уточнил: отсутствующие стоимость и вес не показываются, включая подписи строк.

Основа — схема пользователя, [карточка технологии](elements/TZ_TECHNOLOGY_CARD_RU.md), [словарь оформления](TZ_STYLING_DICTIONARY_RU.md) и [связи этапа 7](TZ_FRONTEND_STAGE_7_RU.md). Подготовку изображений и названий категорий определяет [этап 18 бэкенда](../TZ_BACKEND_STAGE_18_RU.md).

Этот этап заменяет прежнее ограничение «только название», обрезку названия до двух строк и прежние размеры карточки. Открытие готового каталога остаётся явным. Сохраняются выбор родителей, логический порядок деревьев, текущая комбинация и связи только внутри области науки. Интерактивная смена вариантов, дополнительные связи, фильтры империи и форматирование игровых описаний сюда не входят.

## 2. Состав карточки

Слева размещается квадратная область игровой иконки; справа — текстовое содержимое. Иконка сохраняет пропорции и полностью помещается в своей области. Карточка содержит внутреннюю поверхность и внешнюю рамку, соответствующие схеме пользователя.

| Элемент | Отображение |
| --- | --- |
| Название | Полностью; переносы разрешены, многоточие и ограничение числа строк запрещены |
| Информационная строка | Локализованная научная категория — «Уровень N» — «Стартовая» только при `start_tech = yes` |
| Стоимость | «Стоимость:» + значок исследовательского ресурса эффективной области + базовое число |
| Вес | «Вес:» + базовое число |
| Ограниченные повторения | «Уровни: N» только при конечном количестве уровней больше одного |

При нескольких категориях показать все в исходном порядке с локализованным разделителем. Длинная информационная строка переносится. Скрытая необязательная строка не оставляет подпись, значок, прочерк или отдельный пустой ряд; общая высота карточек при этом сохраняется.

Тултип по наведению и клавиатурному фокусу содержит название и описание выбранного представления. Полное название в карточке не заменяет тултип. Сохранить подсветку связей к непосредственному родителю и детям.

## 3. Правила значений

| Поле | Правило |
| --- | --- |
| Уровень в карточке | Исходный игровой `tier`; не номер столбца раскладки |
| Стартовая технология | Основное поле `start_tech = yes`; при отсутствии отметка не показывается |
| Скалярный `cost` | Исходное числовое значение после выполненной бэкендом подстановки статических переменных |
| Блок `cost` | Базовый числовой `factor`, без применения условных модификаторов |
| `weight` | Базовое числовое поле основной технологии; это вес выбора, не вероятность в процентах |
| Отсутствующие `cost` или `weight` | Соответствующая строка полностью скрыта |
| Число `0` в стоимости или весе | Строка видима, значение `0` сохраняется |
| `levels > 1` | Показать конечное число повторений |
| Отсутствующее `levels`, `levels = 1` или `levels = -1` | Строка количества уровней скрыта |

Для повторяемой технологии стоимость показывается для исходного уровня: `cost_per_level` не прибавляется без заданного числа исследований. `weight_modifier`, условные модификаторы стоимости и множители веса внутри `technology_swap` не вычисляются. Поле карточки остаётся базовым весом основной технологии; блок веса варианта не трактуется как его замена простым числом.

Технология игрового уровня 5, размещённая правилами дерева в шестом столбце, подписывается «Уровень 5». Название столбца и подпись карточки имеют разные назначения.

Явно заданное некорректное значение не считать отсутствующим. Не выводить `NaN` и не подставлять ноль: записать диагностическое сообщение с ID технологии, представлением и адресом поля, проблемную необязательную строку скрыть. Отсутствие обязательных данных для самой раскладки обрабатывается существующими ошибками открытия.

## 4. Представления и локализация

Использовать представление из уже подготовленной комбинации дерева. Из него берутся название, описание, эффективные область и категории, подготовленная ссылка на изображение. Категории и область наследуются от основной технологии, если переопределения нет; список категорий варианта заменяет основной целиком.

Стоимость, базовый вес, `tier`, `start_tech`, `levels`, `is_rare` и `is_dangerous` берутся из основной технологии. Не вводить общий механизм произвольного наследования всех игровых полей: перечисленные правила составляют контракт этого этапа. Не выбирать представление по условиям империи во фронтенде.

Подписи интерфейса передаются общему элементу текста через ID строк встроенных словарей RU/EN. Названия технологий и категорий берутся из БД через действующий механизм источников локализации. Сохранить согласованные подписи «Вариант N» для совпадающих названий. Числа форматировать общим средством текущего языка, без выдуманной единицы измерения или процента для веса.

Смена языка обновляет текст, алфавитный порядок по существующим правилам и расчёт необходимых размеров. Она не перечитывает игровые источники и не запускает бэкенд.

## 5. Цвета и состояния

| Признак | Оформление |
| --- | --- |
| Физика | Синий фон |
| Социология | Зелёный фон |
| Инженерия | Жёлтый фон |
| Обычная технология | Внешняя рамка цвета фона карточки |
| `is_rare = yes` | Фиолетовая рамка с мягким свечением |
| `is_dangerous = yes` | Красная рамка с мягким свечением |
| Оба признака | Красное оформление опасной технологии имеет приоритет |

Оформление редкости и опасности постоянно, а не только при наведении. Свечение статическое. Цвет фона определяется эффективной областью представления. Дневная и ночная темы сохраняют эти цветовые значения, подбирая яркость поверхности и контраст текста для каждой темы.

Уточнение пользователя после проверки: рамка — вся полоса между внутренней поверхностью и внешней границей карточки. Цветом редкости/опасности заполняется эта полоса, а не только внешний контур.

Все цвета, шрифты, рамки и параметры свечения задавать однозначными переменными элементов в отдельном словаре оформления, при необходимости через общий слой токенов. Компоненты не содержат собственных цветовых литералов. Размеры и отступы берутся из конфигурации.

Наведение и клавиатурный фокус остаются различимыми и не подменяют цвет редкости/опасности. Их оформление не меняет размер карточки и положение соседей. Подсветка родительских/дочерних линий сохраняет собственные цвета этапа 7.

## 6. Размеры и геометрия

Для всего поля использовать общую настроенную ширину карточки и одну общую вычисленную высоту, достаточную для самого высокого содержимого в текущем языке и комбинации. Настроенный минимум высоты допускается, максимум с обрезкой текста — нет. Зарезервировать размеры иконки до загрузки изображения.

Последовательность: подготовить текст и данные → определить общие размеры с учётом фактических шрифтов и переносов → выполнить пиксельную раскладку и маршрутизацию → показать согласованное поле. Измерение не должно вызывать бесконечный цикл перерасчёта или использовать приблизительную длину строки вместо проверки реального переноса. Кэш измерений внутри сеанса допустим с учётом языка, ширины и типографики.

Логические `(area, column, row)` рассчитываются прежними правилами. Новые размеры, внутренние отступы и пространство для свечения учитываются при расчёте промежутков, портов связей, мостиков, границ поля и прокрутки. Линии не проходят через карточку; стрелка касается её внешней границы, а не внутренней области текста или иконки. Точки ответвлений остаются на самих углах без сдвига.

Изменение языка или типографики, влияющее на размеры, обновляет карточки и SVG в одной согласованной геометрии. Завершение загрузки картинки не меняет размеры. При смене темы пересчёт нужен только при изменении параметров, влияющих на размеры.

## 7. Ресурсы и UI-элементы

Расширить компактный каталог, адаптер и контракт Worker только данными карточки. Полный AST не переносить в UI ради нескольких дополнительных полей. Применить новые схемы манифеста и обогащения из этапа 18; для старого набора сообщить о необходимости явной подготовки ресурсов, не запускать её автоматически.

Изображения загружаются из выбранного каталога через реестр манифеста, с проверкой при чтении. Один ресурс читается и декодируется один раз в пределах открытого набора. Не загружать изображения невыбранных вариантов заранее. Повторные обращения используют кэш; при закрытии или замене набора освобождать объектные URL и другие связанные ресурсы.

Отсутствующее изображение показывает нейтральную заглушку в том же месте с диагностикой. Повреждение объявленного файла также диагностируется; оно не превращается в незаметную подмену. Не обращаться из браузера к абсолютным путям установки игры. Для декоративного изображения рядом с уже озвучиваемым названием не дублировать текст для средств доступности; значок стоимости должен сохранять понятный смысл исследовательской области.

Соблюдать атомарную структуру UI: общий элемент изображения, имеющийся элемент текста, элемент строки характеристик, композиция карточки и общий тултип. Переиспользовать текущие механизмы состояний и отчётов. Имена новых модулей и публичных сущностей следуют соглашениям проекта; файлы остаются компактными.

## 8. Проверки и приёмка

1. Проверить скрытие отсутствующих стоимости/веса и показ явно заданного нуля; базовый `factor`, исходный вес и конечные/бесконечные повторения.
2. Проверить три области, обычную/редкую/опасную карточку и приоритет опасной при обоих признаках в обеих темах.
3. Проверить полные длинные названия, переносы категорий и общие размеры на RU/EN; внутренний текст и иконки не перекрываются.
4. Проверить наследование иконки, собственное изображение варианта и смену области/категории в готовой комбинации.
5. Проверить кэш изображений, освобождение ресурсов при замене набора, отсутствие доступа к игре и автоматической генерации.
6. Проверить тултипы, фокус, подсветку родителей/детей, точки на углах, мостики, прокрутку, изменение окна и сворачивание меню после увеличения карточек.
7. На реальных `reference_default` и `reference_variants` для RU/EN подтвердить наличие всех 679 технологий и сохранение логического порядка относительно действующих правил. Число локальных связей должно сохраниться; пиксельные координаты и число мостиков могут измениться.
8. Выполнить проверку TypeScript, production-сборку, необходимые модульные/браузерные проверки и сохранить снимки новой карточки и поля для визуальной оценки пользователем.

Результаты: расширенный интерфейс и конфиги, рабочий подготовленный набор, отчёты и двуязычное руководство этапа 8. Обновить справочники затронутых UI-элементов, текущие инструкции и оба changelog. Проверка в игре не нужна; синтетические проверки не заменяют оценку читаемости пользователем в браузере.
