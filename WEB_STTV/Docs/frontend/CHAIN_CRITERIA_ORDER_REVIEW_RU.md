## Решение и границы

2026-11-19 пользователь согласился поставить функциональные группы перед прямыми функциональными связями при условии отсутствия нежелательных изменений других цепочек. Проверка базовых представлений текущей БД показала изменение только Джаггернаута в ожидаемую сторону. Для будущего ТЗ фиксируется порядок: прямые улучшения → совпадение `potential` → **функциональные группы → прямые функциональные связи** → косвенное родство → производственные бонусы → лимиты объектов → фильтр империи → старшинство.

Это аналитическая проверка выбора `parent_tech`, а не внедрение сортировки во фронтенд. Геометрия карточек и визуальное отображение не проверялись. Результат относится к текущим данным и описанным формам свидетельств, а не гарантирует неизменность на будущих версиях игры.

## Метод сравнения

- Использован набор `8d7f30af6cc5a9504e6fbb0e2126edae8d18fe9a159f9969e574926ca62b5f01` и ранее согласованный профиль обычной империи. Размеры и SHA-256 восьми исходных БД, необходимых для сравнения, сверены с исследовательскими проекциями.
- Для всех технологий выполнены одинаковые первые шесть критериев: ID без цифр, область, категория, обязательность, прямые улучшения и совпадение `potential`.
- Затем на одном входном наборе сравниваются два порядка: прямые связи → группы и группы → прямые связи. Учитываются обе согласованные группы: подвижный боевой корабль и изменение класса планеты.
- Поддерживаемые прямые связи повторно извлечены из объектов; результаты для входных кандидатов совпали с предыдущим исследованием. Проверены остановка на единственном кандидате, пропуск пустого результата и отсутствие возврата исключённых кандидатов.
- Сравниваются полные оставшиеся наборы, а не только выбранные родители. Одинаковый набор после этой пары означает одинаковый результат последующих неизменённых критериев. Поэтому для изоляции перестановки не требуется заново реализовывать производственное родство и лимиты объектов.

Исследовательские скрипты находятся в рабочей папке `data/chain_analysis/order_review/`. Код продукта и опубликованные БД не менялись. Это не полный новый прогон всех дополненных правил; новые общие числа разрешённых неоднозначностей не заявляются.

## Результаты

| Проверка | Результат |
| --- | ---: |
| Базовые технологии | 679 |
| Технологии с несколькими непосредственными пререквизитами | 89 |
| Дошли до сравниваемой пары критериев | 14 |
| Изменился оставшийся набор кандидатов | 1 |
| Набор кандидатов не изменился | 678 |

Единственное изменение:

| Технология | Прямые связи раньше групп | Группы раньше прямых связей |
| --- | --- | --- |
| Джаггернаут (`tech_juggernaut`) | Цитадель (`tech_starbase_5`) | Линкоры (`tech_battleships`) |

В прежнем порядке связь через `capital_yards` и требование Цитадели завершала выбор раньше группы кораблей. В новом порядке группа подвижных боевых кораблей оставляет только Линкоры. Обе связи подтверждаются данными; меняется их приоритет, а игровые требования сохраняются.

Новая опора является непосредственным пререквизитом. В исходном графе требований нет пути от Линкоров назад к Джаггернауту, поэтому новая связь не создаёт родительский цикл. Проверена также ацикличность предыдущего графа выбранных родителей после этой замены. Для остальных технологий одинаковые входы последующих критериев исключают изменение выбора родителя именно из-за перестановки.

## Чувствительность к вариантам

Дополнительно проверены 128 сочетаний семи вариантов, меняющих область или научную категорию. При неизменных свидетельствах открываемых объектов перестановка затронула только Джаггернаут в 64 сочетаниях; в остальных сочетаниях изменений не было.

Это отдельная проверка чувствительности к области и категории. Она не заменяет полный анализ выбранных представлений, `inherit_effects`, условий доступа или других профилей империи. Полную проверку вариантов и раскладки нужно выполнить при реализации соответствующего алгоритма.
