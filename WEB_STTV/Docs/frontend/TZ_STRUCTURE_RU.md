## Статус и границы

Документ фиксирует согласованное разделение фронтенда на каталоги и их ответственность. Технологии определены в [ТЗ технологической основы](TZ_TECH_STACK_RU.md), поведение элементов — в [справочнике UI-элементов](UI_ELEMENTS_RU.md) и связанных ТЗ.

Это проектирование структуры. В текущей итерации создаётся документация; каталоги реализации, код и зависимости ещё не добавляются. Точные имена файлов и программные интерфейсы определяются отдельно; сообщения и управление операциями описаны в [ТЗ протокола Worker](TZ_WORKER_PROTOCOL_RU.md).

## Каталоги кода

Все пути в таблице отсчитываются от `WEB_STTV/src/frontend/`.

| Каталог | Ответственность |
| --- | --- |
| `app/` | Запуск приложения, общее состояние и управление пользовательскими действиями |
| `ui/` | UI-кит с разделением по согласованным категориям элементов |
| `views/` | Сборка экранов из UI-компонентов; на первом этапе — основное окно |
| `data/` | Адаптер БД, подготовка технологий, требований и связей |
| `workers/` | Запуск Worker и обработка сообщений между ним и приложением |
| `localization/` | Поиск строк, обработчики источников, построение индекса и выбор языка при поиске |
| `locales/` | Встроенные интерфейсные строки RU/EN |
| `styles/` | Словарь оформления и общие стили |
| `assets/` | Локальные шрифты и иконки |

`app/` связывает состояние и действия приложения с представлением. `views/` собирает экран, а отдельные UI-компоненты получают данные и обработчики согласно своим ТЗ. Самостоятельная обработка БД находится в модулях данных, а не внутри компонентов.

## Категории UI-кита

Каталоги соответствуют категориям существующего справочника. Категория «Виды» размещается в `views/` рядом с `ui/`.

| Путь относительно `src/frontend/` | Элементы первого этапа |
| --- | --- |
| `ui/base/` | Текст, иконка, кнопка, элемент выбора |
| `ui/composite/` | Выбор языка, переключатель темы, сворачивание меню, карточка технологии, тултип, панель состояния |
| `ui/layout/` | Панель меню, нижняя группа кнопок, рабочая область просмотра, поле технологий, область науки, столбец уровня |
| `ui/scroll/` | Горизонтальная и вертикальная прокрутка по общему ТЗ |
| `views/` | Основное окно |

Категории определяют расположение компонентов, а не повторяют их требования. Справочник UI-элементов остаётся списком со ссылками; требования поддерживаются в отдельных документах.

## Компоненты и стили

Файлы конкретного компонента и его собственные стили хранятся рядом в соответствующей категории. Общие стили и словарь переменных находятся в `styles/`.

Стили компонентов используют переменные [словаря оформления](TZ_STYLING_DICTIONARY_RU.md). Значения цветов и шрифтов по темам и состояниям задаются в словаре, а не независимо в каждом компоненте. Соседство CSS с компонентом не меняет этого правила.

Модули остаются компактными. Повторяемая логика выносится в небольшие вспомогательные модули рядом с функциональностью, которой она принадлежит, с соблюдением общих правил проекта о модульности и размерах файлов.

## Обработка данных и обмен сообщениями

`data/` содержит самостоятельные модули TypeScript для [адаптации БД](TZ_DATABASE_ADAPTER_RU.md), технологий, требований и связей. Они не зависят от React, DOM или конкретного экрана.

`workers/` отвечает за связь с фоновым обработчиком и вызывает модули подготовки данных. Код запуска Worker выполняется со стороны приложения, обработчик сообщений и вызовы обработки — в Worker; расположение в одном каталоге не объединяет эти контексты выполнения.

Полное дерево БД сохраняется в Worker. Приложение получает подготовленные результаты по [правилам открытия БД](TZ_DATABASE_OPENING_RU.md). Алгоритмы подготовки не дублируются в обработчиках сообщений или компонентах.

Построение индекса строк относится к `localization/`; соответствующие независимые модули вызываются при подготовке данных в Worker. Поиск по подготовленному индексу используется интерфейсом. Один каталог может содержать модули для обоих контекстов; React не становится зависимостью обработки локализации в Worker.

## Локализация и ресурсы

`localization/` содержит механизм работы со строками; `locales/` — сами встроенные переводы. Файлы `locales/ru.json` и `locales/en.json` из [ТЗ локализации](TZ_LOCALIZATION_RU.md) располагаются относительно `src/frontend/`. Названия и описания технологий поступают из открытой БД согласно тому же ТЗ.

`assets/` хранит локальные ресурсы интерфейса: шрифты и иконки. Inter поставляется с необходимыми лицензионными материалами по ТЗ оформления. Конкретные файлы шрифта и способ их подключения определяются отдельно.

Выбор языка хранится в состоянии приложения; механизм локализации получает его для поиска строки и не создаёт независимую копию общей настройки.

## Конфигурация и рабочие данные

Конфиги фронтенда размещаются в `WEB_STTV/config/frontend/`, отдельно от исходного кода. Это также корневой каталог для будущего конфига источников локализации. Конкретные файлы, схемы и способы подключения настроек определяются при проектировании соответствующих модулей и сборки.

Конфигурация диагностики в этом каталоге задаёт соответствие «код → ID встроенной строки» по [ТЗ диагностики](TZ_DIAGNOSTICS_RU.md#сообщение-интерфейса). Тексты находятся в `src/frontend/locales/ru.json` и `src/frontend/locales/en.json`; конфигурация содержит соответствие идентификаторов и не дублирует переводы. Точное имя файла и способ загрузки ещё предстоит определить.

Словарь цветов и шрифтов остаётся CSS в `src/frontend/styles/`, как предусмотрено его ТЗ. Встроенные переводы и ресурсы находятся в собственных каталогах фронтенда; они не переносятся в каталог конфигурации.

`src/frontend/data/` содержит только код обработки. Рабочая папка проекта `WEB_STTV/data/`, настраиваемая через `WORK_DIR`, используется для БД, отчётов и проверок. Фронтенд открывает выбранный пользователем готовый файл; наличие рабочей папки не означает автоматической загрузки или генерации БД. [Диагностический отчёт фронтенда](TZ_DIAGNOSTIC_REPORT_RU.md) сохраняется пользователем по явному действию меню; `WORK_DIR` не задаёт автоматическую запись этой выгрузки в рабочую папку.

## Критерии приёмки

Проверки выполняются после реализации:

1. Код, конфигурация и ресурсы размещены по ответственности, указанной в таблицах.
2. Экран собирается из UI-кита; элементы распределены по категориям справочника.
3. Стили компонентов находятся рядом с компонентами и используют общий словарь цветов и шрифтов.
4. Обработка данных проверяется независимо от React и DOM; Worker использует эти модули без дублирования алгоритмов.
5. Механизм локализации отделён от встроенных переводов и общей настройки языка.
6. Рабочая БД и отчёты не помещаются в каталог кода `src/frontend/data/`.
