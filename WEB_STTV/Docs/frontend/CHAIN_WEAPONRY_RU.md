## Статус и назначение

Согласовано 2026-11-19. Документ добавляет группу «Вооружение против кораблей» к [критерию функциональных групп](CHAIN_FUNCTIONAL_GROUPS_RU.md). Это правило для проектирования выбора родителя; его реализация в продукте потребует отдельного ТЗ. В этой итерации выполнены исследовательская проверка и обновление документации.

Положение критерия сохраняется: после прямых улучшений и совпадения условий доступности, перед прямыми функциональными связями, фильтром империи и старшинством.

## Основания принадлежности

Достаточно одного из двух подтверждённых оснований:

1. Технология открывает оружейный компонент. Проверенная форма в текущей БД — объект типа `weapon_component_template`.
2. Технология открывает объект с доступным пользователю действием, которое через явно связанные события наносит урон кораблям. Для текущего случая связь заканчивается эффектом `damage_ship`.

Связь технологии с объектом берётся из игровых требований. Сохраняются условия, альтернативы и источники; упоминание под отрицанием не становится положительной разблокировкой. Принадлежность означает наличие такой возможности при соответствующих условиях, а не гарантированное применение или текущую доступность конкретной империи.

Описание группы, допустимые типы объектов и маршруты по полям выносятся в конфигурацию. Названия, текст описаний, сходство ID, стоимость в энергии и веса ИИ не заменяют функциональное свидетельство. Пары технологий для этой группы вручную не задаются.

## Связи действия и события

Для исследованного маршрута:

| Переход | Поле и смысл |
| --- | --- |
| Открываемый объект → действие | `scripted_action` содержит ID действия из БД `scripted_actions`. |
| Действие → обработчик | `on_completed` ссылается на определение в БД `on_actions`. |
| Обработчик → событие | `events` содержит ID события; событие из БД `events` находится по собственному полю `id`. |
| Событие → эффект | В `immediate` исследуются эффекты, включая уже раскрытые вызовы скриптовых эффектов; подтверждением служит `damage_ship`. |

Сохраняются весь путь, источники и окружающие условия действия и эффекта. Аргументы `amount`, `attacker` и области видимости не вычисляются по вымышленному игровому состоянию. В Звёздной пушке величина урона зависит от переменных, а разные ветви события обрабатывают цели по-разному.

Упоминание `damage_ship` в произвольном событии без подтверждённого пути от открываемого объекта не присваивает группу технологии. Не считается свидетельством и текстовое упоминание в локализации. Число найденных вызовов урона не увеличивает вес кандидата.

Это обход связей между объектами и событиями. Он не меняет глубину [косвенного родства через технологические пререквизиты](CHAIN_INDIRECT_AFFINITY_RU.md) и не требует повторного раскрытия скриптовых эффектов: в проверенной БД они уже раскрыты внутри события. Другие маршруты должны описываться явно; универсальный обход любых ссылок здесь не вводится.

## Отбор кандидатов

Новая группа объединяется с остальными подтверждёнными группами технологии. Затем применяется общий критерий: оставить текущих кандидатов, имеющих хотя бы одну общую группу. Если совпадений нет — сохранить прежний набор; если остался один кандидат — завершить выбор. Число совпавших групп и объектов не используется как голосование.

Ранее исключённые кандидаты не возвращаются. Игровые пререквизиты, их логика и уровни сохраняются; меняется только аналитическая опора для размещения.

## Звёздная пушка

| Технология | Игровой уровень | Подтверждение группы |
| --- | ---: | --- |
| Звёздная пушка (`tech_dyson_gun`) | 3 | Мегасооружение → действие → событие → нанесение урона кораблям. |
| УФ-лазеры (`tech_lasers_3`) | 2 | Открывает оружейные компоненты, например `SMALL_UV_LASER`. |
| Стабилизация червоточин (`tech_wormhole_stabilization`) | 3 | По проверенным маршрутам принадлежность не подтверждена. |

Подтверждённая цепочка свидетельств: `dyson_gun_1` → `dyson_shoot` → `on_dyson_shoot` → `nomads.8000` → `damage_ship`. Раскрытие включает скриптовые эффекты выстрела и его условные ветви.

Результат: **УФ-лазеры → Звёздная пушка**, то есть `tech_dyson_gun.parent_tech = tech_lasers_3`. Критерий уровня уже не применяется. Стабилизация червоточин остаётся обязательным игровым требованием.

## Проверка влияния

Изолированное сравнение выполнено 2026-11-19 на опубликованном наборе `8d7f30af6cc5a9504e6fbb0e2126edae8d18fe9a159f9969e574926ca62b5f01`. Сравнивались функциональные группы до и после добавления вооружения при одинаковых первых шести критериях и неизменном дальнейшем порядке. Старые группы подвижных боевых кораблей и изменения класса планеты включены в обе стороны сравнения.

| Показатель | Результат |
| --- | ---: |
| Базовые технологии | 679 |
| Имеют несколько непосредственных пререквизитов | 89 |
| Доходят до критерия функциональных групп с несколькими кандидатами | 14 |
| Получили новую группу по проверенным формам | 113 |
| Изменился набор кандидатов после критерия | 1 |
| Набор кандидатов после критерия не изменился | 678 |

Единственное изменение — Звёздная пушка: ранее после групп оставались оба кандидата, теперь остаются УФ-лазеры. Следующие критерии не могут заменить единственного кандидата. У остальных технологий равные выходные наборы означают одинаковый результат неизменных последующих критериев.

Мегапроектирование также получает группу: оно входит в требования старших или восстановленного варианта пушки. Однако ни один оставшийся кандидат Мегапроектирования не разделяет эту группу; пустой результат пропускается. Отбор продолжает работать по остальным критериям, включая согласованное родство через вместимость звёздных баз.

Проверены размеры и SHA-256 используемых БД относительно исследовательских проекций, принадлежность одному набору, остановка при единственном кандидате, пропуск пустого результата и отсутствие возврата исключённых кандидатов. Новый родитель — исходный непосредственный пререквизит. По исходному графу требований у него нет пути обратно к Звёздной пушке, поэтому новая связь не создаёт цикл.

Артефакты: [сравнение всех технологий](../../data/chain_analysis/weapon_review/report.json), [свидетельства и раскрытое тело связанного события](../../data/chain_analysis/weapon_review/evidence.json), [исследовательский расчёт](../../data/chain_analysis/weapon_review/compare.py). Для событий сохранены идентификатор набора, размер и SHA-256 фактически прочитанного файла; огромная БД не загружалась целиком в объект Python.

## Границы проверки

- Рассмотрены базовые представления технологий; переключение вариантов, наследование их эффектов и другие профили империи отдельно не проверялись.
- Проверялись оружейные компоненты и явный маршрут через `scripted_action`, `on_completed`, `events`, `immediate`. Произвольные вызовы между событиями и другие формы выдачи действий не обходились.
- Для маршрутов действий просмотрены БД компонентов, зданий, корпусов, звёздных модулей, звёздных зданий и мегасооружений. Четыре объекта с подтверждённой технологической разблокировкой ведут к одному событию выстрела. Объекты без такой связи не приписывались технологиям автоматически.
- Условия исполнения и величины динамического урона не вычислялись. Сохранение условного свидетельства не доказывает, что каждый запуск события нанесёт урон.
- Это проверка влияния одной группы; итоговые числа на её этапе не пересчитывались. Последующий [общий прогон всех согласованных критериев](CHAIN_RULES_FULL_REVIEW_RU.md) оформлен отдельно и подтверждает родителя Звёздной пушки.
- Продуктовый код, опубликованные БД и размещение карточек не менялись; отрисовка дерева не проверялась.
