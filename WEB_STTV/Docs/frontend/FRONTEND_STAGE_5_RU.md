## Запуск и комбинация

Реализовано [ТЗ этапа 5](TZ_FRONTEND_STAGE_5_RU.md). Запуск из `WEB_STTV`: `npm run dev`, затем открыть `http://127.0.0.1:5173/`. На текущем компьютере:

```powershell
$env:PATH="$PWD/data/frontend-tools/node-v24.22.3-win-x64;$env:PATH"
$env:npm_config_cache="$PWD/data/npm-cache"
npm run dev
```

Через «Открыть набор БД» выбрать **`data/stage17/database_set`** — каталог с `manifest.json`. Существующий набор подходит, пересборка не нужна. Старт и обновление страницы ничего не открывают и не запускают генератор.

`config/frontend/tree_layout.json` задаёт `combination_id`, по умолчанию `reference_default`. Другая готовая комбинация контрольного набора — `reference_variants`. После изменения конфига открыть набор заново; production-сборку предварительно пересобрать командой `npm run build`. Ручного выбора вариантов или комбинаций в меню на этом этапе нет. Карточки используют полный выбор `parameters.variants` сохранённой комбинации.

## Размещение

Поле разделено на физику, социологию и инженерию. Внутри области размещаются целые деревья: сначала со стартовым корнем, затем остальные, по отображаемому названию на выбранном языке. Стартовый потомок остаётся в своей ветви. Одинаковые названия разрешаются сравнением базовых ID.

Продолжение с совпадающим ID после удаления цифр располагается первым; затем идут остальные дети по названию. Родитель и первый ребёнок разных уровней делят строку, если клетка свободна. Ребёнок того же уровня располагается ниже. При обратном переходе занятая клетка сдвигает только соответствующую дочернюю ветвь. Ветви и целые деревья не заполняют пустоты предыдущих ветвей.

Столбец сохраняет игровой уровень. Исключение отображения: `levels = -1`, `tier = 5` и наличие технологического пререквизита дают столбец 6. Игровое значение в данных не меняется. Межобластной родитель сохраняется в данных, а для размещения его ребёнок становится отдельным началом в своей области. Дополнительные требования не задают вертикальных ограничений.

Смена языка пересчитывает порядок и координаты по загруженным данным. Тема, меню и тултипы координаты не меняют. Прокрутка ограничивается новыми размерами поля. Карточки доступны клавиатурному фокусу в порядке обхода деревьев; при фокусе также показывается тултип. Название и описание берутся из выбранного представления. Совпадающие названия вариантов используют локализованный суффикс «Вариант N».

## Модули и отчёт

| Модуль | Назначение |
| --- | --- |
| `data/tree/metadata.ts`, `extraction.ts` | Выбор метаданных комбинации и извлечение записи технологии |
| `data/tree/validation.ts` | Варианты, взаимные ссылки и циклы, включая межобластные |
| `data/tree/forest.ts`, `comparison.ts` | Локальные деревья, уровень отображения и порядок |
| `data/tree/placement.ts`, `layout.ts` | Итеративный обход, строки, геометрия и диагностика |
| `localization/sources.ts` | Общий механизм поиска строк для карточки и сортировки |
| `app/field.ts`, `ui/layout/TechnologyField.tsx` | Подготовка поля, обработка ошибок и CSS Grid |

Старый независимый `sttvOrderColumn` удалён. Родители во фронтенде не пересчитываются. Размещаются компактные объекты, полный AST не передаётся в основной поток. При открытии читаются только 35 документов технологий; 14 остальных видов остаются незагруженными. Метаданные комбинации сравниваются с `set_id` и `source_revision` манифеста без чтения этих видов.

Отчёт фронтенда версии 4 включает `tree`: комбинацию, полный выбор вариантов, входные и итоговые ревизии, язык, настройки, размеры, количество карточек/деревьев/строк по областям, число скрытых межобластных связей и время геометрии. `treeCombination` сохраняет выбранные метаданные также при ошибке подготовки поля. Проверка входных ревизий не объявляется повторным аудитом всех БД.

Отсутствующая/неподдерживаемая комбинация, устаревшие входы, неполное обогащение и ошибка размещения имеют разные сообщения RU/EN. `ambiguous` сохраняет карточку отдельным деревом и предупреждение в отчёте с `NodeRef`, параметрами и настройками поля. Подробная трасса выбора родителей остаётся на бэкенде.

## Проверки и замеры

Пройдены TypeScript, production-сборка и 49 синтетических тестов. Отдельная проверка реального набора прошла для `reference_default` и `reference_variants` на RU/EN: 679 карточек ровно по одному разу, без наложений; сохранены исходные родители, дети и игровые уровни. Проверены лазеры, пять мутаций, переход корабля-ковчега, добыча тёмной материи и физические шифрование/дешифрование с социологическим родителем. Идентичные повторы `start_tech = yes` у трёх технологий допускаются; противоречащие значения проверяются отдельным отрицательным сценарием.

| Комбинация | Физика: карточки / деревья | Социология | Инженерия | Межобластные связи |
| --- | --- | --- | --- | --- |
| `reference_default` | 168 / 62 | 312 / 98 | 199 / 55 | 37 |
| `reference_variants` | 168 / 62 | 319 / 97 | 192 / 57 | 38 |

В обеих комбинациях сохранены 178 корней и 501 выбранный родитель. Количество локальных деревьев отличается от числа сохранённых корней. Переключение языка не вызывает повторного чтения; документы и манифест не изменились.

В Chromium 159.0.8154.6 прошли 16 браузерных сценариев, включая обе комбинации, ошибки входа, сохранение отчёта, отмену, меню, язык, темы, прокрутку, тултипы, координаты и порядок фокуса. Один независимый тест потокового чтения большого нетехнологического документа пропущен: читатель в этом этапе не менялся. Полная подгрузка всех 15 БД не повторялась. Вторая комбинация проверена подменой значения загружаемого конфигурационного модуля в тесте, без правок БД.

Визуально проверены RU/EN в дневной и ночной темах. На текущем компьютере браузерное открытие заняло **5,786 с**, чтение технологических документов — **4,782 с**; прочитано **129 571 596 байт**, проверено 35 из 450 документов, 415 не прочитаны. Начальная геометрия RU — **21,1 мс**, последующая EN — **4,2 мс**. Отдельный загрузчик Node.js: 3,711 с и 4,347 с для двух комбинаций; геометрия 4–6 мс. Это единичные замеры без очистки кэша ОС; полная память браузера/Worker и время полного аудита здесь не измерялись. Управление меню, отменой и переключением языка проверено браузерными сценариями.

Рабочие результаты: `data/frontend-stage5/real-layout.json`, `browser-real-set.json`, `real-ru-night.png`, `real-ru-day.png`, `real-en-day.png`, `real-en-night.png`, `real-tooltip.png`. Журнал браузерных сценариев — `data/frontend-tests/browser-report.json`.

## Ограничения и проверка пользователем

Линии связей, интерактивная смена вариантов с пересчётом бэкенда, отметки событийных/нулевого веса технологий и постоянные координаты не добавлены. Файлы БД и правила выбора родителей не меняются. Поле намеренно сохраняет пустоты ветвей; из-за этого оно выше прежнего независимого списка столбцов.

Пользователю остаётся оценить удобство ветвей и прокрутки на реальном поле. Для приёмки этого этапа запуск Stellaris не требуется.
