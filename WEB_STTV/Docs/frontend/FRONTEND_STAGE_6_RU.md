## Результат

Реализовано утверждённое [ТЗ этапа 6](TZ_FRONTEND_STAGE_6_RU.md): связи выбранного `parent_tech` с детьми внутри области науки, стрелки, общие стволы и точки разветвления. При наведении на карточку путь к родителю подсвечивается синим, пути к непосредственным детям — оранжевым. Соседние ответвления сохраняют обычный цвет; уход указателя снимает подсветку.

Логические строки, уровни и порядок деревьев этапа 5 сохранены. Промежутки расширяются при необходимости для непересекающихся маршрутов. Цвета зависят от темы. Наведение меняет оформление уже рассчитанных отрезков, не вызывает раскладку и не читает БД.

## Запуск и комбинация

Из `WEB_STTV` с Node.js 24: `npm run dev`, затем открыть `http://127.0.0.1:5173/`. Зависимости при первой подготовке устанавливаются через `npm ci`.

Для подготовленного в этом репозитории Node.js:

```powershell
$env:PATH="$PWD/data/frontend-tools/node-v24.22.3-win-x64;$env:PATH"
npm run dev
```

Через «Открыть набор БД» выбрать **`data/stage17/database_set`** с `manifest.json`. Существующая БД подходит; пересборка не требуется. Открытие и обновление страницы не запускают генератор.

`config/frontend/tree_layout.json` выбирает `reference_default` или `reference_variants`. После изменения `combination_id` заново открыть набор. Ручной переключатель вариантов и вызов Python по-прежнему отложены.

## Прокладка и отображение

Чистые функции в `src/frontend/data/connections/` выполняют последовательность:

1. Получают локальные деревья и логические места карточек этапа 5.
2. Выбирают стороны крепления с учётом входящей линии родителя. При занятой боковой точке используют нижний выход.
3. Ищут ортогональный маршрут алгоритмом A* в промежутках. Карточки и линии другого родителя блокируют путь; собственный ствол предпочтителен. Число уточнений сетки и посещённых состояний ограничено.
4. Переводят маршруты и карточки в пиксели. Каждый промежуток имеет собственную ширину; столбцы общие для областей. Независимые деревья переиспользуют горизонтальные полосы, не суммируя их ширину.
5. Делят общие участки на уникальные отрезки со списком дочерних маршрутов. Один отрезок рисуется один раз.
6. Проверяют покрытие родительских пар, конечные точки, ортогональность, отсутствие проходов через карточки и пересечений разных родителей.

| Модули | Назначение |
| --- | --- |
| `routing.ts`, `grid.ts`, `search.ts`, `heap.ts` | Крепления, свободные промежутки и поиск |
| `axis.ts`, `layout.ts` | Размеры промежутков, общие столбцы и итоговая геометрия |
| `segments.ts`, `points.ts`, `validation.ts` | Общие стволы, геометрические операции и проверка |
| `ui/base/Connection.tsx` | Отрезок и стрелка UI-кита |
| `ui/layout/Connections.tsx` | SVG-слой, точки разветвлений и роли подсветки |
| `ui/layout/TechnologyField.tsx` | Единые координаты карточек, заголовков и слоя связей |

SVG не перехватывает указатель и скрыт от дерева доступности. Порядок карточек в DOM и клавиатурный обход сохранены. Клавиатурный фокус сам по себе не подсвечивает линии.

## Конфигурация и оформление

`config/frontend/connections.json` задаёт параметры прокладки и геометрии:

| Параметр | Значение | Назначение |
| --- | --- | --- |
| `cardClearance` | 6 | Минимальный отступ полосы маршрута от карточки, px |
| `laneSpacing` | 6 | Расстояние между полосами, px |
| `exitLength` | 6 | Минимальное пространство для выхода, px |
| `strokeWidth` | 1.5 | Толщина линии, px |
| `arrowSize` | 6 | Длина стрелки, px |
| `junctionRadius` | 2 | Радиус точки разветвления, px |
| `bendPenalty` | 0.4 | Штраф поворота в поиске |
| `sharedPathCost` | 0.1 | Множитель стоимости собственного ствола |
| `maxRefinements` | 2 | Дополнительные попытки с уточнением промежутков |
| `maxSearchStates` | 1000000 | Предел обработки состояний одной попытки |

Минимальные обычные промежутки и размеры карточек остаются в `config/frontend/interface.json`. Числовая толщина из конфига передаётся CSS через `--sttv-connection-stroke-width`.

`styles/elements.css` связывает `--sttv-connection-color-default`, `--sttv-connection-color-parent`, `--sttv-connection-color-children` со словарём `styles/dictionary.css`.

| Тема | Обычная линия | Родитель | Дети |
| --- | --- | --- | --- |
| Ночная | `--sttv-border` | `#73BFFF` | `#F2B366` |
| Дневная | `--sttv-border` | `#1768A6` | `#9B4F0B` |

## Диагностика

Экспортируемый отчёт содержит `tree.connections`: настройки, количество логических связей, отрезков и точек, итоговые промежутки и время подготовки. Логическая связь и отрезок общего ствола учитываются раздельно.

Ошибка прокладки `tree_connections_failed` не публикует частичное успешное поле. Сообщение локализовано; подробности отчёта содержат причину, комбинацию, язык, настройки, а для невозможного пути — родителя, ребёнка, крепления и места карточек. Алгоритм ограничен числом попыток; ошибка не доказывает математическую невозможность иной прокладки.

Проверены RU/EN, обе темы, подсветка и тултипы, прокрутка, размер окна, сворачивание меню, привязка стрелок и экспорт ошибки. ## Ограничения и проверка пользователем

Дополнительные пререквизиты и межобластные связи остаются в данных без линий. Родители и варианты не пересчитываются, БД не изменяется, геометрия между запусками не сохраняется.

Stellaris запускать не требуется. Пользователю остаётся оценить читаемость плотных ветвей, удобство расширенных промежутков и различимость двух цветов подсветки на своём экране.
