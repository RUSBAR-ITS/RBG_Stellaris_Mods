## Статус и границы

Документ фиксирует согласованный выбор React, TypeScript, Vite и обычного CSS для первого интерфейса. Он дополняет требования к UI-элементам и [открытию готовой БД](TZ_DATABASE_OPENING_RU.md). Реализация интерфейса и установка зависимостей в рамках этой итерации документации не выполняются.

Сохраняются ранее согласованные границы: Python отдельно создаёт и обогащает БД; пользователь явно открывает готовый JSON в браузере. Первый интерфейс проверяется из среды разработки, portable-поставка относится к последующим этапам.

## Выбранные инструменты

| Инструмент | Ответственность |
| --- | --- |
| TypeScript | Типы, обработка БД, локализация, взаимодействие с Worker и логика интерфейса |
| React | Компоненты UI-кита, сборка экрана и обновление представления при изменениях состояния |
| HTML и обычный CSS | Разметка, раскладка, размеры, оформление и темы |
| Vite | Среда локальной разработки и сборка файлов фронтенда |
| Web Worker | Выполнение чтения и подготовки выбранной БД вне основного потока интерфейса |

Для состояния первого интерфейса используются встроенные средства React. Дополнительная библиотека управления состоянием не требуется согласованным объёмом работы.

## Компоненты интерфейса

UI-кит строится из самостоятельных React-компонентов по [списку элементов](UI_ELEMENTS_RU.md) и их индивидуальным ТЗ. Составные компоненты собираются из базовых элементов; экран собирается из этих компонентов.

Компонент получает явно описанные входные параметры и сообщает о действиях через обработчики. Например, карточка получает представление технологии и сообщает о выборе другого варианта; выбор языка получает текущее значение и сообщает о его изменении.

Оформление использует обычный CSS и переменные [словаря цветов и шрифтов](TZ_STYLING_DICTIONARY_RU.md). Локализованный текст получается через общий механизм [поиска строк](TZ_LOCALIZATION_RU.md).

## Состояние приложения

Встроенные средства React управляют языком, темой, раскрытием меню, состоянием открытия БД и выбранными представлениями технологий. Распределение состояния между приложением и отдельными компонентами уточняется при проектировании модулей; общее состояние не дублируется независимо в нескольких компонентах.

Правила переходов при открытии, отмене, повторе и замене БД определены отдельным ТЗ. Изменение языка или темы обновляет отображение через состояние приложения.

Этот выбор относится к состоянию текущего запуска. Постоянное хранение и восстановление между запусками требуют отдельного проектирования.

## Обработка данных и Worker

[Адаптер БД](TZ_DATABASE_ADAPTER_RU.md), подготовка требований и связей, построение индекса локализации реализуются самостоятельными модулями TypeScript. Эти модули не зависят от React, DOM или конкретного компонента и могут проверяться отдельно от интерфейса.

Worker вызывает модули обработки и возвращает подготовленные результаты основному потоку по [ТЗ протокола](TZ_WORKER_PROTOCOL_RU.md). Полное дерево БД остаётся в Worker. React отображает полученные данные и состояние операции; разбор полного JSON не переносится в основной поток.

Просмотр готового файла не требует Python-службы. Запуск среды разработки, страницы или её обновление не запускает создание либо обогащение БД.

## Разработка и сборка

Vite запускает локальную среду разработки, обслуживает файлы интерфейса и обновляет их в браузере при изменениях исходников. Его сборка подготавливает файлы приложения для дальнейшей поставки. Конкретная portable-упаковка проектируется отдельно.

Проверка типов TypeScript выполняется отдельной командой и включается в проверки проекта: преобразование TypeScript средствами Vite само по себе не проверяет типы. Для такой проверки используется компилятор TypeScript, например `tsc --noEmit`.

Точные версии инструментов, конфигурации и команды проекта фиксируются при подготовке реализации. Сборка интерфейса не должна зависеть от выбранной пользователем игровой БД.

## Критерии приёмки

Проверки выполняются после реализации:

1. Среда Vite запускает интерфейс и обновляет изменённые компоненты в браузере.
2. Отдельная проверка TypeScript проходит для кода интерфейса, обработки данных и взаимодействия с Worker.
3. Сборка Vite успешно подготавливает фронтенд и используемый им Worker.
4. UI-элементы собраны из React-компонентов с типизированными входными параметрами и обработчиками действий.
5. Модули обработки данных проверяются без запуска React и доступа к DOM.
6. Открытие готовой БД, смена языка и темы выполняются по соответствующим ТЗ; запуск и обновление страницы не вызывают генератор БД.
