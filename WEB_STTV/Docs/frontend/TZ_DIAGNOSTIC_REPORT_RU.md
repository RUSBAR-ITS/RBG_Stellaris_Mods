## Статус и границы

Документ фиксирует согласованное пользователем 2026-11-17 сохранение JSON-отчёта о текущей попытке открытия БД. На первом этапе подробности просматриваются во внешнем редакторе, например VS Code; встроенное окно диагностики отложено.

Основа — [ТЗ диагностики](TZ_DIAGNOSTICS_RU.md), [открытия БД](TZ_DATABASE_OPENING_RU.md) и [панели меню](elements/TZ_MENU_PANEL_RU.md). Это пользовательская выгрузка сведений, уже имеющихся в основном потоке. В этой итерации оформляется документация; код, БД и отчёты бэкэнда не изменяются.

## Действие в меню

В основной группе действий с БД над выбором языка добавляется «Сохранить отчёт» / “Save report”. Оно использует общий [элемент «Кнопка»](elements/TZ_BUTTON_RU.md), встроенные строки RU/EN и оформление UI-кита.

Кнопка расположена рядом с действиями открытия БД в существующей группе. Как и остальные действия этой группы, она скрывается при сворачивании меню. Панель состояния продолжает показывать одно короткое сообщение о работе с БД; кнопка сохранения и технические подробности в неё не добавляются.

Самостоятельный UI-элемент для действия и встроенное окно просмотра на этом этапе не создаются.

## Доступность по состояниям

| Состояние приложения | «Сохранить отчёт» |
| --- | --- |
| БД не открыта | Недоступно |
| Загрузка | Недоступно |
| Готово | Доступно |
| Пустой каталог | Доступно |
| Ошибка | Доступно |

Согласно существующему правилу меню показываются только действия текущего состояния: до открытия и во время загрузки кнопка сохранения скрыта. После завершения попытки она показывается, даже если предупреждений нет. Сбой запуска Worker также даёт завершённую попытку с результатом ошибки и допускает сохранение.

Отчёт относится к текущей попытке и её `operationId`. Начало новой попытки снова переводит приложение в загрузку и делает сохранение недоступным. Отмена загрузки возвращает состояние «БД не открыта»; отчёт об отмене не вводится. Отмена диалога выбора нового файла сохраняет текущий результат и доступность его отчёта по ТЗ открытия БД.

## Структура отчёта

Отчёт — отдельный JSON-объект с восемью обязательными полями:

| Поле | Тип и назначение |
| --- | --- |
| `format` | Строковый идентификатор `sttv.frontend_diagnostics` |
| `formatVersion` | Целое число `1` для первой версии структуры отчёта |
| `exportedAt` | Строка даты и времени сохранения в UTC, формат ISO 8601 с суффиксом `Z` |
| `operationId` | Положительное целое число: номер текущей завершённой попытки |
| `file` | Объект с именем и размером выбранного файла БД |
| `result` | `ready`, `empty` или `error` |
| `error` | Блокирующая диагностическая запись либо `null` |
| `diagnostics` | Массив предупреждений |

`file` содержит два поля: `name` — строковое имя выбранного файла, `size` — его размер в байтах, неотрицательное целое число. Эти сведения доступны из выбранного файла и сохраняются с попыткой; повторное чтение содержимого для их получения не требуется.

`formatVersion` версионирует структуру данного отчёта, а не БД или приложение. `exportedAt` обозначает время формирования выгрузки, а не время завершения обработки БД.

Условный пример успешной попытки с пустым каталогом:

```json
{
  "format": "sttv.frontend_diagnostics",
  "formatVersion": 1,
  "exportedAt": "2026-11-17T10:30:00Z",
  "operationId": 7,
  "file": {
    "name": "database.json",
    "size": 1024
  },
  "result": "empty",
  "error": null,
  "diagnostics": []
}
```

## Результат и диагностика

| `result` | Источник результата | `error` | `diagnostics` |
| --- | --- | --- | --- |
| `ready` | Успешная подготовка непустого каталога | `null` | Предупреждения из `ready.data.diagnostics` |
| `empty` | Успешная подготовка пустого каталога | `null` | Предупреждения из `ready.data.diagnostics` |
| `error` | Ошибка открытия или сбой Worker | Запись причины остановки с `severity: "error"` | Накопленные предупреждения |

Пустой каталог в протоколе Worker по-прежнему возвращается сообщением `ready`; значение `empty` в отчёте отражает итоговое состояние приложения и не добавляет новый тип сообщения Worker.

Каждая запись `error` или `diagnostics` сохраняет согласованные `severity`, `code`, `phase`, `params`, `details`. Массив содержит только предупреждения, блокирующая причина в нём не дублируется. Если предупреждений нет, сохраняется `[]`.

Коды, параметры и технические подробности выгружаются в исходной структуре диагностики, без подмены локализованными сообщениями панели. Язык интерфейса не меняет их содержимое. Повторное сохранение той же попытки использует тот же результат и новый момент `exportedAt`.

## Формирование и просмотр

Сохранение выполняется только по явному действию пользователя. Отчёт собирается из уже имеющихся сведений основного потока о текущей завершённой попытке. Новая попытка открытия, повторное чтение БД, обход дерева и обращение к Worker для получения диагностических записей не требуются.

Полная БД, исходная JSON-строка, каталог технологий, связи и индекс локализации в отчёт не включаются. Технические сведения, предусмотренные `details`, сохраняются по ТЗ диагностики.

Пользователь получает отдельный JSON-файл и открывает его в удобном редакторе для ручного разбора. Сохранение не изменяет выбранную БД, результат её открытия и состояние просмотра технологий. Рабочий каталог `WORK_DIR` не означает автоматическую запись этого отчёта в папку продукта.

Автоматическое ведение файлового журнала, история попыток и постоянное хранение состояния не вводятся. Встроенное окно просмотра диагностики относится к последующему этапу.

## Критерии приёмки

Проверки выполняются после реализации:

1. «Сохранить отчёт» использует общую кнопку в группе действий меню, получает подпись из RU/EN и скрывается вместе с меню.
2. Действие доступно в состояниях «Готово», «Пустой каталог», «Ошибка»; до открытия и во время загрузки оно недоступно и скрыто.
3. Успешная попытка без предупреждений также сохраняется с `error: null` и `diagnostics: []`.
4. JSON содержит все восемь полей, сведения о выбранном файле и текущей попытке; `exportedAt` соответствует моменту сохранения в UTC.
5. Успешный пустой каталог получает `result: "empty"`, не изменяя протокол Worker; ошибка содержит блокирующую запись отдельно от предупреждений.
6. Сохранённая после ошибки диагностика доступна для выгрузки после завершения Worker, включая сбой его запуска.
7. Переключение RU/EN не меняет коды, параметры и технические подробности; повторная выгрузка сохраняет результат той же попытки.
8. Сохранение использует готовые сведения основного потока без чтения БД или Worker-запроса; полная БД не включается и не изменяется.
9. Начало новой попытки и отмена загрузки делают сохранение недоступным; отмена диалога выбора файла сохраняет текущий отчёт. Автоматического журнала и истории нет.

## Дальнейшее проектирование

Конкретный механизм выгрузки файла, правило его имени, идентификаторы интерфейсных строк и обработка ошибок самой выгрузки уточняются при проектировании реализации. Состав `details`, использование `origins` для конфликтов и пустой `params` текущих кодов закреплены ТЗ диагностики; программные типы подробностей уточняются в его рамках. Встроенный просмотр, история и автоматическое сохранение требуют отдельных решений.
