## Статус и границы

Документ фиксирует согласованное поведение запуска интерфейса и открытия существующей БД. Фронтенд использует готовый JSON с результатами парсинга и локализацией. Создание и обновление БД остаются отдельными процессами бэкэнда.

Для первого этапа согласовано чтение выбранного файла в браузере через File API и выполнение адаптера на TypeScript в Web Worker. Python используется отдельными процессами создания и обогащения БД; просмотр готового файла не требует запуска Python-службы. React, TypeScript и Vite закреплены в [ТЗ технологической основы](TZ_TECH_STACK_RU.md); точные программные интерфейсы предстоит определить.

## Запуск и обновление страницы

Запуск приложения и обновление страницы загружают интерфейс и его собственные ресурсы. Они не открывают БД автоматически, не читают игровые источники и не запускают генерацию или обогащение БД.

До явного открытия файла [панель состояния](elements/TZ_STATUS_PANEL_RU.md) предлагает пользователю открыть БД через меню; рабочая область остаётся свободной. Начальные язык, тема и состояние меню определяются [ТЗ основного окна](elements/TZ_MAIN_WINDOW_RU.md). Наличие файла БД на диске само по себе не запускает его загрузку.

На первом этапе после обновления страницы пользователь снова явно открывает готовую БД. Автоматическое восстановление открытого файла не вводится; общий механизм сохранения состояния проектируется отдельно.

## Явное открытие БД

Предусматривается действие **«Открыть БД» / «Open database»**:

1. Пользователь вызывает действие открытия.
2. Пользователь выбирает существующий JSON-файл БД.
3. Приложение читает выбранный файл и подготавливает данные для отображения.
4. После успешной подготовки в рабочей области появляется поле технологий.

До выбора файла загрузка его содержимого не выполняется. Открытие использует готовую БД в режиме чтения и не изменяет выбранный файл.

Действие использует общий [элемент «Кнопка»](elements/TZ_BUTTON_RU.md) и располагается в основном содержимом [панели меню](elements/TZ_MENU_PANEL_RU.md), в группе действий с БД над выбором языка. Его подпись и предложение открыть БД в панели состояния берутся из встроенной локализации. Кнопка вызывает стандартный диалог выбора файла браузера. Точные размеры, отступы и идентификаторы интерфейсных строк определяются при проектировании реализации.

## Чтение файла и Web Worker

Браузер получает выбранный пользователем объект `File` через File API. Основной поток передаёт его Web Worker сообщением; чтение содержимого и разбор JSON выполняются в Worker. Возможность доступа к выбранному файлу описана в [документации File API](https://developer.mozilla.org/en-US/docs/Web/API/File_API/Using_files_from_web_applications), отдельный поток и обмен сообщениями — в [документации Web Workers](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Using_web_workers).

Последовательность обработки:

1. Основной поток получает выбранный файл и отправляет его Worker.
2. Worker читает содержимое, разбирает JSON и проверяет поддерживаемые формат и версию БД.
3. Worker подготавливает каталог технологий и вариантов, технологические требования и связи, индекс локализации RU/EN.
4. Worker отправляет подготовленные данные основному потоку для построения интерфейса.

| Часть | Ответственность |
| --- | --- |
| Основной поток браузера | Выбор файла, получение подготовленных данных, размещение и отображение элементов, действия пользователя |
| Web Worker | Чтение файла, разбор JSON, проверка формата и версии, вызов модулей подготовки данных, хранение полного дерева БД |
| Модули TypeScript | Извлечение технологий, обработка требований и чтение сохранённой локализации по отдельным ТЗ |

Чтение файла и обмен сообщениями составляют внешнюю обвязку. Функции извлечения и преобразования данных отделяются от DOM, диалога выбора и протокола Worker, чтобы их можно было проверять самостоятельно. Координаты карточек и пользовательский выбор остаются ответственностью интерфейса.

Разбор JSON означает чтение уже подготовленной БД. Он не запускает парсер игровых файлов или генератор БД. Обмен данными для просмотра происходит внутри браузера; файл не отправляется Python-службе или внешнему серверу.

## Подготовка данных в памяти

Открытие БД включает подготовку производных данных в памяти:

- Каталога технологий и представлений по [ТЗ адаптера](TZ_DATABASE_ADAPTER_RU.md).
- Дерева требований и его производных результатов для размещения и связей технологий.
- Индекса названий и описаний RU/EN по [ТЗ локализации](TZ_LOCALIZATION_RU.md).

Эта обработка использует только выбранную БД. Она не повторяет парсинг игры, сбор локализации из исходных каталогов или обогащение файла БД. Тексты берутся из уже сохранённых записей локализации.

Подготовленные данные используются для отображения в текущем сеансе. Их создание не записывает новую БД и не перезаписывает исходную.

Полное разобранное дерево БД хранится в памяти Worker, пока эта БД используется. Ссылки `sourceRef` в каталоге указывают на его исходные узлы; разрешение таких ссылок относится к владельцу дерева в Worker. В основной поток передаются каталог, требования и связи, индекс локализации с предусмотренными служебными сведениями. Полное дерево БД и полный исходный JSON не копируются в состояние интерфейса или сообщения с результатом. Виды сообщений определены [ТЗ протокола Worker](TZ_WORKER_PROTOCOL_RU.md), контейнер `ready`, каталог и строковые ссылки — [ТЗ результата](TZ_WORKER_RESULT_RU.md), дерево и связи — [ТЗ технологических требований](TZ_TECHNOLOGY_REQUIREMENTS_RU.md). Записи локализации описаны в [ТЗ индекса](TZ_LOCALIZATION_INDEX_RU.md); общая диагностическая запись и ответ `error` — в [ТЗ диагностики](TZ_DIAGNOSTICS_RU.md).

Индекс БД подготавливается для обоих языков и подключается к общему механизму локализации в основном потоке. Смена языка и показ тултипа используют готовые данные без повторного чтения файла и обхода полного дерева.

Текущий файл БД этапа 10 занимает 140 937 166 байт, около 141 МБ. Это ориентир для проверки, а не ограничение размера в коде. Worker выносит обработку из основного потока, но сам по себе не уменьшает расход памяти. При реализации необходимо проверить время открытия, отзывчивость интерфейса и потребление памяти на реальной БД; результаты пока не получены.

## Состояния интерфейса

| Состояние | Рабочая область | Панель состояния | Действия в меню |
| --- | --- | --- | --- |
| БД не открыта | Свободна | Предложение открыть БД через меню | «Открыть БД» |
| Загрузка | Свободна | Сообщение о текущем этапе обработки | «Отменить» |
| Готово | Поле технологий | Сообщение об открытой БД и число технологий | «Открыть БД» для выбора другого файла, «Сохранить отчёт» |
| Пустой каталог | Свободна | Сообщение «В выбранной БД нет технологий» | «Открыть БД», «Сохранить отчёт» |
| Ошибка | Свободна | Понятное описание проблемы | «Повторить», «Открыть БД», «Сохранить отчёт» |

Все действия с БД находятся в группе над выбором языка. В ней показываются только действия текущего состояния; нижняя группа меню сохраняет кнопки сворачивания и темы. При свёрнутом меню действия скрыты вместе с основным содержимым; для открытия файла, отмены, повтора или сохранения отчёта пользователь раскрывает меню. По [ТЗ сохранения отчёта](TZ_DIAGNOSTIC_REPORT_RU.md) выгрузка доступна после завершения попытки, в том числе успешной без предупреждений; до открытия и во время загрузки она недоступна.

Панель состояния постоянно видима внизу окна на всю ширину, под меню и рабочей областью. Она занимает собственное место, не прокручивается с содержимым и не перекрывает полосы прокрутки. Рабочая область не дублирует сообщения панели. Подробные требования находятся в [ТЗ панели состояния](elements/TZ_STATUS_PANEL_RU.md).

Во время загрузки в панели состояния показывается текущий этап: чтение файла, разбор JSON или подготовка данных. Проценты выполнения на первом этапе не используются. Язык, тема и сворачивание меню продолжают работать. Кнопка открытия другого файла во время обработки скрыта; сначала пользователь может отменить текущую загрузку.

Поле появляется только после успешной подготовки всего набора: каталога, требований и связей, индекса локализации. Частично подготовленные данные не публикуются в интерфейс. Все отображаемые данные относятся к одной открытой БД.

Пустой каталог означает успешное чтение и подготовку корректной БД, в которой нет технологий для отображения. Ошибка чтения, структуры или подготовки не превращается в пустой каталог.

Сообщения о состояниях и подписях действий берутся из встроенной локализации RU/EN. Действия используют общий элемент «Кнопка»; новое оформление и отдельный набор UI-элементов для них не вводятся.

## Отмена и замена БД

Отмена стандартного диалога выбора файла ничего не меняет. Уже открытая БД, её отображение и пользовательский выбор сохраняются; Worker текущей БД продолжает работать.

Отмена начавшейся загрузки завершает Worker этой операции и отбрасывает промежуточные результаты. Приложение возвращается в состояние «БД не открыта» с предложением открыть файл. Сообщения и результаты отменённой либо заменённой операции не должны менять интерфейс, в том числе после начала другой загрузки.

Открытие другой БД выполняется в следующем порядке:

1. До выбора нового файла текущая БД и её отображение сохраняются.
2. После выбора файла завершается старый Worker, из интерфейса удаляются каталог, связи, индекс локализации БД и ссылки на прежние данные. Встроенная локализация интерфейса сохраняется.
3. Новый Worker начинает чтение выбранного файла; интерфейс переходит в состояние загрузки.
4. После успешной подготовки публикуются новые данные. Отображаются основные варианты технологий; позиция просмотра устанавливается в верхний левый угол. Язык, тема и состояние меню сохраняются.

Приложение не удерживает два полных дерева БД для переключения или возврата: старый Worker завершается до начала обработки нового файла. При ошибке или отмене новой загрузки предыдущая БД автоматически не восстанавливается. Для возврата пользователь явно открывает её файл снова.

В состоянии «Готово» или «Пустой каталог» Worker хранит текущую БД. При отмене или блокирующей ошибке загрузки Worker этой операции завершается, промежуточные данные и ссылки на них отбрасываются. По ТЗ протокола каждый новый запуск или повтор получает новый `operationId`; принимаются только ответы актуальной операции от текущего Worker. Отмена сначала делает операцию неактуальной, затем вызывает `worker.terminate()` без команды `cancel` и ожидания подтверждения.

## Ответственность за проверки

Бэкэнд отвечает за корректность создаваемой БД: проверяет её схему, уникальность исходных документов, историю раскрытия конструкций и согласованность локализации перед публикацией. Фронтенд использует этот контракт и не переносит к себе валидатор бэкэнда, его схемы и полный обход дерева ради повторной валидации.

При открытии фронтенд обрабатывает ошибки чтения и разбора JSON и проверяет формат и версию. Затем адаптер выполняет собственные преобразования для карточек, связей и индекса локализации. Неоднозначности, обнаруженные при этих преобразованиях, оформляются как ошибки подготовки; отдельный предварительный проход проверки всех полей БД не вводится.

Например, объединение локализаций объектов в общий индекс требует единственного текста для пары «язык + ID». Разные тексты для этой пары дают согласованный `localization_conflict`: это условие нового индекса для интерфейса, а не повторная проверка структуры исходного дерева. Невозможность выполнить преобразование не подменяется пустым каталогом или произвольно выбранным значением.

## Ошибки и повтор

Нечитаемый файл, некорректный JSON, неподдерживаемые формат или версия БД, а также невозможность подготовить данные для отображения останавливают открытие и переводят интерфейс в состояние ошибки. Границы обработки определены разделом «Ответственность за проверки»; повторная валидация БД не требуется.

Отсутствующие строки локализации не блокируют просмотр. Они обрабатываются маркерами и диагностикой по [ТЗ локализации](TZ_LOCALIZATION_RU.md). Различающиеся тексты под одним ID и языком блокируют подготовку по [ТЗ индекса](TZ_LOCALIZATION_INDEX_RU.md): открытие переходит в состояние ошибки, данные не публикуются, причина требует ручного разбора.

«Повторить» создаёт новую попытку обработки того же выбранного файла. Для этого ссылка на выбранный объект `File` сохраняется в текущем сеансе после ошибки; полное дерево не удерживается. Повторная попытка начинается только по действию пользователя. «Открыть БД» позволяет выбрать другой файл; автоматические повторы и переход к генератору не выполняются.

В панели состояния показывается понятное локализованное сообщение. Технические подробности ошибки остаются в диагностике по [отдельному ТЗ](TZ_DIAGNOSTICS_RU.md). Полученная причина ошибки и предупреждения сохраняются в основном потоке после завершения Worker; на первом этапе подробности просматриваются во внешнем редакторе после явного сохранения JSON по [ТЗ отчёта](TZ_DIAGNOSTIC_REPORT_RU.md). Смена языка обновляет сообщение через встроенный механизм локализации.

## Отделение от генератора БД

Просмотр готовой БД и её создание или обновление независимы. Для открытия готового файла не требуется доступ к исходным каталогам игры и локализации.

На первом этапе отсутствует кнопка «Обновить БД». Запуск генератора не привязывается к открытию файла, обновлению страницы или запуску приложения. Отсутствующая или непригодная для просмотра БД также не должна автоматически запускать её сборку.

Будущее обновление БД через интерфейс потребует отдельного проектирования и явного действия пользователя.

## Режим первого этапа

Первый интерфейс разрабатывается и проверяется из рабочего окружения проекта. Portable-сборка и запуск через упакованный `.exe` не являются требованиями или критериями приёмки этого этапа.

Переносимая поставка для Windows остаётся последующим этапом общего проекта. Для запуска среды разработки и сборки фронтенда выбран Vite. Для просмотра готовой БД используется браузер с Worker; Python-служба для этого этапа не запускается.

## Критерии приёмки

Проверки выполняются после реализации:

1. При запуске и обновлении страницы панель состояния предлагает открыть БД через меню, рабочая область свободна; файл БД не загружается автоматически.
2. Загрузка выбранного JSON начинается только после явного действия пользователя и выбора файла.
3. Успешное открытие готовой БД формирует поле технологий, используя сохранённые названия и описания RU/EN.
4. Открытие работает при недоступных исходных каталогах игры и локализации; исходные данные не перечитываются.
5. Каталог, требования и индекс локализации подготавливаются в памяти, выбранный файл БД остаётся неизменным.
6. Запуск, обновление страницы, открытие БД и ошибки открытия не вызывают генератор или обогащение БД.
7. После обновления страницы требуется новое явное открытие файла. Кнопка обновления БД отсутствует; portable-сборка для проверок не требуется.
8. Файл выбирается через стандартный диалог браузера. Чтение содержимого, разбор JSON и подготовка данных выполняются в Worker; просмотр работает без Python-службы.
9. Основной поток получает данные для отображения без полной копии дерева БД или исходного JSON. `sourceRef` разрешается в соответствующий узел дерева, сохраняемого в Worker.
10. Модули извлечения технологий, обработки требований и чтения локализации проверяются отдельно от диалога выбора, DOM и протокола Worker.
11. На реальной БД зафиксированы время открытия, потребление памяти и результат проверки отзывчивости интерфейса. Проверки выполняются в указанном окружении и браузере; одна только архитектура Worker не считается подтверждением производительности.
12. Проверены все пять состояний: БД не открыта, загрузка, готово, пустой каталог, ошибка. Корректный пустой каталог отличается от неудачного открытия.
13. Во время обработки показан текущий этап без процентов; язык, тема и сворачивание меню работают. Поле получает весь согласованный набор данных только после успеха.
14. Отмена диалога выбора сохраняет текущую БД и пользовательский выбор. Отмена начавшейся загрузки завершает Worker и возвращает начальный экран; устаревшие сообщения не применяются, включая сообщения после начала новой операции.
15. После выбора другой БД старый Worker завершается до обработки нового файла. Прежние данные и индекс БД удаляются; успешное открытие устанавливает основные варианты и верхний левый угол, сохраняя язык, тему и состояние меню.
16. Ошибка или отмена замены не восстанавливает предыдущую БД автоматически. Проверено отсутствие удержания двух полных деревьев для возврата.
17. «Повторить» запускает новую обработку того же выбранного файла только по действию пользователя. Проверены ошибки чтения и JSON, неподдерживаемые формат и версия, ошибки преобразования адаптером, блокирующее противоречие текстов локализации и неблокирующее отсутствие переводов.
18. Действия текущего состояния показаны в меню над выбором языка; остальные скрыты. Сворачивание скрывает действия с БД, сохраняя кнопку раскрытия; после раскрытия доступны действия актуального состояния.
19. Сообщения всех пяти состояний находятся в постоянно видимой нижней панели на всю ширину окна. Рабочая область не дублирует сообщения и показывает поле только в состоянии «Готово»; меню и поле располагаются над панелью без перекрытия содержимого и полос прокрутки.

## Детали последующей реализации

Сообщения `open_database`, `progress`, `ready`, `error`, различение операций и отбрасывание устаревших ответов определены [ТЗ протокола Worker](TZ_WORKER_PROTOCOL_RU.md). Состав `details` и `params: {}` для текущих кодов закреплены ТЗ диагностики. Предстоит уточнить программные типы подробностей ошибок открытия и преобразования, программные интерфейсы модулей, конфигурацию инструментов, размеры и отступы элементов и идентификаторы интерфейсных строк. Поведение состояний, отмены, повтора и замены БД, расположение действий в меню и сообщений в панели состояния установлены настоящим документом.

Постоянное хранение состояния, автоматическое восстановление файла, генерация БД через интерфейс и portable-поставка не реализуются на основании этого документа.
