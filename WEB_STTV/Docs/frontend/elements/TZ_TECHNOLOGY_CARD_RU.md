## Статус и назначение

В действующем справочнике наведение и фокус подсвечивают связи. Левый щелчок открывает подробности, контекстное меню ведёт на страницу, средний щелчок открывает её в новой вкладке. [Действия карточки и страница технологии](../TZ_TECHNOLOGY_PAGE_AND_ACQUISITION_RU.md)

Реализован [редизайн этапа 8](../TZ_FRONTEND_STAGE_8_RU.md): игровая иконка, полное название, характеристики и оформление по области/редкости/опасности. Он заменяет прежние ограничения состава и размеров ниже. Исходный документ сохраняет историю проектирования; актуальное поведение и проверенные сценарии описаны в [руководстве 0.0.8](../FRONTEND_STAGE_8_RU.md). Интерактивное переключение вариантов остаётся отложенным.

Документ фиксирует требования к карточке технологии, согласованные пользователем 2026-11-16: тултип содержит название и описание, варианты технологии переключаются вручную через выпадающий список с управлением мышью и клавиатурой. Реализация элемента ещё не начата; оставшиеся детали перечислены в последнем разделе для дальнейшего проектирования.

Основа — [концепт интерфейса](../CONCEPT_RU.md) и [список UI-элементов](../UI_ELEMENTS_RU.md). Карточка представляет технологию в поле технологий; на первом этапе её видимое содержимое ограничено названием.

## Состав и входные данные

Карточка состоит из контейнера, общего элемента [«Текст»](TZ_TEXT_RU.md) для названия и привязанного общего [«Тултипа»](TZ_TOOLTIP_RU.md) для названия и описания. Для технологии с блоками `technology_swap` карточка позволяет открыть ручной выбор представления.

| Данные или настройка | Назначение |
| --- | --- |
| Источник | БД приложения |
| Базовая технология | Идентификатор исходной технологии, к которому привязаны карточка, связи и выбор представления |
| Набор представлений | Основная версия и варианты `technology_swap` с отдельными ссылками на записи БД, ID строк и сведениями об области науки |
| Текущее представление | Основная версия либо конкретный вариант этой технологии |
| Обработка выбора | Передача выбранного представления использующему компоненту |
| ID строки названия | Например, `tech_titans`; используется в карточке и заголовке тултипа |
| ID строки описания | Например, `tech_titans_desc`; используется в основном тексте тултипа |
| Язык, предоставляемый системой | Текущая локализация `ru` или `en` из состояния приложения |
| Размеры и внутренние отступы | Общие настройки геометрии карточек |
| Роли оформления | Именованные переменные карточки, её названия и тултипа |

Таблица описывает необходимые сведения, а не окончательные имена программных параметров или способ их передачи. Идентификаторы названия и описания соответствуют выбранному представлению и поступают от использующего компонента. Общий механизм локализации получает источник, ID строки и системный язык и применяет конфигурацию источника по ТЗ текста. Идентичность выбранного объекта и ID строки локализации — разные данные.

Каталог и массив `representations` формируются по [ТЗ адаптера БД](../TZ_DATABASE_ADAPTER_RU.md). Каждое представление содержит свой ID, итоговую область, `nameId`, `descriptionId` и `sourceRef`; у вариантов дополнительно задан `variantNumber`. Основная версия идёт первой, затем блоки вариантов в порядке БД. Идентичность представлений относится к загруженной БД; сопоставление после её перестроения рассматривается вместе с сохранением состояния.

## Размеры и размещение

Все карточки имеют одинаковые ширину и высоту. Размеры и внутренние отступы задаются настройками. Изменение окна, языка, состояния наведения или выбранного представления не меняет размер карточки.

Область науки, столбец и вертикальную позицию назначает поле технологий. Карточка отображает переданные данные в назначенном месте; группировка и порядок внутри столбца относятся к полю технологий. Выбор варианта с другой областью науки передаётся полю для изменения размещения.

## Отображение названия

Название выравнивается по центру горизонтально и вертикально. Используется перенос по словам с ограничением в две строки через общий элемент «Текст».

Если название не помещается, в конце видимой части показывается многоточие по правилам текста. Если название помещается, многоточие не добавляется. Ограничение отображения не изменяет исходную строку локализации.

## Название и описание в тултипе

Для базовой технологии справочника после описания идут требуемые технологии, условия доступности и изменения веса выпадения, если они заданы. [Расширенное содержимое тултипа](../TZ_TECHNOLOGY_TOOLTIP_CONTENT_RU.md)

При наведении на любую часть карточки, включая внутренние отступы, появляется общий тултип. При уходе указателя с карточки он скрывается. Элементом привязки служит вся карточка. Открытие списка вариантов скрывает тултип карточки; пока список открыт, тултип этой карточки не показывается.

Тултип содержит:

- Полное название технологии в качестве заголовка.
- Описание технологии под заголовком.

Обе строки получаются из готовой локализации выбранного представления в БД на текущем языке системы. Для заголовка используется тот же ID названия, что и в карточке; для основного текста — ID описания. Для варианта используется в том числе уже подготовленное в БД наследованное описание основной технологии. Ограничение названия в карточке двумя строками и многоточием на тултип не распространяется: его текст переносится по словам, сохраняя полное содержимое.

Размещение возле карточки, показ поверх содержимого без сдвига других элементов, учёт границ видимой области и оформление следуют общему ТЗ тултипа. Смена языка обновляет название в карточке и обе строки тултипа.

## Ручной выбор варианта

При отсутствии заданного выбора отображается основная версия технологии. Нажатие на карточку, имеющую варианты, открывает выбор основной версии и её блоков `technology_swap` из БД. Для технологии без вариантов этот выбор не предлагается.

Одновременно отображается одно представление базовой технологии. После выбора обновляются название карточки, заголовок и описание тултипа. Основная версия остаётся доступной для обратного переключения. Другие технологии сохраняют собственный выбор.

Это ручной просмотр представлений в справочнике. Проверка `trigger` варианта для конкретного государства и автоматический выбор по условиям игры относятся к последующим этапам.

Разные блоки `technology_swap` могут иметь одинаковые `name` и локализованные названия. Они остаются отдельными вариантами: выбранное значение должно различать базовую технологию и конкретный блок варианта, а не только его название или ключ локализации. Подписи формируются по правилам следующего раздела.

Для списка используется общий [элемент выбора](TZ_SELECT_RU.md) UI-кита. Сама карточка служит элементом открытия списка и в закрытом состоянии сохраняет согласованное отображение названия.

## Подписи вариантов

Если в списке выбора одной технологии локализованное название варианта совпадает с названием основной версии или другого варианта, к подписи этого варианта добавляется суффикс ` (Вариант N)` для русского языка или ` (Variant N)` для английского. Основная версия остаётся без суффикса. Вариант с уникальным названием в текущем языке отображается без суффикса.

`N` — порядковый номер блока `technology_swap` внутри базовой технологии в БД, начиная с 1. Основная версия в нумерацию не входит. Номер не зависит от языка, совпадений названий и порядка отображения списка; смена языка сохраняет выбранный блок. Например: «Титаны», «Титаны (Вариант 1)», «Титаны (Вариант 2)»; на английском — «Titans», «Titans (Variant 1)», «Titans (Variant 2)».

Шаблон суффикса хранится во встроенной локализации интерфейса отдельно для RU и EN, название берётся из БД. Суффикс формируется для подписи в списке выбора и не изменяет строки, ключи локализации или идентификаторы объектов БД. Выбор по-прежнему связан с конкретным блоком варианта; подпись и номер не заменяют его идентификатор.

## Работа со списком вариантов

- Нажатие на карточку с вариантами открывает выпадающий список.
- Первой в списке идёт основная версия, затем варианты в порядке блоков `technology_swap` в БД. Текущий выбранный пункт визуально отмечен.
- Выбор пункта применяет соответствующее представление и закрывает список.
- Нажатие вне списка или `Escape` закрывает список без изменения выбранного представления.
- Пока список открыт, тултип карточки скрыт.
- Когда карточка находится в фокусе, `Enter` или `Space` открывают список. В открытом списке стрелки вверх и вниз перемещают фокус между пунктами, `Enter` подтверждает выбор и закрывает список. Перемещение фокуса само по себе не применяет вариант.

Визуальная отметка выбранного пункта и фокус навигации различаются по правилам общего элемента выбора. Отмена после перемещения фокуса сохраняет ранее выбранное представление.

## Состояние выбора и размещение

Выбор хранится в состоянии приложения отдельно для каждой базовой технологии. Карточка получает текущее представление и сообщает о его изменении использующему компоненту. Смена языка или темы и перемещение карточки в другую область науки сохраняют выбранное представление.

Базовый идентификатор и технологические зависимости сохраняются. В текущих данных `technology_swap` не переопределяет `tier` и `prerequisites`; выбор не создаёт дополнительную независимую технологию или отдельные связи.

Область науки берётся из выбранного варианта, если он её задаёт, иначе — из основной технологии. Если область изменилась, поле переносит карточку в соответствующую область с сохранением столбца `tier` и применением правил вертикального порядка. Например, выбор `tech_biogenesis_titans` переносит карточку `tech_titans` из инженерии в социологию. Возврат к основной версии возвращает её область науки.

Сохранение выбранных вариантов между запусками рассматривается отдельно в рамках [общего механизма состояния](../CONCEPT_RU.md#сохранение-настроек-и-состояния). Карточка не вводит собственное постоянное хранилище.

## Состояния и оформление

Дополнение от 2026-11-19: наведение на карточку также выделяет отображаемую связь с непосредственным родителем одним цветом, а связи с непосредственными детьми — другим, по [ТЗ элемента связи](TZ_CONNECTION_RU.md#подсветка-при-наведении-на-карточку). При уходе указателя выделение снимается. Подсветка связей не меняет геометрию карточки или маршрутов и не отменяет показ тултипа. Это требование относится к проектируемому этапу связей и ещё не реализовано.

Поддерживаются обычное состояние и наведение, а для карточки с выбором вариантов — клавиатурный фокус. Наведение и фокус визуально выделяют карточку, сохраняя её размеры и назначенное положение. Состояния пунктов списка оформляются по ТЗ общего элемента выбора.

Цвета фона, границы и текста, а также шрифтовые параметры назначаются именованными переменными [словаря цветов и шрифтов](../CONCEPT_RU.md#словарь-цветов-и-шрифтов) для обеих тем и соответствующего состояния. Название в карточке, заголовок и описание тултипа используют свои роли оформления общего элемента «Текст».

## Критерии приёмки

Проверки выполняются после реализации:

- Карточка содержит только название, отображаемое общим элементом «Текст» из источника БД на языке системы.
- Все карточки имеют одинаковые настроенные ширину и высоту; размер сохраняется при изменении окна, языка, выбранного представления и наведении.
- Короткое название центрировано по обеим осям; длинное переносится по словам максимум на две строки и получает многоточие только при переполнении.
- При закрытом списке вариантов наведение на название и внутренние отступы показывает тултип с полным названием и описанием; уход указателя скрывает его.
- Сокращённое в карточке название полностью доступно в заголовке тултипа; описание выводится отдельно под ним.
- Смена RU/EN обновляет название карточки, заголовок и описание тултипа через общий механизм локализации.
- Появление тултипа не меняет геометрию карточек; размещение возле краёв соответствует общему ТЗ тултипа.
- Обычное состояние, наведение и клавиатурный фокус используют переменные словаря обеих тем; наведение и фокус различимы.
- Без заданного выбора показана основная версия; карточка с вариантами открывает выбор основной версии и её вариантов. Для технологии без вариантов выбор не предлагается.
- Список использует общий элемент выбора: основная версия идёт первой, варианты следуют в порядке БД, текущий выбор отмечен.
- Выбор пункта применяет представление и закрывает список; нажатие вне списка и `Escape` закрывают его без изменения выбора, в том числе после перемещения фокуса.
- `Enter` и `Space` открывают список с карточки в фокусе; стрелки перемещают фокус, `Enter` подтверждает вариант. Навигация не применяет вариант до подтверждения.
- Открытие списка скрывает тултип карточки; он остаётся скрытым всё время работы с открытым списком.
- Выбор обновляет название и обе строки тултипа по готовой локализации БД; проверяется вариант с наследованным описанием и возврат к основной версии.
- Разные блоки с одинаковыми названиями остаются разными значениями выбора и получают в списке суффиксы «(Вариант N)» / «(Variant N)»; проверяются совпадения с основной версией и между вариантами. Основная версия и варианты с уникальными названиями не получают суффикс.
- Номер соответствует порядку блоков `technology_swap` в БД и сохраняется при смене языка; проверяется случай совпадения названий только в одном языке. Подписи не изменяют исходную локализацию БД.
- Изменение выбора одной технологии не меняет выбор других; переключение RU/EN и темы сохраняет выбранное представление.
- Смена области науки выбранным вариантом перемещает карточку по правилам поля, сохраняя её размер, `tier`, базовый ID и зависимости; обратное переключение восстанавливает основную область.
- Карточка следует месту, назначенному полем технологий, включая изменение области при выборе варианта.

## Детали последующей реализации

Конкретные размеры, отступы, имена параметров и переменных оформления, а также интеграция с полем технологий определяются при проектировании реализации. Поиск и поведение при отсутствии строк закреплены в [ТЗ локализации](../TZ_LOCALIZATION_RU.md); размещение содержимого тултипа, превышающего доступную область, относится к общему ТЗ тултипа.

При проектировании реализации остаётся определить обозначение наличия вариантов, геометрию и размещение списка у границ окна, начальный и возвращаемый фокус, в том числе при переносе карточки между областями науки. Программная форма идентификатора и ссылки на вариант уточняется в реализации адаптера; восстановление выбора после перестроения БД — в механизме состояния. Эти детали не считаются утверждёнными настоящим документом.
