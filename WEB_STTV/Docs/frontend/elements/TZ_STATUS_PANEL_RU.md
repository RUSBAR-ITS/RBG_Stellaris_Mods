## Статус и назначение

Документ фиксирует согласованные требования к панели состояния первого интерфейса. Реализация элемента ещё не начата.

Основа — [концепт интерфейса](../CONCEPT_RU.md), [список UI-элементов](../UI_ELEMENTS_RU.md) и [ТЗ открытия БД](../TZ_DATABASE_OPENING_RU.md#состояния-интерфейса). Панель постоянно показывает текущее состояние работы с БД в нижней части основного окна.

## Состав и ответственность

Панель является составным элементом UI-кита и использует общий [элемент «Текст»](TZ_TEXT_RU.md). На первом этапе она содержит одно короткое сообщение о текущем состоянии.

Приложение передаёт идентификатор сообщения из встроенной локализации и необходимые параметры. Язык определяется общим состоянием приложения. Панель отображает полученные данные; чтение БД, обработка требований, подсчёт технологий и управление Worker выполняются вне неё.

Действия «Открыть БД», «Отменить», «Повторить» и [«Сохранить отчёт»](../TZ_DIAGNOSTIC_REPORT_RU.md) находятся в [панели меню](TZ_MENU_PANEL_RU.md). Панель состояния не содержит этих кнопок. Рабочая область не дублирует её сообщения: она показывает поле технологий в состоянии «Готово», а в остальных состояниях остаётся свободной.

## Расположение и размеры

Панель располагается внизу [основного окна](TZ_MAIN_WINDOW_RU.md) на всю его ширину, под меню и рабочей областью технологий.

- Она постоянно видима и занимает собственное место в раскладке.
- Меню и рабочая область располагаются над ней и используют оставшуюся высоту окна.
- Панель не участвует в прокрутке меню или технологий и не перекрывает их содержимое либо полосы прокрутки.
- Сворачивание меню не меняет ширину панели состояния и не скрывает её.
- Нижняя группа кнопок меню остаётся внизу самого меню, выше панели состояния.

Высота, внутренние отступы и точное поведение текста при недостаточной ширине уточняются при проектировании реализации. На первом этапе используются короткие сообщения и простой дизайн.

## Сообщения и локализация

Панель отражает пять состояний из ТЗ открытия БД: БД не открыта, загрузка, готово, пустой каталог и ошибка. При загрузке сообщение показывает текущий этап без процентов выполнения. Отмена, повтор и замена файла изменяют сообщение согласно состоянию приложения; панель не определяет эти переходы самостоятельно.

| Состояние или этап | Пример сообщения RU | Пример сообщения EN |
| --- | --- | --- |
| БД не открыта | БД не открыта. Откройте файл через меню. | No database open. Open a file through the menu. |
| Чтение файла | Загрузка: чтение файла… | Loading: reading file… |
| Разбор JSON | Загрузка: разбор JSON… | Loading: parsing JSON… |
| Подготовка данных | Загрузка: подготовка данных… | Loading: preparing data… |
| Готово | БД открыта. Технологий: {count}. | Database opened. Technologies: {count}. |
| Пустой каталог | В выбранной БД нет технологий. | No technologies found in the selected database. |
| Ошибка JSON | Не удалось открыть БД: некорректный JSON. | Could not open database: invalid JSON. |

Сообщение «Готово» получает фактическое число базовых технологий из подготовленного каталога. Количество вариантов не прибавляется к этому числу. Значение не зашивается в строку; оно передаётся параметром встроенного шаблона по [ТЗ локализации](../TZ_LOCALIZATION_RU.md).

Для блокирующих ошибок используются согласованные [строки диагностики](../TZ_DIAGNOSTICS_RU.md#сообщение-интерфейса). Основной поток сопоставляет `code` идентификатору `sttv_diagnostic_<код>` через конфигурацию диагностики, использует источник `builtin` и передаёт `params: {}`. Тексты RU/EN хранятся во встроенных файлах локализации. Технические подробности `details` сохраняются отдельно и не подменяют сообщение панели. Предупреждение `missing_localization` остаётся в диагностике и не заменяет сообщение об успешной загрузке с количеством технологий.

Смена языка обновляет текущее сообщение без повторного открытия БД. Панель остаётся видимой и продолжает отражать состояние при свёрнутом меню; для действий с БД пользователь раскрывает меню.

## Оформление

Фон, граница, цвет сообщения и шрифтовые параметры задаются собственными именованными переменными панели в [словаре оформления](../TZ_STYLING_DICTIONARY_RU.md). Общий элемент «Текст» использует переданную роль панели.

Дневная и ночная темы определяют все используемые назначения. Переменные могут ссылаться на общие значения словаря; литералы цветов и шрифтов не дублируются в компоненте. Конкретные назначения и необходимость отдельных значений для состояний уточняются при проектировании реализации.

## Критерии приёмки

Проверки выполняются после реализации:

1. Панель находится внизу окна на всю ширину и постоянно видна, в том числе при свёрнутом меню.
2. Меню и рабочая область располагаются выше панели; она занимает собственное место, не перекрывая содержимое и полосы прокрутки.
3. Прокрутка технологий и меню не перемещает панель состояния; нижние кнопки меню остаются над ней.
4. Панель показывает одно короткое сообщение для каждого из пяти состояний; загрузка показывает текущий этап без процентов.
5. Сообщение «Готово» использует число технологий из каталога. Варианты не считаются отдельными базовыми технологиями.
6. Сообщения используют встроенные строки RU/EN и общий элемент «Текст»; смена языка обновляет сообщение без повторной загрузки БД.
7. Действия с БД находятся в меню. Рабочая область не дублирует сообщения и показывает поле только в состоянии «Готово».
8. Обе темы используют собственные переменные панели для цветов и шрифтов; компонент не повторяет конкретные значения.

## Детали последующей реализации

Предстоит определить программный интерфейс элемента, идентификаторы остальных сообщений состояния, высоту, отступы, поведение длинного текста и точные имена и назначения переменных оформления. ID и тексты текущих сообщений диагностики уже закреплены соответствующим ТЗ. Панель использует уже согласованные состояния приложения; новые переходы и действия этим документом не вводятся.
