## Статус и назначение

Документ фиксирует требования, согласованные пользователем 2026-11-16 при обсуждении базового элемента «Текст». Реализация элемента ещё не начата.

Основа — [концепт интерфейса](../CONCEPT_RU.md) и [список UI-элементов](../UI_ELEMENTS_RU.md). Элемент предназначен для повторного использования в названиях технологий, описаниях и подписях настроек.

## Содержимое и входные настройки

Для получения текста нужны три значения: источник, идентификатор строки внутри этого источника и язык. Использующий компонент передаёт источник и идентификатор; текущий язык предоставляет система из состояния приложения. Идентификатор обязателен; при отсутствии явно указанного источника используется встроенная локализация интерфейса.

Поддерживаются два источника:

- **Встроенный:** отдельные локализованные файлы интерфейсных строк; настройка языка определяет используемый файл.
- **БД приложения:** локализация объектов, уже сохранённая в `enrichments.localization`. Для выбранного языка используется `text` нужного поля (`name` или `description`); структура хранения описана в [руководстве этапа 10](../../BACKEND_STAGE_10_RU.md#хранение-и-чтение-бд).

Получение строки выполняется общим механизмом локализации, используемым элементом «Текст». Использующие компоненты передают источник и идентификатор, не дублируя поиск перевода. Идентификатор разрешается в пределах выбранного источника. При смене языка текст обновляется для той же пары источник/идентификатор; сам элемент не определяет язык независимо от приложения. Источник БД не требует переноса игровых строк во встроенные файлы интерфейса.

Параметр источника выбирает хранилище для отображения. Поле `source` внутри записи локализации БД имеет другое назначение: хранит происхождение перевода — приоритет, файл и строку.

Необходимые входные данные и настройки:

| Данные или настройка | Назначение |
| --- | --- |
| Источник, необязательный | Встроенная локализация интерфейса по умолчанию либо БД приложения |
| Идентификатор строки | Обязательный идентификатор текста внутри выбранного источника |
| Язык, предоставляемый системой | Текущая локализация `ru` или `en` из состояния приложения |
| Параметры встроенного шаблона, необязательные | Именованные значения, например `number` для подписи варианта; не меняют ID строки |
| Роль оформления | Набор именованных переменных для данного назначения текста |
| Состояние родительского компонента | Выбор соответствующих переменных, если оформление зависит от состояния |
| Выравнивание и ограничения размера | Размещение в пределах использующего компонента |
| Режим переполнения | Полный текст с переносом либо ограниченное число строк |
| Максимальное число строк | Предел для режима ограничения строк |

Таблица описывает необходимые сведения, а не окончательные имена программных параметров или способ их передачи.

## Общий поиск и конфигурация источников

Поиск выполняется по [ТЗ общего механизма локализации](../TZ_LOCALIZATION_RU.md). Структуры встроенных файлов и БД могут отличаться; общий механизм поиска получает источник, ID строки и язык и применяет описание выбранного источника. Элемент «Текст» не строит путь по внутренней структуре конкретного хранилища.

Конфигурация каждого источника должна описывать:

- Где находятся данные и записи локализации.
- Как системный язык выбирает файл или языковую ветку данных.
- Как переданный ID строки сопоставляется с ключом или полем записи.
- Откуда берётся итоговый текст.

Пример запроса: источник — БД, ID строки — `tech_titans`, язык системы — `ru`. Общий механизм использует конфигурацию БД, находит соответствующую запись и возвращает её `text`: «Титаны». Вызывающий компонент не передаёт дополнительно `name` или `description`: он передаёт ID именно строки, а адресация внутри источника описывается его конфигурацией.

В текущей БД строки вложены в объекты и их варианты. При загрузке обработчик строит индекс в памяти по `requested_key` для каждого языка; отображается поле `text`. Поле `key` описывает фактически выбранный перевод и не заменяет ID поиска. По [ТЗ записей индекса](../TZ_LOCALIZATION_INDEX_RU.md) повторы с одинаковым текстом объединяются с сохранением происхождения; разные тексты под одним ID и языком дают блокирующую ошибку подготовки и требуют ручного разбора. При отсутствии строки выводится `⟦ID строки⟧`; пустая строка остаётся пустой. Автоматической подмены языка нет.

Встроенный источник читает отдельные JSON-словари RU/EN. Его шаблоны могут получать именованные параметры, например `{number}`. Строки БД через обработчик интерфейсных параметров не проходят. При смене языка используется уже подготовленный индекс; при замене источника его индекс перестраивается.

## Оформление и роли

Через именованные переменные отдельного словаря задаются:

- Цвет текста.
- Семейство шрифта.
- Размер шрифта.
- Насыщенность шрифта.
- Межстрочный интервал.

Назначение переменных и их значения для дневной и ночной темы определяются по [ТЗ словаря оформления](../TZ_STYLING_DICTIONARY_RU.md). Используются собственные CSS-переменные текстовой роли, связанные с общими определениями в словаре. Конкретные цвета и шрифтовые значения не дублируются в элементе или использующих его компонентах.

Название технологии, описание и подпись настройки могут использовать разные наборы переменных при одном базовом элементе «Текст». Ссылки на общие определения задаются в словаре. На первом этапе семейство, размер, насыщенность и межстрочный интервал одной роли одинаковы в дневной и ночной теме; шрифт поддерживает кириллицу и латиницу.

## Состояния и взаимодействие

Если оформление текста меняется при наведении или другом состоянии родительского компонента, используются переменные для этого состояния. Сам элемент не вводит независимый набор действий или собственное действие при нажатии.

Состояния, влияющие на оформление конкретного текста, задаются требованиями использующего компонента.

## Размещение и переполнение

Выравнивание и ограничения по размеру задаёт использующий компонент. Поддерживаются два режима:

1. **Полное отображение:** текст переносится по словам и отображается полностью.
2. **Ограничение строк:** текст занимает не больше заданного числа строк; при превышении этого предела в конце видимой части показывается многоточие. Если текст помещается, многоточие не добавляется.

Выбор режима и предельного числа строк определяется при описании карточки, тултипа и остальных составных элементов. Ограничение отображения применяется к полученному тексту и не изменяет его идентификатор или содержимое в выбранном источнике.

Исходная строка сохраняется в БД. При выводе «Текст» применяет игровую палитру к цветовым фрагментам. Остальные обозначения, включая значки и нераскрытые подстановки, выводятся буквально. [Цвет игровых названий](../TZ_TECHNOLOGY_TOOLTIP_CONTENT_RU.md#цвет-игровых-названий)

## Критерии приёмки

Проверки выполняются после реализации:

- Без явного источника по идентификатору отображается строка из встроенного файла выбранного языка; явный выбор встроенного источника даёт тот же результат.
- При выборе БД отображается `text` соответствующего названия или описания объекта на выбранном языке.
- Идентификатор разрешается в выбранном источнике, в том числе при наличии такого же идентификатора в другом источнике; текстовые литералы не задаются в использующих компонентах.
- При переключении RU/EN одна и та же пара источник/идентификатор даёт соответствующий перевод через общий механизм локализации.
- Язык поступает из состояния приложения; вызывающий компонент передаёт ID строки, при необходимости источник и именованные параметры встроенного шаблона.
- Встроенный источник и БД используют общий механизм с отдельными конфигурациями; знание их путей и расположения полей не дублируется в элементе и его потребителях.
- Один элемент используется для названия, описания и подписи с разными ролями оформления.
- Все пять перечисленных параметров оформления задаются через словарь; изменение назначенных переменных отражается в отображении для обеих тем.
- При изменении состояния родителя применяется соответствующее оформление текста без появления самостоятельного действия при нажатии.
- В режиме полного отображения длинный текст с пробелами переносится по словам и сохраняет всё содержимое.
- В режиме ограничения строк проверены короткий текст, помещающийся без многоточия, и длинный текст, заканчивающийся многоточием при превышении предела.
- Изменение доступной ширины сохраняет выбранный режим переполнения и заданное выравнивание.
- Повторы, конфликты, пропуски и параметры встроенных шаблонов обрабатываются по ТЗ локализации. В строке с окрашенным названием проверить цвет самого названия и восстановление обычного цвета для текста после него.

## Детали последующей реализации

Конкретные имена параметров и переменных, способ связи со словарём и библиотека интерфейса определяются при проектировании реализации. Режимы и размеры для конкретных применений закрепляются в ТЗ соответствующих составных элементов.

JSON-словари встроенных строк, индекс в памяти, поиск по `requested_key`, повторы и отсутствие текста описаны в [ТЗ локализации](../TZ_LOCALIZATION_RU.md). Полная схема конфигурации, загрузка ресурсов, API и диагностика требуют проектирования реализации. Внутренние поля названия/описания и условные варианты учитывает механизм поиска по конфигурации; они не становятся дополнительными параметрами элемента. Текущее хранение переводов внутри объектов БД сохраняется; индекс в файле БД не вводится.
