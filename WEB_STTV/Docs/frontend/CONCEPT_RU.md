## Статус

Актуальный этап — [фронтенд 0.0.12](FRONTEND_STAGE_10_RU.md): разделы дерева и настройки DLC, черновик и применение через локальный Python-сервис. Открывается каталог набора с манифестом; готовое дерево можно смотреть без сервиса, пересчёт DLC требует его запуска. При смене DLC выполняется обогащение существующей БД, без генератора и чтения игровых источников. Описание первого этапа ниже сохраняется как история.

Связи дерева и подсветка при наведении появились в [фронтенде 0.0.6](FRONTEND_STAGE_6_RU.md).

Документ фиксирует согласованные решения по схеме окна и первому интерфейсу. По подготовленным и утверждённым ТЗ реализован первый этап; запуск и фактическое устройство описаны в [руководстве](FRONTEND_STAGE_1_RU.md).

[Справочник UI-элементов](UI_ELEMENTS_RU.md) содержит только список текущих элементов по категориям со ссылками на их ТЗ. Согласованные требования оформляются отдельными парами документов в `Docs/frontend/elements/`; описаны элементы [«Текст»](elements/TZ_TEXT_RU.md), [«Иконка»](elements/TZ_ICON_RU.md), [«Кнопка»](elements/TZ_BUTTON_RU.md), [«Элемент выбора»](elements/TZ_SELECT_RU.md), [«Выбор языка»](elements/TZ_LANGUAGE_SELECTOR_RU.md), [«Переключатель темы»](elements/TZ_THEME_TOGGLE_RU.md), [«Кнопка сворачивания/раскрытия меню»](elements/TZ_MENU_TOGGLE_RU.md), [«Карточка технологии»](elements/TZ_TECHNOLOGY_CARD_RU.md), [«Тултип»](elements/TZ_TOOLTIP_RU.md), [«Панель меню»](elements/TZ_MENU_PANEL_RU.md), [«Нижняя группа кнопок меню»](elements/TZ_MENU_BUTTON_GROUP_RU.md) и [«Рабочая область просмотра технологий»](elements/TZ_TECHNOLOGY_VIEWPORT_RU.md).

Документация фронтенда размещается в `Docs/frontend/`, код — в `src/frontend/`. Общие решения о Python, TypeScript, HTML/CSS и переносимой поставке находятся в [общем ТЗ](../TZ_RU.md). Названия и описания RU/EN уже хранятся в БД по [этапу 10](../BACKEND_STAGE_10_RU.md).

По [ТЗ технологической основы](TZ_TECH_STACK_RU.md) интерфейс строится на React и TypeScript с обычным CSS; Vite отвечает за среду разработки и сборку. Состояние текущего запуска управляется встроенными средствами React. Обработка БД остаётся в независимых модулях TypeScript, вызываемых из Worker. [ТЗ структуры фронтенда](TZ_STRUCTURE_RU.md) определяет каталоги кода, конфигурации, локализаций и ресурсов; точные программные интерфейсы проектируются отдельно.

[ТЗ протокола Worker](TZ_WORKER_PROTOCOL_RU.md) задаёт команду `open_database`, ответы `progress`, `ready`, `error` и общий `operationId`. Приложение принимает ответы только актуальной операции от текущего Worker; отмена завершает его без ожидания подтверждения. [ТЗ результата Worker](TZ_WORKER_RESULT_RU.md) фиксирует контейнер `data` с каталогом, связями, локализацией и диагностикой, поля технологии, ID представлений `base`/`swap:N` и строковые ссылки на исходные узлы. [ТЗ технологических требований](TZ_TECHNOLOGY_REQUIREMENTS_RU.md) описывает дерево с корневым `AND` и связи с путями к упоминаниям. [ТЗ записей индекса локализации](TZ_LOCALIZATION_INDEX_RU.md) задаёт `status`, `text`, `origins`, объединение повторов и ошибку при противоречивых текстах. [ТЗ диагностики](TZ_DIAGNOSTICS_RU.md) задаёт общую запись, начальные коды и ответ `error`: одна блокирующая причина и накопленные предупреждения. Полученная диагностика сохраняется в основном потоке после завершения Worker. [ТЗ сохранения отчёта](TZ_DIAGNOSTIC_REPORT_RU.md) задаёт действие меню «Сохранить отчёт» для завершённой попытки: JSON с результатом и диагностикой открывается во внешнем редакторе. Встроенный просмотр отложен; точные технические подробности и использование отрицаний в раскладке уточняются отдельно.

По [ТЗ запуска и открытия готовой БД](TZ_DATABASE_OPENING_RU.md) первый интерфейс проверяется из рабочего окружения без portable-сборки. Запуск и обновление страницы загружают только интерфейс; пользователь явно выбирает готовый JSON действием «Открыть БД» в меню. До этого нижняя панель состояния предлагает открыть файл через меню, рабочая область свободна. Чтение выбранного файла через File API, разбор JSON и модули адаптера на TypeScript выполняются в Web Worker. Полное дерево БД остаётся в Worker; основной поток получает каталог, требования и связи, индекс локализации RU/EN. Генератор и обогащение не запускаются, игровые источники не читаются, кнопка обновления БД пока отсутствует. Просмотр готовой БД работает без Python-службы.

В [ТЗ открытия БД](TZ_DATABASE_OPENING_RU.md#состояния-интерфейса) определены пять состояний: БД не открыта, загрузка, готово, пустой каталог и ошибка. Загрузка показывает текущий этап без процентов и поддерживает отмену. Отмена диалога выбора сохраняет текущую БД; выбор нового файла завершает старый Worker и удаляет прежние данные. Ошибка или отмена новой загрузки не восстанавливает прежнюю БД. При успехе новые технологии показываются в основных вариантах с верхнего левого угла, язык, тема и состояние меню сохраняются. Повтор обработки того же файла выполняется явно; устаревшие сообщения Worker игнорируются.

## Простой дизайн и атомарная структура

Первый этап использует максимально простой дизайн: читаемый текст, понятные границы элементов, базовые отступы и две темы. Визуальное усложнение относится к последующим этапам.

Интерфейс строится по принципам атомарного дизайна. Переиспользуемые UI-элементы описываются в UI-ките; составные элементы и виды собираются из них. Поведение и оформление повторяющихся элементов задаются в одном месте.

Предварительное разложение для будущего ТЗ:

| Уровень | Состав |
| --- | --- |
| Общие настройки оформления | Цвета дневной и ночной темы, типографика, отступы, границы |
| Базовые элементы | Текст, иконка, кнопка, элемент выбора |
| Составные элементы | Выбор языка, переключатель темы, карточка технологии, общий тултип |
| Области интерфейса | Панель меню и прокручиваемое поле технологий |
| Вид | Основное окно, собранное из областей и элементов UI-кита |

Конкретные имена компонентов, структура исходников и библиотека интерфейса определяются при подготовке ТЗ. Разделение должно оставаться соразмерным простому первому экрану.

Кнопка допускает необязательные текст и иконку, а также видимую или скрытую границу; пункт меню может использовать этот же элемент. [ТЗ кнопки](elements/TZ_BUTTON_RU.md) описывает необязательную привязку к общему [элементу «Тултип»](elements/TZ_TOOLTIP_RU.md), который также используется для описания технологии. Общие правила размещения и оформления находятся в ТЗ тултипа; условия его показа определяются использующим компонентом.

[Элемент выбора](elements/TZ_SELECT_RU.md) на первом этапе представляет собой выпадающий список с одним выбранным значением. Набор вариантов, идентификаторы их подписей и текущее значение передаются использующим компонентом; результат выбора возвращается ему.

## Локализованные строки

В [элемент «Текст»](elements/TZ_TEXT_RU.md) передаются источник и идентификатор строки. По умолчанию источник встроенный: интерфейсные строки хранятся в отдельных локализованных файлах, а настройка языка приложения определяет используемый файл. Вторым источником может быть БД приложения: названия и описания объектов уже находятся в её `enrichments.localization` для RU и EN.

Общий механизм локализации получает три значения: источник, ID строки и текущий язык. Компоненты передают источник и ID с возможностью опустить встроенный источник; язык предоставляет система из состояния приложения. Это правило распространяется на подписи кнопок и настроек, варианты выбора, тултипы и названия действий для средств доступности. Смена языка обновляет отображаемые строки для прежних пар источник/идентификатор.

По [ТЗ общего механизма локализации](TZ_LOCALIZATION_RU.md) отдельная конфигурация источников описывает расположение записей, выбор языка, сопоставление ID и получение текста. Два небольших обработчика читают JSON-словари интерфейса и обогащённые узлы БД, подготавливая индекс в памяти `источник → язык → ID строки`. Для БД ID берётся из `requested_key`, содержимое — из `text`. Вызывающая сторона передаёт ID строки без дополнительного выбора `name` / `description`.

Повторы ID с одинаковым текстом объединяются с сохранением происхождения. Разные тексты под одним ID и языком являются блокирующей ошибкой подготовки данных, требующей ручного разбора; готовый результат не публикуется. Записи индекса имеют состояния `resolved` и `missing`. Отсутствие строки показывается маркером `⟦ID строки⟧`, найденный пустой текст остаётся пустым. Пропуски вместе с одним однозначным текстом дают `resolved` с сохранением всех исходных записей. Автоматической подмены языка нет. Смена языка использует готовый индекс, замена источника перестраивает его часть индекса.

Встроенные строки хранятся в JSON-файлах RU/EN и могут содержать именованные параметры, например `{number}` для суффикса варианта. Текст БД выводится как есть: игровая разметка и подстановки сохраняются без обработки. Локализованные строки задают содержимое, словарь оформления — цвета и шрифты. Полная схема конфигурации, API и загрузка ресурсов требуют проектирования реализации; существующее хранение переводов в БД сохраняется.

## Словарь цветов и шрифтов

Цвета и шрифтовые параметры интерфейса задаются в отдельном централизованном словаре оформления по [ТЗ словаря цветов и шрифтов](TZ_STYLING_DICTIONARY_RU.md). Словарь хранится в CSS-файлах с двумя уровнями переменных: общими определениями и собственными переменными элементов. UI-элементы обращаются к своим однозначно именованным переменным; конкретные значения и связи между переменными назначаются в словаре. Цветовые литералы и значения шрифтов не дублируются в компонентах или видах.

Имя переменной отражает элемент, назначение свойства и, когда применимо, состояние. Для каждого элемента описываются используемые цвета фона, текста, иконок и границ, а также шрифтовые параметры: семейство, размер, насыщенность и межстрочный интервал. Учитываются состояния, которые действительно есть у элемента: обычное, наведение, фокус, нажатие, выбор, недоступность. Лишние состояния и переменные заранее не добавляются.

Примеры назначения переменных с префиксом `--sttv-`; полный перечень имён предстоит определить при проектировании реализации:

| Переменная | Назначение |
| --- | --- |
| `--sttv-tech-card-background-default` | Фон карточки в обычном состоянии |
| `--sttv-tech-card-background-hover` | Фон карточки при наведении |
| `--sttv-tech-card-title-color` | Цвет названия технологии |
| `--sttv-tech-card-title-font-family` | Семейство шрифта названия технологии |
| `--sttv-tech-card-title-font-size` | Размер шрифта названия технологии |
| `--sttv-tooltip-text-color` | Цвет текста тултипа |

Компонент выбирает переменную по своему состоянию, словарь определяет её значение для действующей темы. Дневная и ночная темы предоставляют полный набор используемых переменных; совпадающие значения, в том числе шрифтовые, могут ссылаться на общие определения.

Общие переменные задают переиспользуемые значения. Например, собственная переменная фона карточки ссылается на общий фон поверхности, а переменная шрифта названия — на общий шрифт интерфейса. Даже при одинаковом оформлении разных элементов их собственные переменные остаются раздельными. Совпадающие значения элементов и состояний явно связываются с общими определениями; уникальные значения задаются в словаре соответствующего элемента.

На первом этапе семейство, размер, насыщенность и межстрочный интервал каждой текстовой роли одинаковы в обеих темах. Выбран Inter с кириллицей и латиницей; файлы шрифта и лицензия включаются в portable-сборку для локальной загрузки. Согласованы нейтральные серые фоны и приглушённый зелёный акцент: [палитры](TZ_STYLING_DICTIONARY_RU.md#согласованная-палитра) и [типографика](TZ_STYLING_DICTIONARY_RU.md#шрифты-и-текстовые-роли) приведены в ТЗ словаря. Области науки различаются заголовками. Общие определения, значения дневной и ночной темы и назначения элементов разделяются по CSS-файлам; назначения элементов распределяются по небольшим файлам.

Таким образом, изменение темы или общего оформления выполняется через словарь; составные компоненты и виды продолжают использовать те же UI-элементы и имена переменных.

## Основное окно

[Основное окно](elements/TZ_MAIN_WINDOW_RU.md) занимает доступную область приложения. Внизу на всю ширину расположена [панель состояния](elements/TZ_STATUS_PANEL_RU.md), над ней — левая панель меню и [рабочая область просмотра технологий](elements/TZ_TECHNOLOGY_VIEWPORT_RU.md) справа. Меню и рабочая область занимают оставшуюся высоту окна. Рабочая область управляет видимой частью поля и прокруткой; размещение карточек по строкам и столбцам определяет само поле технологий.

Окно собирает готовые элементы UI-кита и связывает их с общим состоянием. При отсутствии восстановленного состояния используются русский язык, ночная тема, раскрытое меню, основные версии технологий и верхний левый угол поля. Предоставленное восстановленное состояние имеет приоритет; механизм сохранения между запусками проектируется отдельно. Смена языка и темы обновляет весь интерфейс, включая открытые всплывающие элементы, сохраняя выбор технологий, состояние меню и допустимые смещения.

- Панель меню остаётся на месте при прокрутке технологий.
- Рабочая область занимает всё пространство справа от панели.
- Вертикальная полоса прокрутки располагается справа от рабочей области, горизонтальная — снизу. Каждая появляется при переполнении соответствующего направления.
- При изменении размеров окна меняется видимая часть поля; размеры карточек и их заданное расположение сохраняются.
- При прокрутке к левому краю столбец `Level-0` начинается возле панели с небольшим отступом. Поле выровнено слева; изменение размеров окна и сворачивание меню не создают пустого пространства перед этим столбцом.

Начальная позиция просмотра по умолчанию — верхний левый угол; переданное восстановленное состояние имеет приоритет с учётом допустимых границ. Смена языка или темы, изменение размеров окна, сворачивание и раскрытие меню сохраняют текущие допустимые смещения прокрутки. Если смещение выходит за новые границы, оно ограничивается ближайшим допустимым значением по соответствующей оси; при исчезновении переполнения это ноль. Сохранение позиции между запусками предстоит обсудить в рамках общего механизма состояния.

[Полосы прокрутки](elements/TZ_SCROLLBAR_RU.md) имеют общее поведение для двух направлений: дорожка и ползунок, настраиваемая толщина и минимальная длина ползунка, размер ползунка по доле видимого содержимого. Полосы остаются видимыми при переполнении и не перекрываются. Поддерживаются перетаскивание и нажатие на дорожку для перемещения примерно на размер видимой области; колесо над рабочей областью прокручивает вертикально, `Shift` + колесо — горизонтально. Полоса доступна через `Tab`; в фокусе стрелки её оси прокручивают малыми шагами, `Home` / `End` переходят к началу или концу оси. Размеры и смещение предоставляет контейнер, которому передаются изменения. Дорожка и состояния ползунка оформляются переменными словаря с сохранением геометрии при смене состояния.

Собственные цвета окна и фон рабочей области задаются соответствующими переменными словаря для каждой темы; вложенные элементы используют свои роли оформления. Тултипы и списки выбора находятся поверх содержимого, не обрезаются границами вложенных контейнеров и учитывают видимые границы окна, не изменяя основную раскладку и диапазоны прокрутки поля.

## Панель меню

На первом этапе в [панели меню](elements/TZ_MENU_PANEL_RU.md) две настройки: выбор языка и переключение дневной/ночной темы. Сворачивание панели является отдельным действием управления окном.

Панель разделена на основное содержимое сверху, где группа действий с БД расположена над выбором языка, и нижнюю группу кнопок сворачивания и переключения темы. Ширина раскрытой панели и внутренние отступы задаются настройками; панель занимает доступную высоту над панелью состояния. Фон и граница с рабочей областью оформляются через словарь обеих тем, вложенные элементы используют свои ТЗ.

[Кнопка сворачивания/раскрытия](elements/TZ_MENU_TOGGLE_RU.md) использует стрелку влево для сворачивания и вправо для раскрытия, без видимой текстовой подписи, с локализованным тултипом. Её размер сохраняется, и кнопка доступна внизу панели в обоих состояниях. При первом запуске меню раскрыто; восстановленное состояние имеет приоритет. Сохранение состояния между запусками относится к общему механизму приложения.

В раскрытом состоянии:

- В панели доступен выбор русского или английского языка.
- Над выбором языка показаны действия текущего состояния: «Открыть БД»; при загрузке — «Отменить»; при ошибке — «Повторить» и «Открыть БД».
- Кнопка сворачивания расположена внизу панели.
- Кнопка переключения темы находится рядом с ней, правее.

В свёрнутом состоянии:

- Панель сохраняется как узкая полоса шириной с кнопку раскрытия и минимальными отступами.
- Кнопка раскрытия остаётся внизу.
- Действия с БД, выбор языка и кнопка темы скрываются; для действий пользователь раскрывает меню. Панель состояния остаётся видимой.
- Рабочая область расширяется на освободившееся место; действующие язык и тема сохраняются при сворачивании и раскрытии панели.

Если основное содержимое меню не помещается по высоте, только эта область прокручивается вертикально и независимо от поля технологий. [Нижняя группа кнопок](elements/TZ_MENU_BUTTON_GROUP_RU.md) находится вне прокручиваемого содержимого и остаётся доступной внизу панели.

Кнопки нижней группы выровнены по правому краю панели с небольшим отступом и образуют одну строку: сворачивание слева, тема сразу справа. Они имеют одинаковые настроенные размеры и не растягиваются вслед за панелью. При сворачивании место и промежуток под кнопку темы не резервируются; размер кнопки меню и высота группы сохраняются. Фон группы общий с панелью, кнопки используют собственное оформление. Их тултипы могут выходить за границы группы и панели без обрезания, оставаясь в видимых границах окна.

## Панель состояния

[Панель состояния](elements/TZ_STATUS_PANEL_RU.md) — отдельный составной элемент UI-кита с элементом «Текст». Она постоянно видима внизу окна на всю ширину, занимает собственное место под меню и рабочей областью, не участвует в их прокрутке и не перекрывает полосы прокрутки. Сворачивание меню не меняет её ширину.

На первом этапе панель содержит одно короткое локализованное сообщение о текущем состоянии или этапе загрузки. Сообщение «Готово» использует фактическое число базовых технологий из каталога. Действия остаются в меню; рабочая область показывает поле только в состоянии «Готово», в остальных состояниях свободна и не дублирует сообщения. Цвета и шрифты панели задаются собственными переменными словаря оформления.

## Поле технологий

Согласованные требования собраны в отдельном [ТЗ поля технологий](elements/TZ_TECHNOLOGY_FIELD_RU.md).

[Адаптер БД](TZ_DATABASE_ADAPTER_RU.md) подготавливает в памяти каталог по базовым ID: уровень, дерево `prerequisites`, массив представлений и ссылку на исходный узел. Представление содержит собственный ID, итоговую область науки и ID строк названия и описания; варианты имеют номер в исходном порядке. Отдельный обработчик требований вычисляет непосредственных предшественников, число требований и связи. Поле отвечает за группировку и размещение, состояние приложения — за выбор представлений. Исходная БД сохраняется без изменений.

Поле разделено на три области сверху вниз: **физика** (`physics`), **социология** (`society`), **инженерия** (`engineering`). Область каждой карточки определяется её текущим представлением; межобластные зависимости сохраняются, не меняя порядок областей науки.

[Область науки](elements/TZ_RESEARCH_AREA_RU.md) — контейнер с заголовком и переданными полем упорядоченными столбцами. Заголовок использует общий элемент «Текст» и встроенную локализацию RU/EN, расположен над столбцами слева по краю `Level-0`. Ширина области равна ширине поля, высота определяется самым высоким столбцом с учётом заголовка и отступов. Области различаются заголовками и настраиваемыми вертикальными промежутками; следующая начинается ниже завершившейся предыдущей. Заголовок прокручивается вместе с областью. Цвета и шрифты задаются собственными переменными словаря, которые могут ссылаться на общие значения темы.

В каждой области столбцы соответствуют полю `tier`: слева направо `Level-0`, `Level-1`, …, `Level-5` для текущих данных игры. Столбцы выровнены между областями. Карточки одного столбца располагаются одна под другой.

[Столбец уровня](elements/TZ_TIER_COLUMN_RU.md) получает готовый порядок карточек от поля. Заголовок «Уровень N» / «Level N» использует общий элемент «Текст» и встроенную локализацию, выровнен слева по карточкам и повторяется в каждой области. Ширина всех столбцов одинакова и соответствует карточке; заголовки и начало списков выровнены по высоте внутри области, вертикальный промежуток между карточками настраивается. Пустой столбец сохраняет ширину, позицию и заголовок. Заголовок прокручивается вместе с карточками; цвета и шрифты столбца и заголовка задаются собственными переменными словаря.

Текущий подход — расположение связанных технологий облаком: близость по зависимостям помогает размещать карточки рядом, без обязательной линейной строки на каждую цепочку. Ручное определение семейств технологий будет проработано отдельно.

Вертикальный порядок внутри столбца одной области науки подчиняется следующим правилам:

- Предшественник из `prerequisites`, находящийся в том же столбце и области, располагается выше зависимой технологии; правило действует для всей последовательности зависимостей.
- С соблюдением этих зависимостей выше располагаются технологии с меньшим числом технологических требований.
- Для подсчёта используются только требования к технологиям из `prerequisites`: отдельная обязательная технология даёт одно требование, одновременно обязательные технологии суммируются, группа альтернатив `OR` считается одним требованием. При отсутствии технологических требований число равно нулю.
- Условия по DLC, государству, виду, зданиям и прочие ограничения в этот подсчёт не входят.
- При равенстве числа требований технологии с одинаковым набором непосредственных предшественников размещаются подряд; внутри группы применяется стабильный порядок по базовым ID. Приоритет технологических зависимостей сохраняется. Межобластные зависимости не переставляют области науки.

Набор непосредственных предшественников включает ID технологий из `prerequisites`, в том числе участников альтернатив, и не зависит от порядка перечисления. Он отличается от числа требований: обязательные `A` и `B` дают два требования, а `OR` из тех же технологий — одно. Смена языка не меняет группировку и порядок карточек.

В первом интерфейсе по решению пользователя линии связей не рисуются. Порядок между группами описан в [руководстве реализации](FRONTEND_STAGE_1_RU.md#детали-отображения); отдельное выравнивание связанных групп между столбцами относится к дальнейшему проектированию.

## Карточка и тултип

На первом этапе [карточка технологии](elements/TZ_TECHNOLOGY_CARD_RU.md) содержит только название на выбранном языке. Все карточки имеют одинаковые настроенные ширину и высоту; изменение окна, языка или наведение не меняют их размеры. Название центрировано по обеим осям, переносится по словам максимум на две строки и получает многоточие только при переполнении.

При наведении на любую часть карточки, включая внутренние отступы, появляется общий [тултип](elements/TZ_TOOLTIP_RU.md) с полным названием в заголовке и описанием под ним на том же языке. При уходе указателя он скрывается. Пока открыт список вариантов этой карточки, её тултип скрыт. Ограничение названия в карточке двумя строками на тултип не распространяется. Тултип находится поверх содержимого, не сдвигает карточки и размещается с учётом границ видимой области.

Карточка получает источник БД и ID строк названия и описания выбранного представления; язык предоставляет система, поиск выполняется по общей конфигурации источника. Обычное состояние и наведение оформляются через словарь цветов и шрифтов, наведение визуально выделяет карточку. Область науки, столбец и вертикальную позицию назначает поле технологий.

У технологий с `technology_swap` поддерживается [ручной выбор представления](elements/TZ_TECHNOLOGY_CARD_RU.md#ручной-выбор-варианта) отдельно для каждой карточки. По умолчанию отображается основная версия; нажатие открывает выбор основной версии и вариантов из БД. Выбор обновляет название и описание, сохраняя базовый ID, `tier` и технологические связи. Если вариант задаёт другую область науки, поле переносит карточку в неё. Выбор сохраняется при смене языка и темы; сохранение между запусками относится к отдельному проектированию общего состояния.

Варианты с одинаковыми названиями остаются отдельными значениями выбора. В списке к совпадающим названиям вариантов добавляются [суффиксы «(Вариант N)» / «(Variant N)»](elements/TZ_TECHNOLOGY_CARD_RU.md#подписи-вариантов); номер определяется порядком блоков `technology_swap` в БД и не зависит от языка. Основная версия остаётся без суффикса. Шаблон суффикса берётся из встроенной локализации, исходные строки БД не меняются. Автоматический выбор по условиям государства рассматривается на последующих этапах.

[Список вариантов](elements/TZ_TECHNOLOGY_CARD_RU.md#работа-со-списком-вариантов) использует общий элемент выбора: основная версия первая, далее варианты в порядке БД; текущий выбор отмечен. Выбор пункта применяет вариант и закрывает список. Нажатие вне списка или `Escape` закрывает его без изменения выбора. С карточки в фокусе `Enter` / `Space` открывают список, стрелки перемещают фокус между пунктами, `Enter` подтверждает выбор; перемещение фокуса само по себе вариант не применяет.

Ванильные изображения из общего концепта остаются возможностью последующих этапов; текущий состав карточки ограничен названием.

## Язык и тема

[Выбор языка](elements/TZ_LANGUAGE_SELECTOR_RU.md) состоит из подписи «Язык» / «Language» и выпадающего списка «Русский» (`ru`) / «English» (`en`). Выбор сразу меняет язык интерфейса, названий технологий и описаний в тултипах по [общим правилам локализованных строк](#локализованные-строки). Источником текстов технологий служит готовая локализация БД. При сворачивании меню действующий язык сохраняется.

[Переключатель темы](elements/TZ_THEME_TOGGLE_RU.md) — кнопка с иконкой и тултипом без видимой текстовой подписи. Солнце предлагает включить дневную тему, луна — ночную. Переключение сразу меняет оформление всего интерфейса, включая меню, карточки и тултипы. Значения для обеих тем задаются в отдельном [словаре цветов и шрифтов](#словарь-цветов-и-шрифтов) UI-кита.

При первом запуске используются русский язык (`ru`) и ночная тема; восстановленный выбор пользователя имеет приоритет. Сохранение между запусками относится к общему механизму, описанному ниже.

## Сохранение настроек и состояния

Пользователь планирует сохранять между запусками множество настроек и данных состояния приложения. Общий механизм сохранения и восстановления требует отдельной проработки и отдельного ТЗ; его согласованные применения включают язык, тему, раскрытое/свёрнутое состояние меню, выбранные представления технологий и позицию просмотра поля.

UI-элементы получают текущее значение и сообщают об изменениях использующему компоненту. Работа с постоянным хранилищем относится к уровню приложения. Эти границы позволяют обсуждать требования к элементам параллельно с отдельным проектированием сохранения.

При проработке механизма необходимо определить состав сохраняемых данных, моменты записи, порядок восстановления, формат и расположение хранилища, а также взаимодействие с остальными частями приложения. Конкретный способ хранения, включая ранее обсуждавшийся пример JSON-файла, ещё не выбран.

## Дальнейшее проектирование

Перед реализацией отдельное ТЗ должно определить:

- Порядок между разными группами с равным числом требований и размещение связанных групп в соседних столбцах при согласованной группировке по предшественникам; последующую ручную группировку семейств и отображение линий связей.
- Оставшиеся детали ручного выбора вариантов технологии: обозначение наличия вариантов, геометрия и размещение списка, начальный и возвращаемый фокус.
- Программную форму данных и API модулей адаптера, вложенные данные сообщений согласованного протокола Worker и диагностику открытия и преобразования. Валидация создаваемой БД остаётся на бэкэнде по [разделению ответственности](TZ_DATABASE_OPENING_RU.md#ответственность-за-проверки); фронтенд её не дублирует.
- Отдельное ТЗ общего механизма сохранения и восстановления настроек и состояния между запусками.
- Структуру компонентов UI-кита, конкретные размеры и минимальное оформление обеих тем.
- Точные CSS-файлы словаря в `src/frontend/styles/`, файлы Inter в `src/frontend/assets/` и порядок их подключения; полный перечень имён переменных элементов и состояний и назначения в обеих темах на основе согласованных палитр и типографики.
- Размеры и отступы группы действий в меню и панели состояния, идентификаторы сообщений, встроенный просмотр диагностики и обработку некорректных параметров шаблона; поведение состояний открытия и замены БД закреплено в ТЗ запуска, правила отсутствия и конфликтов строк — в ТЗ локализации.
- Проверки раскладки, прокрутки, сворачивания меню, языка, темы и тултипов.
