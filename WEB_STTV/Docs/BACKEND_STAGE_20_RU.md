## Результат

Реализовано [ТЗ этапа 20](TZ_BACKEND_STAGE_20_RU.md). Python рассчитывает видимость технологий по выбранным DLC, затем выбирает родителей только среди видимых кандидатов. Неизвестные условия империи и событий не превращаются в запрет.

Подготовленный набор: `data/stage20/database_set/manifest.json`. Он получен из полного набора этапа 19 без повторного парсинга игры. Сохраняются 25 видов БД, 543 документа, 679 технологий и их исходные данные; старый набор этапа 19 не изменён.

| Профиль | Видимых | Скрытых | Расчёт Python, с |
| --- | ---: | ---: | ---: |
| Все DLC | 678 | 1 | 60,023 |
| Ни одного DLC | 543 | 136 | 63,233 |
| `dlc002`, `dlc036` | 544 | 135 | 63,621 |
| Повтор первого профиля | 678 | 1 | 11,057 |

В трёх профилях нет неоднозначного выбора родителя. Повтор использовал готовую комбинацию и не записал документы. Это время операции Python в заключительном прогоне, без загрузки и отрисовки браузером; параллельно выполнялись синтетические проверки, поэтому это не отдельный сравнительный тест производительности. Отчёты: `data/stage20/dlc_{all,none,mixed,all_reused}_report.json`. Первый прогон сохранён в `data/stage20/firstpass/`.

## Запуск

Из корня репозитория, в отдельном терминале PowerShell:

```powershell
$env:PYTHONPATH = (Resolve-Path WEB_STTV/src/backend).Path
WEB_STTV/data/.venv/Scripts/python.exe -X utf8 -B -m sttv.service
```

Сервис слушает `127.0.0.1:8765`; Vite перенаправляет `/api/sttv` с адреса интерфейса. Запуск сервиса сам по себе не собирает и не обогащает БД. Для остановки — Ctrl+C.

Конфигурация — `config/service.json`; другой файл передаётся `--config <путь>`. Поле `variables` указывает на `data/stage20/variables.json`, где `WORK_DIR` равен `data/stage20`. `config/storage.json` определяет относительное размещение набора. При выборе другого набора изменить конфигурацию и перезапустить сервис. Пути конфигурации ограничены репозиторием; браузер не передаёт абсолютные пути.

Публичная Python-функция `sttv.enrichment.technology_tree.enrich_technology_tree` принимает `dlc_enabled=None` для всех DLC либо список ID. Если аргумент не передан, выполняется обычное обогащение подготовленной комбинации без DLC-фильтра. `variants` сохраняет явно выбранные представления. Это не запуск парсера.

## Правила и хранение

`config/enrichment/dlc.json` содержит поддерживаемые предикаты, константы, прозрачные обёртки и поля веса. В `config/enrichment/technology_tree.json` задана ссылка на него. Соответствие ID и технического имени DLC берётся из БД `dlcs`.

Вычислитель различает `true`, `false`, `unknown`. Для доказательства DLC-причины он сравнивает условие с результатом при неизвестных состояниях DLC. Самостоятельный `weight = 0` или независимый `always = no` не является причиной скрытия этим фильтром. Неподдерживаемые действия веса сохраняют неопределённость; вероятность появления не вычисляется.

Комбинация `dlc_<hash>` зависит от выбранных DLC, справочного профиля и вариантов. Метаданные сохраняют ревизии исходных наборов, правил, реализации и результата. В каждом результате технологии находятся `visibility`, причины и доказательства, `parent_tech`, `children`, `status`. Скрытые технологии остаются в БД без связей текущей комбинации. Если видимая технология потеряла всех кандидатов, она становится корнем с `no_visible_parent`; исходные пререквизиты сохраняются.

Меняются только документы технологий. Новые версии файлов неизменяемы; манифест переключается атомарно. Неизменившиеся файлы переиспользуются. Отмена проверяется до публикации; публикация и принятие отмены согласованы общей блокировкой. После завершённой публикации результат считается завершённым.

## Сервис и снимки

Модули: `sttv/enrichment/dlc`, `sttv/service`, интеграция в `sttv/enrichment/technology_tree`. Новые схемы `dlc.schema.json` и `service.schema.json` генерируются общим генератором; расширены схемы комбинаций, ресурсов и конфигурации изображений.

Основные маршруты относительно `/api/sttv`:

| Метод и путь | Назначение |
| --- | --- |
| `POST /connect` | Проверить `setId`/`snapshotRevision`, создать сессию |
| `POST /operations` | Применить `enabled` и `baseCombinationId` к указанной ревизии |
| `GET /operations/{id}` | Получить состояние и результат |
| `POST /operations/{id}/cancel` | Запросить отмену |
| `GET /snapshots/{revision}/manifest` | Получить согласованный манифест |
| `GET /snapshots/{revision}/documents/{kind}/{document_id}` | Прочитать объявленный документ |
| `GET /snapshots/{revision}/images/{hash}` | Прочитать объявленное изображение |

Сессионный токен передаётся заголовком `X-Sttv-Session`. Обрабатывается один расчёт одновременно. Неизвестный ресурс, чужой Origin, несовпадение набора и устаревшая ревизия диагностируются. Запросы не запускают команды и не позволяют выбрать произвольный файл. Полные отчёты операций сохраняются в `WORK_DIR/reports/dlc/`; основной отчёт обогащения остаётся по пути его конфигурации.

Фронтенд получает новый манифест и читает изменившиеся документы потоком через API с проверкой хеша. Старые объекты `File` не подменяются новыми байтами. Неизменившиеся каталоги и проверенные изображения сохраняются в памяти.

## Изображения

`config/enrichment/assets.json` задаёт `dlc_thumbnails`: поле `thumbnail` и переменную `DLC_DIR`. Путь разрешается относительно соответствующего DLC-описателя и ограничивается каталогом дополнений. Используется существующая конвертация в PNG и реестр ресурсов; в `presentation.dlc_icons` хранится соответствие ID DLC и ресурса.

Для 36 строк каталога подготовлены 32 миниатюры; у `dlc001`, `dlc003`, `dlc010`, `dlc011` нет подходящей миниатюры. Они остаются в списке с заглушкой. Получилось 822 уникальных изображения; 805 прежних обращений к изображениям обслужены из кеша, 32 исходника сконвертированы. Документы БД при подготовке изображений не переписаны.

## Проверки

Прошли 94 проверки модулей обогащения/хранения и 3 проверки генерации схем. Полный аудит проверил 543 документа и 822 изображения; после заключительного пересчёта повторно проверены 35 документов технологий и все изображения, а неизменность остальных 508 дескрипторов подтверждена сравнением. Итоги: `full_audit.json`, `post_recalculation_audit.json`.

Синтетические проверки охватывают трёхзначную логику, отрицание и обёртки, независимые запреты, нулевые модификаторы, неизвестные DLC, исключение родителей, неизменность источников, повторное использование, отмену, атомарную публикацию и ограничения API. Результаты браузерных проверок описаны в [руководстве интерфейса](frontend/FRONTEND_STAGE_10_RU.md#проверки).

Отчёты и журналы приёмки находятся в `data/stage20/`. Проверка не моделирует выполнение условий движком Stellaris и не определяет владение DLC в Steam. Файлы игры не менялись.

После приёмки подтверждён пробел покрытия: DLC-зависимость через `uses_ship_category` и определения наборов кораблей остаётся неизвестной, поэтому оружие ткачей видно без BioGenesis. Результаты проверок выше не подтверждают полноту косвенных ограничений. Рекурсивный анализ таких связей предложен в [проекте этапа 21](TZ_BACKEND_STAGE_21_RU.md).
