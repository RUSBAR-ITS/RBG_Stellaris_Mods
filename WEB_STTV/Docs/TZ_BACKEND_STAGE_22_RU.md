## Цель и источники

**Утверждено и реализовано 2026-11-20.** Первый импорт на тестовый сервер формирует в базе `wiki` коллекцию `localization`. Её содержимое определяется всеми игровыми строками из настроенных источников RU и EN, включая строки, к которым справочник пока не обращается. Встроенные переводы интерфейса обслуживает фронтенд. [Запуск и результаты проверки](BACKEND_STAGE_22_RU.md)

Порядок источников и параметры чтения берутся из [конфига локализации](../config/enrichment/localization.json), расположение каталогов — из [глобальных переменных проекта](../global_variables.json). Используется [существующий читатель](../src/backend/sttv/enrichment/localization/reader.py). Для каждого языка он рекурсивно читает `*.yml` и извлекает определения из секций с соответствующим заголовком.

| Язык | Источники от высшего приоритета к низшему |
| --- | --- |
| `ru` | `RU_LOC_TIER_1` — `replace` мода Russian Localization Fix RE → `RU_LOC_TIER_2` — основной перевод мода → `RU_LOC_TIER_3` — ванильный русский |
| `en` | `EN_LOC_TIER_1` — ванильный английский |

## Документ локализации

Один документ содержит один ключ на одном языке. При записи и поиске по составному `_id` первым полем идёт `language`, вторым — `key`. Ключ сохраняет исходный регистр. Описание с суффиксом `_desc` имеет собственный документ. Если перевод существует только на одном языке, создаётся только имеющийся документ.

```json
{
  "_id": { "language": "ru", "key": "tech_titans" },
  "selected": 0,
  "definitions": [
    { "tier": "RU_LOC_TIER_2", "file": "technology_l_russian.yml", "line": 51, "raw": "Титаны" },
    { "tier": "RU_LOC_TIER_3", "file": "technology_l_russian.yml", "line": 47, "raw": "Титаны" }
  ]
}
```

`definitions` хранит каждое вхождение. `file` — путь относительно каталога соответствующего `tier` с разделителем `/`, `line` — номер строки начиная с 1. `raw` хранит содержимое внешних кавычек в исходной записи, включая пустую строку, буквальные escape-последовательности, ссылки `$KEY$`, динамические подстановки и игровую разметку. Раскрытие ссылок относится к последующему обогащению.

## Выбор перевода

1. Для пары `(language, key)` собрать все определения. Упорядочить по приоритету из конфига, внутри одного приоритета — по относительному пути и номеру строки. Сохранить также вхождения с одинаковым текстом.
2. Выбрать высший приоритет, в котором найден ключ. Если на этом уровне у всех определений одно значение `raw`, записать в `selected` индекс первого такого определения с отсчётом от нуля. Потребитель получает текст через `definitions[selected].raw`.
3. Разные значения `raw` на выбранном уровне образуют конфликт. Указать в отчёте язык, ключ, приоритет и координаты определений. Такой набор не публикуется. Расхождения на перекрытом уровне сохраняются в документе и отмечаются в отчёте. Это сохраняет действующие [правила выбора перевода](../src/backend/sttv/enrichment/localization/index.py).

## Подготовка и загрузка

Подготовка запускается на Windows, где установлена игра. Она формирует в рабочем каталоге JSON с переносами строк и отчёт с количеством файлов, определений, документов и конфликтов по языкам и приоритетам. Пакет можно загрузить повторно без чтения игровых файлов.

Загрузка запускается явной командой с этой машины напрямую в MongoDB по TLS от имени `wiki`. Адрес, база, коллекция и ссылки на пароль и публичный сертификат центра сертификации в Vault задаются конфигурацией. Секреты подключения обрабатываются в памяти.

Загрузчик записывает документы пакетами и публикует полный словарь после проверки. Повторная загрузка того же набора даёт те же документы. При загрузке изменённого набора исчезнувшие из всех источников ключи исчезают из словаря. При ошибке подготовки или записи предыдущий полный словарь остаётся доступным. Операция ограничена коллекцией локализации. Сброс всей БД — отдельная административная операция.

## Приёмка

Базовые значения получены при чтении настроенных источников 2026-11-20. При обновлении исходников ожидаемые значения рассчитываются заново.

| Источник | Файлов | Определений |
| --- | ---: | ---: |
| `RU_LOC_TIER_1` | 9 | 2 167 |
| `RU_LOC_TIER_2` | 233 | 149 404 |
| `RU_LOC_TIER_3` | 232 | 151 952 |
| `EN_LOC_TIER_1` | 232 | 150 258 |
| **Всего** | **706** | **453 781** |

- Сверить опубликованные документы с подготовленным JSON по составному ключу, определениям и `selected`. Эталон содержит 303 500 документов, в том числе 153 242 RU и 150 258 EN. Только на русском присутствуют 2 984 ключа.
- Прочитать `tech_titans` на обоих языках. В RU выбран `Титаны` из `RU_LOC_TIER_2`, в EN — `Titans` из `EN_LOC_TIER_1`. Проверить также ключ описания, строку с подстановкой и ключ, существующий только на русском.
- Для RU в эталоне 13 ключей с разным текстом внутри ванильного приоритета. Все они перекрыты вышестоящими переводами. На синтетическом наборе отдельно проверить одинаковые повторы, конфликт на выбранном уровне и пустой текст.
- Проверить повторную загрузку, исчезновение ключа после обновления источника и ошибку в середине загрузки. Сопоставить результат чтения с ожидаемым полным словарём в каждом случае.
