## Проверки

Таблица ограничена контекстами, нужными для текущего анализа. Она не перечисляет все поддерживаемые движком scopes.

| Ключ | Контекст и значение | Игровое назначение | Использование и границы | Источники |
| --- | --- | --- | --- | --- |
| `is_nomadic` | Государство; `yes` / `no` | Проверяет кочевую империю. | Различение кочевых и обычных путей технологий. Учитывать отрицания и альтернативы целиком. | C1 |
| `uses_ship_category` | Государство; ID категории кораблей | Проверяет используемую категорию кораблей, например `bio_ship`. | Различение биологических и обычных корабельных ветвей. Категория кораблей не равна научной `category`. | C2 |
| `has_ethic` | Здесь государство; ID этики | Проверяет наличие конкретной этики. | Сопоставление ограничений; `ethic_gestalt_consciousness` относится к принятому профилю. Другие этики не назначаются автоматически. | C3, C7 |

| `is_archetype` | Вид; ID архетипа | Проверяет архетип вида, например `MACHINE` или `BIOLOGICAL`. | В условиях государства сначала учитывать переход к нужному виду, например `founder_species`. | C5, C7 |

## Именованные функции

`country_uses_bio_ships` — **scripted trigger**, определённый в игровых файлах, а не отдельное базовое поле технологии. Его тело в текущей установке:

```text
country_uses_bio_ships = {
    exists = this
    uses_ship_category = bio_ship
}
```

Источник: C2. При анализе раскрытой БД следует использовать полученное тело и контекст вызова. Не нужно создавать независимое значение признака, которое могло бы противоречить `uses_ship_category`. Это пример различия между именованной функцией и встроенной проверкой; универсальная классификация по префиксу имени не применяется.

## Применение к цепочкам

- Согласованный профиль справочника: некочевая империя без гештальт-сознания, биологическое население, обычные корабли. Этика за пределами этого ограничения, происхождение и пути развития не фиксированы.
- Неизвестный параметр профиля не доказывает недоступность технологии. Наличие специального условия в одной ветке `OR` не исключает доступную альтернативу.
- Для совпадения специальных условий сохранять операторы, значения и контекст. Общие проверки вроде `exists = this` сами по себе не доказывают содержательное родство двух технологий.
- Условия доступности используются по своему месту в структуре. Условия в весах выбора исследования или ИИ не становятся ограничениями доступности.
- Для выбора предшественника согласовано [полное сравнение непустых `potential`](../frontend/CHAIN_AVAILABILITY_RU.md) после раскрытия вставок. Сопоставляются блоки целиком, а не отдельные совпавшие проверки.
- Эти записи поясняют смысл условий. Полный вычислитель империи и новый выбор предшественника этим словарём не реализованы.
