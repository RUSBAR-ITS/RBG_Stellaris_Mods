## Контейнеры эффектов

| Ключ | Контекст и форма | Назначение и использование | Источники |
| --- | --- | --- | --- |
| `modifier` | Технология; блок модификаторов | Бонусы технологии. Содержимое помогает определить, что она улучшает. | F1, F4 |
| `modifier` | Компонент; блок модификаторов | Характеристики, для которых документация предусматривает показ в конструкторе кораблей. Нельзя трактовать как модификаторы государства только по имени блока. | F2 |
| `ship_modifier` | Компонент; блок модификаторов | Воздействие на корабль. Например, укрепление брони. | F2, F3 |
| `triggered_station_modifier` | Звёздное здание; блок с `potential`, модификаторами и возможным множителем | Условное воздействие на станцию. Сохранять условие и величину; наличие ключа ещё не означает безусловный бонус. | F5 |
| `feature_flags` | Технология; список ID возможностей | Открываемые игровые возможности, например `megaengineering`. Назначение конкретного флага подтверждается местами его использования, а не догадкой по названию. | F1 |

## Экономические поля

| Ключ | Контекст и форма | Назначение и использование | Источники |
| --- | --- | --- | --- |
| `resources` | Объект; структурированный блок | Контейнер экономических параметров. Сохранять вложенные категории, стоимость, производство, содержание и условия раздельно. | F3, F6 |
| `category` | Внутри `resources`; ID экономической категории | Группа экономического учёта и модификаторов. Не научная категория технологии. | F6 |
| `produces` | Внутри `resources`; блок ресурсов и значений, иногда с условиями | Производимые ресурсы. Даёт свидетельство производственной функции объекта; блок может повторяться с разными условиями. | F6 |
| `upkeep` | Внутри `resources`; блок ресурсов и значений | Затраты на содержание. Расход кристаллов не делает объект технологией производства кристаллов. | F3, F6 |
| `cost` | Внутри `resources`; блок ресурсов и значений | Стоимость создания или действия в контексте объекта. Не равна исследовательской стоимости `technology.cost`. | F3 |

## Конкретные модификаторы

Значения в приведённых случаях числовые, в исходниках могут быть заданы через статические переменные. Модификаторы описывают характеристики и бонусы, а не технологические ссылки.

| Ключ | Что изменяет | Возможное свидетельство назначения | Источники |
| --- | --- | --- | --- |
| `ship_armor_hardening_add` | Укрепление брони корабля | Защита брони от обходящих её воздействий; родство броневых компонентов. | F3 |
| `ship_cloaking_detection_add` | Обнаружение маскировки | Общая функция модуля обнаружения и усиливающего здания. | F5, F7 |
| `planet_metallurgists_produces_mult` | Множитель производства в соответствующей экономической категории металлургов | Улучшение металлургического производства. | F4 |
| `starbase_upgrade_cost_mult` | Множитель стоимости улучшения звёздной базы | Развитие инфраструктуры базы. | F4 |
| `starbase_upgrade_speed_mult` | Множитель скорости улучшения звёздной базы | То же направление по скорости строительства. | F4 |
| `country_starbase_capacity_add` | Прибавка к вместимости звёздных баз государства | Связь с объектами, использующими этот лимит; сопоставление с их полями задаётся в конфигурации. | F1, F8 |

## Поля использования лимитов

| Ключ | Контекст и форма | Назначение и использование | Источники |
| --- | --- | --- | --- |
| `starbase_capacity_used` | Уровень звёздной базы в `starbase_levels`; число | Используемая объектом вместимость звёздных баз. Положительное значение подтверждает связь с соответствующим лимитом. Это поле объекта, а не модификатор государства. | F8, F9 |
| `ship_size` | Уровень звёздной базы; ID корпуса | Связывает определение использования лимита с корпусом из `ship_sizes`; его требования позволяют найти открывающую технологию. | F8, F9, F10 |

## Использование свидетельств

Совпадение конкретного модификатора сильнее общего сходства «относится к кораблям», но может встречаться у нескольких несмежных технологий. Это вход для согласованных критериев отбора, а не готовая связь `parent_tech`.

При сравнении необходимо сохранить контекст применения, знак и условия бонуса. Блок `modifier` внутри `weight_modifier` задаёт изменение веса выбора; он не является бонусом исследованной технологии. Модификаторы выбранного `technology_swap` следует рассматривать с учётом `inherit_effects`.

Согласованное [правило функциональных групп](../frontend/CHAIN_FUNCTIONAL_GROUPS_RU.md) описывает получение назначения из сочетаний признаков открываемых объектов. Первый пример использует `ship_sizes`, скорость и боевые роли. Это правило выбора опоры для будущей реализации, а не расширение синтаксиса парсера.

Отдельно согласовано [косвенное родство](../frontend/CHAIN_INDIRECT_AFFINITY_RU.md) через исходные пререквизиты кандидата с начальной глубиной в один переход. Пример использует `ship_armor_hardening_add` у компонентов закалки и брони; контекст и знак совпадают, величины бонуса различаются.

`feature_flags` и экономические категории содержат ID других игровых понятий. Этот словарь поясняет роль ссылки, но не заявляет, что все потребители флагов и формулы экономики уже вычислены.

Собственные производственные бонусы технологии участвуют в отдельном [критерии родства через экономическую категорию, профессии и предоставляющие их объекты](../frontend/CHAIN_PRODUCTION_AFFINITY_RU.md). Пример связывает `planet_metallurgists_produces_mult` с `resources.category` профессии `foundry` и зданием `building_foundry_2`.

Следующим согласован [критерий родства через лимиты объектов](../frontend/CHAIN_CAPACITY_AFFINITY_RU.md), непосредственно перед фильтром по империи. Пример связывает собственный бонус Мегапроектирования `country_starbase_capacity_add` с `starbase_capacity_used > 0`, затем через `ship_size` — с требованиями корпуса. Это отдельное соответствие из конфигурации, а не автоматическая трактовка любых ключей с `capacity`.
