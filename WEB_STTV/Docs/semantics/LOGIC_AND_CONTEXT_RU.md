## Логические конструкции

| Ключ или значение | Форма | Назначение в рассматриваемом контексте | Источники |
| --- | --- | --- | --- |
| `AND` | Именованный логический блок | Требует выполнения всех дочерних условий. | L1 |
| `OR` | Именованный логический блок | Требует выполнения хотя бы одного дочернего условия. Альтернативы нельзя превращать в обязательные зависимости. | L1, L2 |
| `NOT` | Именованный логический блок | Логическое отрицание. Сохранять весь блок, включая несколько дочерних записей; не обрезать его до одного узла. | L1 |
| `NAND` | Именованный логический блок | Отрицание И: не все условия выполнены. | L1 |
| `NOR` | Именованный логический блок | Отрицание ИЛИ: ни одно условие не выполнено. | L1, L3 |
| `yes`, `no` | Логические значения | Ожидаемое состояние в логической проверке. Значение `no` не превращает произвольную команду в логическое отрицание: роль определяется командой. | L1, L3 |
| `always` | Проверка с `yes` / `no` | Постоянный результат условия, независимо от параметров империи. | L4 |
| `exists` | Проверка со ссылкой на объект, например `owner` или `this` | Проверка существования указанного объекта. Не создаёт его и не переключает контекст вложенных проверок. | L3, L4 |

## Контекст объекта

Это ссылки и переходы контекста, а не самостоятельные признаки империи. У блоковой формы справа находится содержимое для обработки в указанном контексте; в скалярной форме ссылка передаётся другой конструкции.

| Имя | Назначение | Применение в анализе | Источники |
| --- | --- | --- | --- |
| `owner` | Владелец текущего объекта, если такой переход поддерживается | `owner = { has_technology = ... }` проверяет технологию владельца; `exists = owner` проверяет наличие владельца. | L3 |
| `founder_species` | Вид-основатель государства | Позволяет применить `is_archetype` к виду, не приписывая проверку архетипа непосредственно объекту государства. | L5 |
| `this` | Текущий объект в данной точке выполнения | Сохранять контекст при разборе вложенностей; не считать ссылку постоянной на всё дерево. | L3, L6 |
| `root` | Корневой объект текущей цепочки выполнения | Не заменять автоматически на владельца или текущую технологию: технология как определение не равна объекту игрового scope. | L7 |
| `from` | Объект, переданный вызывающим контекстом | Значение зависит от места вызова. В `potential` компонента документация задаёт `this` как проект корабля, `from` как государство. Это не универсальный синоним предыдущего блока. | L6 |

## Правила анализа

- Сохранять дерево, порядок и повторения условий. Именованные логические операции не совпадают со знаками сравнения или присваивания.
- В `prerequisites` встречаются списки ID технологий внутри `OR`; в обычном триггере находятся проверки. Общая форма блока не делает контексты одинаковыми.
- Этот словарь не вводит вычислитель логики. В частности, нельзя автоматически назначать семантику произвольным скалярным формам операторов или сворачивать многозаписный `NOT` без проверки контекста движка.
- Неизвестная ссылка или неизвестное условие не означают `false`. Перенос проверки через `owner`, `from` или `founder_species` меняет объект проверки и может изменить её смысл.
- `custom_tooltip` и `hidden_trigger` описаны отдельно в [разделе подсказок](TOOLTIPS_RU.md): они управляют представлением условий, а не переходом контекста.
