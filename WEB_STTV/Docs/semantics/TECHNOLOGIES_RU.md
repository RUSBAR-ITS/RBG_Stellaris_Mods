## Поля технологии

| Ключ | Форма значения | Игровое назначение и применение в анализе | Источники |
| --- | --- | --- | --- |
| `area` | Идентификатор `physics`, `society` или `engineering` | Область исследования. Определяет раздел поля и критерий общей области кандидатов. | T1, T2 |
| `category` | Список идентификаторов в блоке | Научные категории технологии. Для сравнения сохранять весь набор, а не только первое значение. | T1, T2 |
| `tier` | Целое число | Игровой уровень технологии. Основа столбца; не номер в конце ID, не стоимость и не число повторных исследований. | T1, T3 |
| `prerequisites` | Блок ID технологий и вложенных логических конструкций | Технологические зависимости. Сохранять выражение целиком; обязательность и участие в альтернативе различаются. | T4 |
| `start_tech` | `yes` / `no` | Признак стартовой технологии. Не доказывает безусловную выдачу любой империи; доступность и правила инициализации рассматриваются отдельно. Полезен для отметки стартовых карточек. | T3 |
| `levels` | Целое число; `-1` обозначает неограниченное повторение | Повторяемость исследования. Для нашего отдельного правила отображения сопоставляется с `tier` и наличием технологических требований. | T5 |
| `potential` | Блок условий | Условия, при которых технология рассматривается как доступная соответствующей империи. Используется для сравнения специальных условий и фильтра профиля; не заменяет `prerequisites`. | T6 |
| `technology_swap` | Повторяемый блок варианта | Условное представление основной технологии. Порядок блоков значим; вариант не превращается в самостоятельную исследуемую технологию. | T1, T2 |

## Поля варианта

Контекст следующих записей — непосредственное содержимое `technology_swap`.

| Ключ | Форма значения | Игровое назначение и применение в анализе | Источники |
| --- | --- | --- | --- |
| `trigger` | Блок условий | Условие применения варианта. По документации игра выбирает первый подходящий вариант; ручной выбор в справочнике — отдельный режим. | T1, T2 |
| `name` | Идентификатор, используемый для названия варианта | Связь с локализованным представлением варианта. Не подменяет ID основной технологии в её пререквизитах. | T1, T2 |
| `inherit_effects` | `yes` / `no` | Управляет наследованием эффектов основной технологии. Его следует учитывать при сравнении назначения выбранного варианта. Это не универсальный флаг наследования всех полей. | T1, T2 |
| `area` | Идентификатор области | Переопределяет область; при отсутствии используется область основной технологии. Может изменить раздел карточки и отбор предшественника. | T1, T2 |
| `category` | Список идентификаторов | Заменяет весь список категорий основной технологии; при отсутствии остаётся исходный список. Не добавляется к нему автоматически. | T1, T2 |

## Границы трактовки

- `potential`, `technology_swap.trigger` и условия в `weight_modifier` выполняют разные роли. Совпадение вложенного ключа не делает их взаимозаменяемыми.
- Документация технологии описывает прогрессию уровней, но реальные определения могут требовать технологию более высокого уровня. У `tech_reactor_boosters_3` указан `tier = 1`, а среди требований присутствует `tech_antimatter_power` с `tier = 3`. Числовой суффикс ID не исправляет `tier`.
- Исходные связи и игровая семантика остаются в БД. Выбранная опора `parent_tech`, вычисляемый столбец повторяемых технологий и координаты размещения относятся к модели справочника.
- Формы логических блоков сохраняются структурно; эта запись не утверждает поддержку всех возможных комбинаций операторов движком внутри `prerequisites`.
