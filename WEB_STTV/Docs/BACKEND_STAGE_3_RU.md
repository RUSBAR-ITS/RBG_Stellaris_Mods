## Результат этапа

Утверждённое [ТЗ третьего этапа](TZ_BACKEND_STAGE_3_RU.md) реализовано. Синтаксический механизм получает текст и проверенную конфигурацию, сохраняет структуру и исходное написание, работает без профиля игровых команд. Сборщик и анализатор используют этот механизм через общие настройки.

Источники читаются напрямую. Для проверки сохранены контрольная БД и хеши, а не копии игровых файлов. Формат БД остаётся прежним; её текущая сборка побайтно совпала с контрольной.

## Конфигурация

В [backend.json](../config/backend.json) выбран раздел:

```json
{
  "parser": {
    "lexical": {"base": "product", "path": "config/parser/lexical.json"},
    "constructs": {"base": "product", "path": "config/parser/constructs.json"}
  }
}
```

- [lexical.json](../config/parser/lexical.json): BOM, пробельные символы, начало комментария, кавычки и экранирование, многострочность, операторы, фигурные разделители.
- [constructs.json](../config/parser/constructs.json): самостоятельные значения, анонимные и смешанные блоки, метки `rgb`/`hsv`, параметры с необязательным значением по умолчанию, формулы, условные фрагменты.

Для пользовательских конфигов можно выбрать `base: "work"`: путь отсчитывается от `WORK_DIR`. `product` означает каталог продукта. Выбор не зависит от текущего каталога терминала; отсутствие или ошибка файла не включает запасной вариант.

Закрытые схемы [parser_lexical.schema.json](../schemas/parser_lexical.schema.json) и [parser_constructs.schema.json](../schemas/parser_constructs.schema.json) генерируются из `schema_generation/syntax.py` общей командой генератора. Сборка читает схемы и конфиги, но не перезаписывает их. Дополнительно проверяются конфликты обозначений; намеренные пересечения операторов разрешаются по наиболее длинному совпадению, разделители составных форм — по состоянию.

Конфиги задают обозначения и переключатели реализованных форм. Новая форма требует обработчика в коде. Здесь нет перечня игровых команд или языка исполняемых правил.

## Модули и интерфейс

В `src/backend/sttv/script/`:

| Модуль | Назначение |
|---|---|
| `syntax.py` | Проверка конфигов и объект `Syntax` |
| `nodes.py` | Исходный текст, токены, узлы, координаты |
| `delimiters.py` | Строки, параметры, формулы, заголовки условных фрагментов |
| `lexer.py` | Токенизация с сохранением комментариев и пробелов |
| `parser.py` | Последовательности, вложенность и составные узлы |
| `serialization.py` | Явное преобразование представимых форм в данные текущей БД |

Пример отдельного вызова из Python с доступным пакетом `sttv`:

```python
from sttv.common.paths import PRODUCT_ROOT
from sttv.script.parser import parse_text
from sttv.script.syntax import load_syntax

syntax = load_syntax(PRODUCT_ROOT / "config/parser/lexical.json",
                     PRODUCT_ROOT / "config/parser/constructs.json")
document = parse_text('new_command = { value = @[ 2 * 3 ] }', syntax, "example.txt")
assert document.items[0].key.text == "new_command"
assert document.items[0].value.items[0].value.body == " 2 * 3 "
```

`parse_text(text, syntax, source_name=None)` не читает файлы. `load_syntax` выполняет отдельную загрузку; `make_syntax(lexical, constructs)` проверяет уже прочитанные словари. Парсер не импортирует проверку команд или разрешение переменных.

## Узлы и координаты

`Document` содержит `source`, `tokens`, `items`. В списке узлов различаются `Assignment`, `Scalar`, `Block`, `TaggedBlock`, `Formula`, `Conditional`. Порядок и повторения сохраняются.

У скаляра есть исходное `raw`, содержимое `text`, признак `quoted` и массив `parameters`. Каждый параметр сохраняет имя, исходное написание, координаты и `default`: `None` означает отсутствие значения по умолчанию, пустая строка — явно заданное пустое значение. Строки не декодируются как JSON; обратные косые черты сохраняются.

Формула сохраняет `raw`, `opener`, `body`; её арифметика не вычисляется. Условный фрагмент содержит `parameter`, `negated`, `items`, без проверки фактического наличия параметра. Имена ссылок сохраняются как текст, без определения их игрового смысла.

`span` содержит смещения `start`/`end` с нуля, строку/колонку `line`/`column` и `end_line`/`end_column` с единицы. Конец исключается. Смещения относятся к символам декодированной строки Python, не к байтам UTF-8. Токены, включая комментарии, пробелы и начальный BOM, покрывают весь текст без пропусков.

## Подключение сборщика и анализатора

`load_settings` читает и проверяет оба конфига до записи результатов. Выбранные файлы включаются в защиту от пересечения с путями выходных данных. До генерации рабочего реестра и анализа проверяется, что используемые реестром операторы присутствуют в выбранном синтаксисе.

`data_entries(document)` преобразует представимые узлы в `DataEntry` для существующего преобразователя технологии; `script_block` создаёт структуру текущего формата БД. Это отдельный шаг: успешный синтаксический разбор не разрешает новое поле технологии или новый вид значения в БД.

Формулы, условные фрагменты, цветовые и анонимные блоки не подменяются строками. Если они встретятся в преобразуемом документе, выдаётся `unsupported_database_form`, прежняя БД сохраняется. Существующие проверки команд работают после разбора; их профиль в этом этапе не удалён.

Анализатор также использует явное преобразование. Если форма пока не представима его текущими наблюдениями, файл получает диагностику `unsupported_analysis_form`, а результат — статус `partial`. Наблюдения из такого файла не выдаются за полный анализ. Имена параметров извлекаются из разобранных фрагментов, включая настраиваемые разделители и значения по умолчанию.

- БД сохранила 679 технологий и 206 вариантов и побайтно совпала с контрольной. SHA-256: `86624c6b75558115884bddafc1b121bac0ebf04dbaf902a8e16d87575c7c6afd`.
- Хеши всех 2 950 проверяемых файлов игры и локализационных источников неизменны. Все Python-файлы бэкэнда и тестов не превышают 200 строк.

## Границы реализации

Парсер не раскрывает `inline_script`, не исполняет команды, не вычисляет условия и формулы, не разрешает игровые ссылки и не исправляет источники. Его принятие записи подтверждает только поддерживаемую структуру. Произвольная грамматика через конфиг и редактор форматирования не реализованы.

Справочник по-прежнему не имеет UI и portable-поставки. Следующий этап замены реестра и определения необходимой предметной интерпретации согласуется отдельно.
