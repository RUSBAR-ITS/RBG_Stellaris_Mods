## Запуск

Реализация [утверждённого этапа 11](TZ_BACKEND_STAGE_11_RU.md). Команда запускается явно из `WEB_STTV`; интерфейс её не вызывает:

```powershell
$env:PYTHONPATH = 'src/backend'
python -B -m sttv.database_sets
```

В текущем рабочем окружении вместо `python` можно использовать `data/.venv/Scripts/python.exe`. Аргументы `--variables` и `--config` выбирают файлы глобальных переменных и конфигурации набора. По умолчанию это `global_variables.json` и `config/backend.json` относительно каталога продукта. Код завершения: `0` при успехе, `1` при ошибке.

## Файлы и настройки

| Роль | Источник относительно `STELLARIS_ROOT` | Результат относительно `WORK_DIR` |
| --- | --- | --- |
| `technologies` | `TECH_PATH`: `common/technology` | `databases/technologies.json` |
| `components` | `COMPONENTS_DIR`: `common/component_templates` | `databases/components.json` |
| `buildings` | `BUILDINGS_DIR`: `common/buildings` | `databases/buildings.json` |

Общие настройки парсера находятся в `config/backend.json` → `parser`. Раздел `datasets` задаёт источники и результаты каждого вида. Поле `localization` выбирает конфигурацию обогащения, `report` — сводный отчёт. Схема набора — `schemas/database_set.schema.json`; `backend.schema.json` описывает вход универсального сборщика отдельного дерева.

В `config/enrichment/localization.json` общими остаются языки, приоритеты источников и раскрытие ссылок. В `targets` находятся селекторы и правила ключей каждого вида. Все пути результатов проверяются совместно: совпадение, вложенность и пересечение с защищёнными источниками запрещены.

## Формат и локализация

Формат БД — `sttv.parse_database`, версия `5`. Каждая база набора содержит `dataset.kind` и общий `dataset.set_id`. Идентификатор вычисляется из канонических SHA-256 трёх полностью обогащённых деревьев без `dataset`; имена выходных файлов и время запуска на него не влияют.

Базы записываются компактным JSON без отступов. Это меняет только представление файла: AST, порядок элементов, происхождение раскрытия и локализация сохраняются. Общие служебные сведения разбора не превращаются в объекты каталога.

Названия и описания RU/EN хранятся в `enrichments.localization`. Для технологий сохранены варианты и наследование описания. ID компонента берётся из прямого `key`; описание ищется по `<key>_DESC`, затем по явному `<component_set>_DESC`. Поле `fallback` фиксирует ссылку на `component_set`. Пустой найденный перевод считается найденным и не заменяется запасным.

У зданий основной ключ описания — `<id>_desc` либо явный скалярный `desc`. Каждый условный блок `desc` получает собственное поле `description` по своему `text`, без `name`. Условия остаются в дереве; активное описание не выбирается. Исходные строки, раскрытые статические ссылки, динамические подстановки и источники переводов сохраняются по правилам этапа 10.

## Публикация и диагностика

Координатор `src/backend/sttv/database_sets/` последовательно разбирает, локализует, проверяет и временно сохраняет участников. Перед публикацией проверяются все три результата, хеши использованных источников и состав каталогов. Итоговые файлы не заменяются при ошибке подготовки любого участника.

Каждый файл заменяется атомарно, весь набор — последовательно. Сбой между заменами может оставить смешанный набор; отчёт показывает фактически записанные роли, фронтенд отклоняет несовпадающие `set_id`. После устранения причины нужно повторить сборку набора.

Отчёты по умолчанию: `reports/<kind>_build.json`, `reports/<kind>_localization.json`, `reports/database_set.json`. Сводный отчёт содержит статусы и количества по видам, хеши входов, идентификатор набора и результат публикации. Отсутствующие переводы и нераскрытые динамические ссылки — предупреждения; конфликт выбранного перевода, дубль ID, ошибка разбора и изменение входа — ошибки.

Отдельное обогащение файла с `dataset` запрещено: оно нарушило бы принадлежность набору. Универсальное дерево без этой метки можно обогащать отдельно. Старые базы версии 4 нужно перестроить.

## Проверки

Пройдены 192 проверки Python, включая восемь сценариев набора: локализация разных видов, общий идентификатор, воспроизводимость, изменение участника, ошибка третьей БД, изменение общего входа, частичная публикация и запрет отдельного обогащения участника. Дополнительно проверены TypeScript, сборка и открытие полного набора во фронтенде.

Полный прогон использует 118 файлов TXT и сохраняет 696 588 игровых узлов:

| БД | Файлы | Игровые узлы | Объекты локализации |
| --- | ---: | ---: | --- |
| Технологии | 35 | 82 246 | 679 технологий и 206 вариантов |
| Компоненты | 55 | 357 812 | 1506 компонентов |
| Здания | 28 | 256 530 | 498 зданий и 21 условное описание |

Размеры компактных файлов: технологии — 39 493 998 байт, компоненты — 220 001 927 байт, здания — 130 987 059 байт; всего около 390,5 МБ. Изменение размера относительно прежней записи с отступами не означает удаления игровых данных.

Имена найдены для всех объектов на обоих языках. У технологий и зданий отсутствующих описаний нет; для 81 варианта технологии описание наследуется от основной технологии. У компонентов не найдены 85 описаний в каждом языке. Ещё четыре предупреждения относятся к двум неразрешимым ссылкам в двух языках: `SPACE_AMOEBA_WEAPON_DESC` и `null_void_siphon`; исходные подстановки сохранены. Итого в отчёте локализации компонентов 174 предупреждения, ошибок нет. В разборе компонентов зарегистрировано 14 предупреждений `unused_inline_argument` из игровых вызовов.

Сверка ранее исследованных улучшений подтвердила 16 случаев и 60 свидетелей. Итоги независимой проверки содержимого и исходников — `data/stage11/independent_verification.json`; сводка финального прогона — `data/reports/database_set.json`. Проверка воспроизводимости на синтетическом наборе сравнивает файлы побайтно; реальный повтор дополнительно сверяется по хешам содержимого и общему идентификатору.

Финальная сборка завершилась за 758,309 с в текущем окружении. Повтор подтвердил тот же `set_id` и хеши всех трёх обогащённых деревьев; опубликованные компактные файлы побайтно совпали с независимым компактным представлением первого результата. Повторно проверены 1066 входных файлов — изменений нет. Все три статуса разбора, локализации и публикации успешны.

## Ограничения

Обрабатываются TXT трёх каталогов; CSV/ODS с характеристиками оружия не входят в этот этап. Парсер сохраняет игровые конструкции, но не вычисляет состояние государства. Новый порядок карточек и определение главных цепочек относятся к следующему этапу.
