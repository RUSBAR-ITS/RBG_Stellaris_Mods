## Результат

Реализовано утверждённое [ТЗ пятого этапа](TZ_BACKEND_STAGE_5_RU.md). Обе формы `inline_script` раскрываются в месте вызова, включая вложенные вызовы и код, переданный строковым аргументом. Аргументы изолированы между вызовами. Порядок записей, повторные ключи и пустые результаты сохраняются.

История вызовов вынесена из рабочего дерева. Сборщик и анализатор используют раскрытые узлы; статистика не считает аргументы и пути из метаданных повторно. Игровые источники читаются без изменения.

## Конфигурация

`INLINE_SCRIPTS_DIR` в `global_variables.json` задаёт каталог относительно `STELLARIS_ROOT`; текущее значение — `common/inline_scripts`. Выход за корень игры запрещён.

`config/backend.json` выбирает `parser.inline_scripts` через обычную пару `base`/`path`. В `config/parser/inline_scripts.json` находятся:

| Поле | Текущее значение | Назначение |
| --- | --- | --- |
| `path_field` | `script` | Поле пути в блочном вызове |
| `parameter_case_sensitive` | `true` | Сопоставление имён аргументов |
| `extension` | `.txt` | Расширение искомого файла |
| `encoding` | `utf-8-sig` | Кодировка шаблонов |
| `max_depth` | `64` | Максимальная глубина вызовов |

Имя самой конструкции остаётся в `constructs.json`, разделители параметров и правила строк — в существующих конфигах синтаксиса. Команды игры не используются для поиска шаблонов. Четыре конфига парсера проверяются отдельными закрытыми схемами.

## Модули и интерфейс

В `src/backend/sttv/script/inlining/`:

- `binding.py` читает путь и аргументы без классификации имён аргументов как логических операторов.
- `loader.py` разрешает безопасный путь, читает шаблон и кеширует текст с SHA-256 только в пределах операции.
- `substitution.py` подставляет параметры до структурного разбора; комментарии не требуют аргументов.
- `text.py` связывает сгенерированный текст с физическими фрагментами источников.
- `expansion.py` управляет вложенностью, циклами, изоляцией аргументов и вставкой узлов.

`script/inline.py` экспортирует `Expansion`, `FileTemplates`, `MemoryTemplates` и `expand_inline_script`. `sources/expansion.py` создаёт контекст из настроек и исключает каталог шаблонов из самостоятельных входов.

```python
from sttv.script.parser import parse_text
from sttv.sources.expansion import expansion_context

context = expansion_context(settings)
document = parse_text(text, settings.syntax, "example.txt",
                      expansion=context, root="TECH_PATH")
```

Один контекст обслуживает один запуск; ID вызовов уникальны в нём. `role="template"` предназначен для явно выбранного исследования шаблона без раскрытия. Обычный документ с вызовом и без контекста выдаёт `inline_context_required`, а не пропускает вставку.

## История и происхождение

`document.metadata.inline_scripts` содержит вызовы в порядке «родитель, затем дети». Запись хранит ID, родителя, место вызова, форму, исходный и эффективный путь, файл шаблона и аргументы `{name, raw, value}`. `insertion = {container, index, count}` описывает вставку в окончательном AST. Для пустого шаблона `count = 0`.

У каждого узла есть `origin`. Для подставленного текста сохраняются физические фрагменты, место параметра и отдельный диапазон сгенерированного текста. Ошибка раскрытия или последующей проекции содержит исходное место и цепочку вызовов. Переданные аргументы не наследуются вложенным вызовом без явной передачи через его текст.

В БД вместо AST-позиции используется `result_paths`: проверяемые JSON Pointer к итоговым значениям. Формат полностью описан в [модели БД](DATABASE_MODEL_RU.md#история-вставок).

## База и профиль

Формат БД изменён на `2`: обязательная история `metadata.inline_scripts`, расширенный `SourceLocation`, `source` у скриптовых записей, повторов и локальных переменных. Формат 1 не поддерживается.

В профиле `stellaris_4_5_4.json` ревизия увеличена до `2`. По отдельному разрешению пользователя добавлены `is_preferred_weapons`, `is_councilor_type`, `ai_armor_ratio`, `ai_shields_ratio`, `is_ai_ship_role` и контекст его двух аргументов. Остальные эффективные правила совпадают с исходным контрольным отпечатком; это проверяется тестом.

Схемы по-прежнему генерируются кодом из `schema_generation/`; добавлена `parser_inline_scripts.schema.json`. При ошибке сборки прежняя БД сохраняется. Глобальные `@...`, scripted triggers/effects и игровые условия не исполняются.

## Запуск проверок

Из корня репозитория, используя имеющееся окружение Python:

```powershell
$env:PYTHONPATH = "$PWD/WEB_STTV/src/backend;$PWD/WEB_STTV/src/backend/tests"
WEB_STTV/data/.venv/Scripts/python.exe -B -m unittest discover -s WEB_STTV/src/backend/tests -v
WEB_STTV/data/.venv/Scripts/python.exe -B -m sttv.schema_generation
WEB_STTV/data/.venv/Scripts/python.exe -B WEB_STTV/src/backend/tests/script/audit_corpus.py
```

Общий аудит пишет `WORK_DIR/stage5/corpus_report.json` и новые TXT/JSON-списки в `WORK_DIR/stage5/text_frequency/`, включая подпапку `scalar_analysis/`. Файлы в прежнем `WORK_DIR/text_frequency/` сохраняются; проверяются их хеши. Параметры `@name`, `$NAME$`, значения `yes`/`no`, логические имена и единичные вхождения исключаются по прежним правилам. Текст нормализуется через `casefold`.

Проверен 111 автоматический сценарий: общий набор из 110 тестов и дополнительный тест происхождения ошибок определений и переменных. Ошибок и пропусков нет. Проверяются обе формы, пустые вставки, вложенность, передача кода и кавычек, происхождение ошибок, цикл/глубина, изоляция, изменение шаблона между сборками, метаданные и сохранение прежней БД при отказе. Отчёт — `WORK_DIR/stage5/test_report.json`.

## Проверки на игре

Технологическая сборка: **679 технологий, 206 вариантов, 301 раскрытый вызов, 10 шаблонов, ошибок нет**. Все названия RU/EN сохранены. Изменились предметные данные ровно 261 технологии с вставками; остальные 418 технологий, категории, уровни и локальные переменные совпали с контрольной БД после нормализации происхождения. Есть 1 272 предупреждения: 1 265 ссылок на внешние переменные и 7 повторных полей; они не вычисляются предположительно.

Общий проход: 2 238 физических TXT-файлов; 631 файл внутри каталога шаблонов исключён из самостоятельных входов. Из 1 607 оставшихся входов два являются документацией, 1 583 разобраны полностью, 22 имеют диагностику. Достигнуто 10 487 вызовов: 10 450 раскрыты, 37 завершились ошибкой, включая родительские вызовы при сбое ребёнка. Прочитаны 572 шаблона, максимальная вложенность — 3.

Частоты и скалярные списки построены только по полностью успешным входным файлам. Счётчики вызовов дополнительно включают попытки в неуспешных файлах. Итоговые списки: 56 322 частотные записи, 34 749 скалярных значений, 3 785 имён со скалярной правой частью. Это наблюдения данного корпуса, не универсальные правила языка. Хеши игровых файлов, прочитанных шаблонов и прежних рабочих списков совпали до и после прохода.

## Ограничения

Полный корпус имеет статус `partial`; полный перечень ошибок с цепочками сохранён в `corpus_report.json`:

- Одна ранее известная конструкция без оператора: `common/named_colors/01_trait_colors.txt:65`.
- Три файла традиций ссылаются на отсутствующий `traditions/tr_purity_imperfection_remediation_wilderness.txt`.
- Четырнадцать файлов признаков достигают шаблонов без обязательного `CLASS`; неявное наследование словаря родителя запрещено текущим ТЗ.
- Два файла событий достигают шаблона `grand_archive/collection/stage_3_reward_option.txt` без `RELIC`.
- Два файла scripted effects передают ещё не связанные параметры `TARGET` и `IGNORE_COUNTRY_GFX`; исполнение внешних scripted effects не входит в этап.

Эти сообщения характеризуют пределы текущего обработчика и конкретные источники; они не доказывают поведение движка в игре. Условные фрагменты и параметры со значением по умолчанию при раскрытии диагностируются как неподдерживаемые. Файлы игры не исправлялись; дальнейшее расширение правил требует отдельного решения.
