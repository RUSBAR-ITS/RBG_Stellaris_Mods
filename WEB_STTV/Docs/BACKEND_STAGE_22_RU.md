## Запуск с Windows

Выполнять в PowerShell из корня `WEB_STTV` с установленным окружением бэкенда. Первая команда устанавливает зависимости, включая PyMongo. Каждую из трёх операций можно запускать отдельно.

```powershell
.\data\.venv\Scripts\python.exe -m pip install -r src/backend/requirements.txt
$env:PYTHONPATH = 'src/backend'
.\data\.venv\Scripts\python.exe -B -m sttv.localization_import prepare
.\data\.venv\Scripts\python.exe -B -m sttv.localization_import load
.\data\.venv\Scripts\python.exe -B -m sttv.localization_import verify
```

| Операция | Вход | Результат |
| --- | --- | --- |
| `prepare` | Локальные каталоги переводов игры и мода | Готовый JSON-пакет и отчёт в `WORK_DIR/localization_import` |
| `load` | Готовый пакет, Vault и MongoDB | Публикация полного словаря в `wiki.localization` |
| `verify` | Тот же пакет и доступ к серверу | Сверка всех опубликованных документов с пакетом |

На этапе 22 настройки источников и публикации были объединены. Для текущей версии см. [конфиг парсера](../config/parser_sources.json), [конфиг загрузчика](../config/loader.json) и [команды этапа 23](BACKEND_STAGE_23_RU.md).

Для сетевых операций используется Windows `curl.exe` с Schannel и сертификатом из личного хранилища пользователя. Загрузчик получает из Vault пароль `wiki` и публичный сертификат центра сертификации MongoDB, отзывает выданный токен и подключается напрямую к MongoDB по TLS и SCRAM-SHA-256. Временный файл публичного сертификата удаляется после закрытия соединения.

## Пакет и публикация

`manifest.json` перечисляет партии документов, их SHA-256 и количество записей. В `batches/` лежит форматированный JSON. Последним шагом успешной подготовки атомарно заменяется манифест. В `prepare_report.json` записываются итоги по языкам и источникам, координаты конфликтов и признак `blocking`. Конфликт на выбранном уровне останавливает подготовку до публикации манифеста.

Загрузчик сверяет хеши файлов, записывает партии во временную коллекцию с уникальным именем и читает её целиком для сравнения с пакетом. После совпадения всех записей одно переименование внутри базы заменяет целевую коллекцию. Старые ключи, исчезнувшие из игры, исчезают из опубликованного словаря. При ошибке записи или сверки загрузчик удаляет свою временную коллекцию.

В `mongosh` из базы `wiki` выбранный текст и источник можно получить так:

```javascript
const row = db.localization.findOne({ _id: { language: "ru", key: "tech_titans" } })
row.definitions[row.selected]
```

## Проверка на тестовом сервере

20 ноября 2026 года с рабочей станции Windows выполнены подготовка, две публикации и полная сверка опубликованной коллекции на `192.168.1.39:27017`. Обработаны 706 файлов и 453 781 определение. Опубликованы 153 242 документа RU и 150 258 EN, всего 303 500. Все 13 расхождений внутри ванильного русского источника перекрыты более высоким приоритетом.

Проверены `tech_titans` (`Титаны` и `Titans`), оба описания, сохранённая ссылка `$02_ACCEPT_NEGOTIATE_EXISTING_AGREEMENT_NEUTRAL$` и ключ `Awareness_rinfix`, присутствующий только на русском. В отдельной тестовой коллекции проверены повторная публикация, ошибка записи второго пакета из-за повторяющегося ключа и исчезновение устаревшего ключа при успешной замене. После ошибки предыдущий словарь полностью читался.

Для повторения четырёх направленных тестов установить `$env:STTV_TEST_MONGO_LOCALIZATION = '1'` и выполнить `.\data\.venv\Scripts\python.exe -B -m unittest discover -s src/backend/tests -p test_localization_import.py` с тем же `PYTHONPATH`. Без переменной окружения выполняются локальные проверки. Также пройден полный набор из 51 теста обогащения и 3 теста генерации схем. [ТЗ этапа](TZ_BACKEND_STAGE_22_RU.md)
