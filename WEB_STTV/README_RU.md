## Проект

**Stellaris Technological Tree View**, каталог проекта — `WEB_STTV`.

Локальный интерактивный веб-справочник по технологиям Stellaris. Первый интерфейс показывает поле карточек по областям науки и уровням, названия и описания в тултипах, варианты из готовой комбинации. Ванильные изображения относятся к последующим этапам. Данные собираются из выбранных пользователем источников и преобразуются во внутреннюю базу справочника. Предполагается переносимая поставка для Windows без отдельной установки веб-сервера.

## Статус

Реализованы [этап 17 бэкенда](Docs/BACKEND_STAGE_17_RU.md) и [фронтенд 0.0.5](Docs/frontend/FRONTEND_STAGE_5_RU.md): манифест, 450 постоянных документов для 15 видов, проверка при чтении, выборочная загрузка и сетка деревьев по сохранённым родителям. Конфиг `config/frontend/tree_layout.json` выбирает готовую комбинацию; сортировка использует текущий язык. JSON сохраняет отступы, переносы, AST, историю и RU/EN-локализацию. Монолитное объединение удалено.

Обогащение дерева сохраняет 13 критериев: проверены 679 базовых решений, 206 вариантов и три сочетания. Все 450 документов совпали с эталоном после нормализации формата. Полный аудит прошёл без ошибок. Сборка заняла 387,885 с; начальное открытие загрузчика — 2,601 с с чтением только 35 технологических документов. Условия замеров — в руководствах.

Сохраняются библиотеки вставок и явные режимы их подготовки/переиспользования. Интерактивный пересчёт вариантов, линии связей, HTTP API и portable-поставка остаются отдельными этапами.

## Запуск интерфейса

Из `WEB_STTV` при наличии Node.js 24: `npm ci`, затем `npm run dev`. Адрес — `http://127.0.0.1:5173/`. Для текущего компьютера Node.js подготовлен в `data/`; команда приведена в [руководстве](Docs/frontend/FRONTEND_STAGE_5_RU.md#запуск-и-комбинация).

Нажать «Открыть набор БД» и выбрать папку **`data/stage17/database_set`**. Будущие сборки по умолчанию записываются в `data/database_set`. Выбирается корень с `manifest.json`; старые 15 монолитных файлов не поддерживаются. Сборка выполняется отдельно: `$env:PYTHONPATH="src/backend"`, затем `python -B -m sttv.database_sets --rebuild-libraries`. Старт и обновление страницы не запускают генератор и не открывают БД автоматически.

## Структура каталога

| Путь | Назначение |
| --- | --- |
| `src/frontend/` | Код интерфейса |
| `src/backend/` | Код Python для обработки и последующей служебной части |
| `config/` | Источники, пути результатов, конфиги парсера, библиотек и локализации |
| `schemas/` | 32 генерируемые схемы конфигурации, БД и отчётов |
| `data/` | Рабочая папка по умолчанию для БД, отчётов, временных результатов и проверок |
| `Docs/` | Документация на русском и английском |
| `Docs/frontend/` | Концепт интерфейса и последующая документация фронтенда |
| `Docs/semantics/` | Словарь игровых конструкций для анализа технологий и связей объектов |

Путь рабочей папки задаётся через `WORK_DIR`. Относительное значение отсчитывается от каталога `WEB_STTV`/продукта; допускается абсолютное внутри репозитория. Изменение настройки не перемещает существующие данные. В корневой `.gitignore` добавлено `/WEB_STTV/data/`; другую рабочую папку при необходимости исключают отдельно. Настройка применяется при каждом запуске сборщика.

Исходники читаются непосредственно из выбранных каталогов в режиме read-only. Результат парсинга сохраняется в JSON для последующего обогащения; копии исходных файлов не создаются. Для перестроения нужны источники, для чтения готовой базы — нет.

## Глобальные переменные

Общий файл [global_variables.json](global_variables.json) хранит уже определённые переменные проекта. Он пополняется по мере появления новых переменных для любых частей приложения; его назначение не ограничено парсингом.

| Переменная | Назначение | Текущее значение |
| --- | --- | --- |
| `WORK_DIR` | Рабочая папка продукта и проверок, по умолчанию относительно каталога проекта | `data` |
| `STELLARIS_ROOT` | Абсолютный путь к корню установленной игры | `E:/SteamLibrary/steamapps/common/Stellaris` |
| `TECH_PATH` | Путь к каталогу технологий относительно `STELLARIS_ROOT` | `common/technology` |
| `COMPONENTS_DIR` | Каталог компонентов относительно `STELLARIS_ROOT` | `common/component_templates` |
| `BUILDINGS_DIR` | Каталог зданий относительно `STELLARIS_ROOT` | `common/buildings` |
| `INLINE_SCRIPTS_DIR` | Каталог шаблонов `inline_script` относительно `STELLARIS_ROOT` | `common/inline_scripts` |
| `SCRIPTED_EFFECTS_DIR` | Библиотека именованных эффектов относительно `STELLARIS_ROOT`, исключённая из самостоятельного обхода | `common/scripted_effects` |
| `SCRIPTED_TRIGGERS_DIR` | Библиотека именованных триггеров относительно `STELLARIS_ROOT`, индексируется отдельно и исключена из самостоятельного обхода | `common/scripted_triggers` |
| `SCRIPTED_VARIABLES_DIR` | Библиотека статических переменных относительно `STELLARIS_ROOT`, читается отдельно для подстановки; исключена из самостоятельного обхода | `common/scripted_variables` |
| `SCRIPT_VALUES_DIR` | Библиотека расчётов относительно `STELLARIS_ROOT`, индексируется отдельно и исключается из самостоятельного обхода | `common/script_values` |
| `WORKSHOP_DIR` | Абсолютный путь к модам Stellaris из Steam Workshop | `E:/SteamLibrary/steamapps/workshop/content/281990` |
| `RU_LOC_TIER_1` | Русская локализация, высший приоритет: `replace` мода Russian Localization Fix RE | `${WORKSHOP_DIR}/681483874/localisation/replace` |
| `RU_LOC_TIER_2` | Русская локализация, второй приоритет: каталог `russian` того же мода | `${WORKSHOP_DIR}/681483874/localisation/russian` |
| `RU_LOC_TIER_3` | Русская локализация, третий приоритет: ванильная, относительно `STELLARIS_ROOT` | `localisation/russian` |
| `EN_LOC_TIER_1` | Английская локализация: ванильная, относительно `STELLARIS_ROOT` | `localisation/english` |

Пути `TECH_PATH`, `INLINE_SCRIPTS_DIR`, `SCRIPTED_EFFECTS_DIR`, `SCRIPTED_TRIGGERS_DIR`, `SCRIPTED_VARIABLES_DIR`, `SCRIPT_VALUES_DIR`, `RU_LOC_TIER_3` и `EN_LOC_TIER_1` отсчитываются от `STELLARIS_ROOT`. Запись `${WORKSHOP_DIR}` в двух остальных путях обозначает подстановку значения одноимённой переменной. Это соглашение файла настроек: JSON хранит обычные строки и сам подстановку не выполняет. В путях используются прямые слеши `/`, как и в ранее заданных переменных.

`INLINE_SCRIPTS_DIR` используется для раскрытия вставок. Например, `script = technologies/rare_technologies_weight_modifiers` указывает на `STELLARIS_ROOT/INLINE_SCRIPTS_DIR/technologies/rare_technologies_weight_modifiers.txt`. Каталог доступен только для чтения. Выбранные конфигом шаблоны подготавливаются в общую библиотеку; найденные вызовы, включая вложенные, используют её готовые планы.

Вложенные вызовы, подстановка аргументов и история вставок реализованы. Метаданные исключены из аналитического обхода; актуальное представление описано в [руководстве восьмого этапа](Docs/BACKEND_STAGE_8_RU.md).

Русский текст для каждого ключа выбирается в порядке `RU_LOC_TIER_1` → `RU_LOC_TIER_2` → `RU_LOC_TIER_3`, с переходом к следующему источнику при отсутствии ключа. Английский текст того же ключа берётся из `EN_LOC_TIER_1`. Русская и английская локализации рассматриваются отдельно; наличие ключей в обоих языках проверяется независимо.

Абсолютные корни источников относятся к текущему окружению. Каталоги игры и локализации доступны только для чтения; `WORK_DIR` предназначен для записи результатов. Сборщик загружает настройки, раскрывает inline-вставки, именованные эффекты, триггеры и script values и подставляет статические переменные. Универсальный сборщик дерева не требует локализации; координатор набора затем обогащает все 15 деревьев и публикует их совместно.
